## 4. 验收条件

<a id="ac-01"></a>
### AC-01：测试项填表登记

- 开始前状态：qa 环节表已生成，测试范围已确认
- 触发动作：AI 在表中填写全部测试项后执行登记命令
- 可检查结果：登记命令核对表完整并一次登记全部任务，不再逐条接受命令行登记参数
- 通过标准：表中的每个测试项都登记为待执行任务；缺项或格式错时按表检查失败输出
- 不通过标准：仍要求逐条命令行登记，或登记与表内容不一致
- 产品设计依据：[编写并执行测试](../spec/功能_编写并执行测试.md#4-规则) R6

<a id="ac-02"></a>
### AC-02：测试计划与结果文档程序生成

- 开始前状态：测试记录表已填写；主题测试已真实执行并产生机器记录
- 触发动作：查看 qa 目录下该主题的测试计划与测试结果文档的生成方式
- 可检查结果：两份文档由程序按表和当前机器记录生成：固定标题、编号行、命令、时间、退出码和报告事实由程序写入
- 通过标准：文档固定字段与机器记录一致；删除或改坏文档后可按表重新生成
- 不通过标准：固定字段需要 AI 手抄，或与机器记录分叉
- 产品设计依据：[编写并执行测试](../spec/功能_编写并执行测试.md#4-规则) R12、R32

<a id="ac-03"></a>
### AC-03：验收条件表与验收文档生成

- 开始前状态：acceptance_plan 环节表已生成
- 触发动作：AI 在表中填写验收条件后过第二道门；主题验收时用验收记录命令引用表中编号
- 可检查结果：验收条件以表为准；验收计划文档由程序按表生成；验收记录命令引用的编号必须在表中存在；验收结果文档由程序按表生成
- 通过标准：引用不存在编号时被拒绝并指出；文档由程序生成
- 不通过标准：验收编号可脱离表随意引用，或文档需手写固定部分
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R8
