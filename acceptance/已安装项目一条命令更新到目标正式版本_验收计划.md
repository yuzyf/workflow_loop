# 【验收主题】已安装项目一条命令更新到目标正式版本

- 验收主题：已安装项目一条命令更新到目标正式版本

## 1. 本次需求与验收目标

### 需求来源

- [产品总说明：项目更新场景和通用规则](../spec/产品总说明.md)
- [更新已安装项目](../spec/功能_更新已安装项目.md)
- [安装到项目：区分后续管理](../spec/功能_安装到项目.md#4-规则)

### 验收目标

项目维护者在一个已经完整安装旧版 Workflow Loop 的项目根目录执行一条更新命令后，电脑全局命令和当前项目达到同一个目标正式版本；更新只覆盖 Workflow Loop 静态管理文件并保留项目运行资料、业务代码和正式产物，失败时显示两侧真实版本并允许重试。

## 3. 验收范围

### 本主题验收

- 从当前项目根目录更新到 PyPI（Python 公共软件包仓库）最新正式版本或指定的更高正式版本。
- 一条操作处理电脑全局命令和当前项目，支持只补落后的一侧、重复更新零修改和旧版本脚本入口。
- 项目管理文件的直接覆盖范围，以及运行资料、业务代码和正式产物的保留范围。
- 进行中轮次更新、材料变化后的旧结论失效、跨版本更新、残缺项目停止和中途失败后的真实报告。
- GitHub Release（GitHub 正式发布页）和 README（项目说明文档）提供更新脚本及入口。

### 本主题不验收

- 自动更新同一电脑上的其它项目、降级、预发布版本或残缺安装自动修复。
- 被覆盖文件的备份、更新回滚或全局命令与项目文件的整体事务恢复。
- 项目卸载和电脑全局命令卸载。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
### AC-01：根目录预检和一次确认

- 条件与触发：用户在准备更新的项目目录执行更新命令，程序尚未取得用户确认。
- 预期结果：程序只把当前目录作为目标，先检查项目骨架、全局命令版本、项目版本、目标版本和发布来源，再显示项目绝对路径、两侧当前版本、目标版本、覆盖范围和保留范围；只询问一次，用户取消时不修改全局命令或项目文件。
- 产品设计依据：[更新已安装项目 R1、R7、R8、R9](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-02"></a>
### AC-02：目标正式版本选择正确

- 条件与触发：用户未指定版本、指定一个正式版本，或者请求低于当前项目版本或来源不一致的版本。
- 预期结果：未指定时选择 PyPI 最新正式版本；指定时只接受已经正式发布且高于或等于当前项目版本的版本；拒绝降级、预发布版和 PyPI 包与对应 GitHub Release 更新脚本版本不一致的目标，并在任何写入前停止。
- 产品设计依据：[更新已安装项目 R2 至 R6](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-03"></a>
### AC-03：一条操作更新电脑和当前项目

- 条件与触发：用户确认更新，全局命令和当前项目可能都落后，也可能只有一侧落后或两侧都已达到目标版本。
- 预期结果：一次更新把落后的一侧或两侧更新到同一目标版本；已达到目标版本的一侧不重复修改；两侧都已达到目标版本时不修改文件并明确显示无需更新。
- 产品设计依据：[更新已安装项目 R5、R8、R17](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-04"></a>
### AC-04：旧版本可以直接跨版本更新

- 条件与触发：当前项目骨架完整且版本受支持，但旧版本没有 `workflow update` 命令，或者目标版本跨过一个或多个中间正式版本。
- 预期结果：用户从项目根目录执行当前操作系统的 `update.sh` 或 `update.ps1` 后，一条脚本先更新全局命令再更新当前项目；不要求先安装中间版本。
- 产品设计依据：[更新已安装项目 R13、R14](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-05"></a>
### AC-05：项目覆盖和保留范围准确

- 条件与触发：用户确认更新，项目中的智能体契约、模板、规范或项目状态包含旧版内容或项目定制。
- 预期结果：程序直接覆盖 `AGENTS.md`、模板仓库和规范仓库，只修改 `project.json`（项目级状态文件）的安装版本；保留该文件其它项目级字段、当前轮次状态、追加历史、回退资料、业务代码和所有正式产物，不保存被覆盖内容的备份。
- 产品设计依据：[更新已安装项目 R10、R11](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-06"></a>
### AC-06：进行中轮次重新确认变化材料

- 条件与触发：当前项目有进行中的 Workflow Run（工作流轮次），更新改变了当前或后续环节使用的模板或规范。
- 预期结果：更新不结束或删除当前轮次；后续推进时，受影响环节的旧材料确认失效，AI 必须重新读取变化后的材料并与用户重新确认相关结论。
- 产品设计依据：[更新已安装项目 R12](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-07"></a>
### AC-07：异常结果真实并允许重试

- 条件与触发：项目骨架残缺，或者全局更新、项目覆盖或最终版本核对中的任一步失败。
- 预期结果：残缺项目在写入前停止并列出残缺项；中途失败不回滚已经完成的修改，显示失败步骤、当前全局命令版本和当前项目版本并允许重新执行；只有两侧都达到目标版本时才显示更新成功。
- 产品设计依据：[更新已安装项目 R15、R16、R17](../spec/功能_更新已安装项目.md#4-规则)

<a id="ac-08"></a>
### AC-08：正式发布提供一条命令更新入口

- 条件与触发：维护者发布包含本功能的新正式版本。
- 预期结果：对应 GitHub Release 同时提供 `update.sh` 和 `update.ps1`，脚本版本与 PyPI 正式包版本一致；README 分别给出 macOS、Linux 和 Windows 可直接执行的一条命令更新入口。
- 产品设计依据：[更新已安装项目 R6、R18](../spec/功能_更新已安装项目.md#4-规则)、[安装到项目 R22](../spec/功能_安装到项目.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-08 全部通过，本主题才算完成。
- 任一落后一侧没有达到目标版本、保留范围被覆盖、取消后发生修改、失败结果隐瞒两侧真实版本或正式发布缺少更新入口，本主题均不通过。
