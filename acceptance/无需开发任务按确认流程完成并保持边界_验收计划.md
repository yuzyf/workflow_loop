### 验收目标

## 3. 验收范围

### 本主题验收

- 用户确认路线后开始无需开发任务，且同一项目只保留一个进行中轮次。
- AI 先调查事实、每次只问一个问题，用户确认讨论完毕后才执行。
- 文档修改、文档生成、调查和已准备操作共用同一条简单流程。
- 本地提交、远程推送、发布、删除和其它难以撤销操作的准确范围确认。
- 按任务约定核对并展示实际结果，用户确认后正式收工。
- 部分失败、整轮作废和发现需要开发时保留真实状态并正确结束或重新分类。
- 无需开发任务不误入完整研发阶段、三道门、固定测试和回退流程。

### 本主题不验收

- 修改正式产品规则、源代码、测试代码或影响运行、构建、测试、部署和依赖的配置。
- 产品代码质量、完整代码测试、固定全量回归和完整研发验收。
- Git 托管、发布平台或其它外部系统自身的可用性。
- 自动撤销本地提交、远程推送、发布、删除或其它已经执行的外部操作。
- 为无需开发任务生成产品设计、验收计划、测试计划、实施记录或结果文档。
- 同一项目并行开启多个轮次，或执行用户没有确认的额外操作。

## 4. 验收条件

<a id="ac-01"></a>
### AC-01：路线确认后才开始无需开发任务

- 条件与触发：已安装项目没有进行中轮次，用户提出一项任务，AI 根据项目事实推荐工作意图。
- 预期结果：产品显示从零创建、修改产品、修复缺陷和无需开发任务四种工作意图；用户确认进入无需开发任务后才建立 `light_task`（无需开发任务）轮次。已有进行中轮次时不另开新轮次。
- 产品设计依据：[开始或继续一轮工作 R1 至 R5、R12、R16](../spec/功能_开始或继续一轮工作.md#4-规则)

<a id="ac-02"></a>
### AC-02：讨论完成前不执行任务

- 条件与触发：无需开发任务轮次已经开始，任务目标、设计或准确操作仍有未决问题。
- 预期结果：AI 先调查可查事实，每次只问一个需要用户决定的问题并给出推荐；用户确认任务摘要、核对方法和讨论完毕后，产品才允许进入执行。文档修改和文档生成也遵守相同规则。
- 产品设计依据：[处理无需开发任务 R2 至 R4、R7](../spec/功能_处理无需开发任务.md#4-规则)

<a id="ac-03"></a>
### AC-03：难以撤销的操作单独取得准确批准

- 条件与触发：共同确认的任务准备执行本地提交、远程推送、发布、删除或其它难以撤销的操作。
- 预期结果：AI 先展示准确对象和影响，再取得一次针对该操作的明确批准；`commit`（创建本地 Git 提交）不会被自行扩大为 `push`（推送远程仓库），每次批准都保留在追加日志中。
- 产品设计依据：[处理无需开发任务 R5、R6、R10](../spec/功能_处理无需开发任务.md#4-规则)

<a id="ac-04"></a>
### AC-04：无需开发任务不继承完整研发负担

- 条件与触发：用户确认开始 `light_task`（无需开发任务）轮次，或该轮次收到完整研发流程命令。
- 预期结果：本轮不生成研发阶段路径、研发过程文档、文件哈希、固定全量测试或回退副本，也不使用逐环节三道门；完整研发命令不能把本轮误送入研发阶段。原有三种完整研发流程仍保持原行为。
- 产品设计依据：[产品总说明：无需开发任务保持简单](../spec/产品总说明.md#6-产品通用规则)、[推进并确认工作环节 R14](../spec/功能_推进并确认工作环节.md#4-规则)

<a id="ac-05"></a>
### AC-05：结果确认后只正式收工一次

- 条件与触发：AI 已经按共同确认的范围执行任务，并使用共同确认的方法完成核对。
- 预期结果：AI 展示实际操作和对应核对结果，不把操作成功说成代码质量、产品测试或研发验收通过；用户确认结果后才能正式收工，正式收工不重复询问同一个结束决定。
- 产品设计依据：[处理无需开发任务 R7 至 R10](../spec/功能_处理无需开发任务.md#4-规则)、[产品总说明：正式收工不重复确认](../spec/产品总说明.md#6-产品通用规则)

<a id="ac-06"></a>
### AC-06：失败、作废和重新分类保留真实状态

- 条件与触发：无需开发任务只完成一部分、执行失败、用户决定整轮作废，或处理时发现必须修改产品、代码、测试或运行配置。
- 预期结果：产品保留文件和外部系统当时的实际状态，记录已完成、未完成和失败内容，不自动恢复或撤销；需要开发时结束当前轮次，AI 推荐完整研发意图，用户重新确认后才能另开新轮次。
- 产品设计依据：[处理无需开发任务 R11、R12](../spec/功能_处理无需开发任务.md#4-规则)、[整轮作废并恢复 R6、R19](../spec/功能_整轮作废并恢复.md#4-规则)

<a id="ac-07"></a>
### AC-07：安装后的 AI 契约和公开说明包含简单流程

- 条件与触发：用户查看公开项目说明，或在已安装项目中向 AI 提出新任务。
- 预期结果：公开说明和安装到项目的 AI 契约都列出四种工作意图，并明确无需开发任务每次只问一个问题、用户确认讨论完毕后才执行、难以撤销的操作需要额外批准；用户不需要手工执行日常工作流命令。
- 产品设计依据：[产品总说明：支持范围与产品功能](../spec/产品总说明.md#7-产品功能)、[开始或继续一轮工作 R1、R4、R5、R14](../spec/功能_开始或继续一轮工作.md#4-规则)、[处理无需开发任务 R1 至 R6](../spec/功能_处理无需开发任务.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-07 全部通过后，本主题才算完成。
- 验收结果必须区分简单流程操作成功与代码质量、产品测试或完整研发验收通过。
- 本主题没有前置主题。
