# 【验收主题】退回验收计划后新增主题能走通门禁与追踪表

- 工作流编号：2026-09-01-1141-bugfix
- 验收主题：退回验收计划后新增主题能走通门禁与追踪表

## 1. 本次需求与验收目标

### 需求来源

- 缺陷复现记录 bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md 的 BUG-01（死锁）、BUG-02（追踪表不补行）、BUG-03（scaffold 不建表），由用户确认三项同根一并修复。
- 同一缺陷记录的 BUG-04（同一 Run 重进实施环节入场基线被重新冻结，第一次实施在校验语义上被抹平，57 项误报根源）、BUG-05（复用既有实现说明的豁免只写在报错文案里、代码无条件报错）与 BUG-06（同一 Run 第二遍缺陷复现确认因全量重注册主题报「主题名称已经使用过」卡死），经用户确认「合并到本轮」修复。
- 同一缺陷记录的 BUG-09（整体验收阶段暴露：引用回补用空机器任务集重刷测试结果文档，抹掉已通过的机器事实），与前八项同属退回重走路径缺口，按用户先前合并原则一并处理。
- 同一缺陷记录的 BUG-10（最终设计同步暴露：impl 失效检查以登记快照为基线却用完整观察范围计算当前值），与前九项同属重走路径事实保护缺口，按用户确认一并处理。

### 验收目标

- 修复后退回到验收计划环节再往索引新增验收主题的完整路径走通：第二道门校验集接纳新主题，追踪表自动补行，scaffold 自动建表；同时首轮与复核旧轮次两种既有场景结果不变。

## 2. 产品设计依据

- 产品既定规则：acceptance/索引.md 是本轮验收主题关系的事实源，第二道门要求索引与校验集一致；candidate_topics 的设计注释即「保留当前主题，并接纳未使用过的新主题」。本主题不新增产品规则，只恢复被 or 短路破坏的既定行为。

## 3. 验收范围

### 本主题验收

- 退回 acceptance_plan 后向索引新增未使用主题时，门禁、追踪表、记录表三处对该新主题的接纳行为；同一 Run 重进实施环节的入场基线继承；实施结果中复用既有实现说明的豁免生效；同一 Run 重走缺陷复现确认的幂等；以及首轮、复核旧轮次两种既有场景保持不变的回归结论；引用回补对测试结果文档机器事实的保护。

### 本主题不验收

- bugfix 意图下退回补主题的路径（该路径主题在缺陷复现阶段确定，不走 candidate_topics）；qa、impl 等环节索引的同类扩展场景由最终全量回归统一检查。

## 4. 验收条件

<a id="ac-01"></a>
### AC-01：第二道门放行含新主题校验集

- 开始前状态：一个 product_change 轮次已推进过验收计划，state.topics 含 2 个已注册旧主题；用户执行 workflow return 退回 acceptance_plan 后，向 acceptance/索引.md 追加 1 个主题历史中未使用过的新主题，并填好新主题的验收计划记录表与主题关系表。
- 触发动作：AI 在该项目目录执行 workflow gate acceptance_plan --discuss-done，再执行 workflow gate acceptance_plan。
- 可检查结果：门禁报告输出：第二道门「代码校验通过」，校验主题集为 2 个旧主题加 1 个新主题共 3 个，不再出现「索引的主题必须覆盖当前工作流全部主题」报错；随后执行 workflow gate acceptance_plan --confirmed 能记录用户确认并把 state.topics 更新为 3 个主题、进入下一阶段。
- 通过标准：第二道门一次通过；第三道门 --confirmed 无需任何外部干预即可执行成功，state.topics 变为索引中的 3 个主题。
- 不通过标准：第二道门仍报索引主题与当前主题不一致；或第三道门报「第二道程序校验还没有通过」；或 state.topics 在 --confirmed 后仍缺新主题。
- 产品设计依据：[制定验收与测试计划 R5](../spec/功能_制定验收与测试计划.md#r-5)：acceptance/索引.md 保存本轮主题关系；[缺陷记录 第 6 节根因 BUG-01](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-02"></a>
### AC-02：追踪表按初值为新主题补行

- 开始前状态：同 AC-01：退回后需求交付追踪表的当前工作流章节已存在且仅含旧主题的交付行，索引新增了 1 个主题并填好其验收计划记录表。
- 触发动作：AI 执行 workflow gate acceptance_plan，程序按记录表生成需求交付追踪表环节产物。
- 可检查结果：打开 需求交付追踪表.md 当前工作流章节：新主题按记录表的每条验收条件各占一行十列，需求来源、验收主题链接、验收条件单元格与旧主题行同格式，穿刺列、测试项、实施计划等初值列与首次建章节时的规则一致（如「本轮未执行穿刺，无可复用资产」「待制定」「待执行」「待更新」）。
- 通过标准：新主题的每条验收条件都出现在当前工作流章节表内且为完整十列；第二道门不再报缺少主题的交付记录；旧主题已有行不被改写。
- 不通过标准：新主题不出现在表内任何行；或第二道门报缺少主题交付记录；或补行时覆盖、改写了旧主题行或初值与建章节规则不一致。
- 产品设计依据：[制定验收与测试计划 3.1 支持范围 第 3 条](../spec/功能_制定验收与测试计划.md#31-支持范围)：追踪表连接验收主题与验收条件；[缺陷记录 第 6 节根因 BUG-02](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-03"></a>
### AC-03：scaffold 为新主题建记录表

- 开始前状态：同 AC-01：退回后停在 acceptance_plan，索引含新主题，state.topics 只有 2 个旧主题，新主题尚无 acceptance_plan 记录表。
- 触发动作：AI 执行 workflow scaffold。
- 可检查结果：命令输出列出为 acceptance_plan 环节生成的记录表路径；.workflow_loop/records/ 下当前工作流目录中，除 2 个旧主题的 acceptance_plan 表外出现新主题同名记录表，且旧主题表已填内容与执行前逐字段一致。
- 通过标准：新主题记录表被创建（含空栏目待填）；旧主题表内容与修改前逐字段一致；随后门禁不再报「验收计划工作记录表尚未填写内容」类缺表错误。
- 不通过标准：新主题无表、需要手动 workflow scaffold --topic 指定才生成；或旧主题已填内容被覆盖清空。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md)：scaffold 为当前环节生成缺失记录表；[缺陷记录 第 6 节根因 BUG-03](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-04"></a>
### AC-04：复核旧轮次行为保持不变

- 开始前状态：一个轮次已推进过 acceptance_plan 且 state.topics 与 acceptance/索引.md 主题完全一致（无新增、无删除），全部记录表已填写。
- 触发动作：AI 执行 workflow gate acceptance_plan 复核该轮验收计划。
- 可检查结果：门禁报告与修复前同输入下的输出一致：校验集等于 state.topics 等于索引主题，全部检查按既有规则通过或报出既有错误。
- 通过标准：通过/报错结论与修复前完全一致，不引入新的报错或静默。
- 不通过标准：同输入下出现与修复前不同的通过或报错结论。
- 产品设计依据：[制定验收与测试计划 R2](../spec/功能_制定验收与测试计划.md#r-2)：修复缺陷复用已确认主题；[缺陷记录 第 6 节根因 BUG-01](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-05"></a>
### AC-05：首轮仍从索引取全部主题

- 开始前状态：新一轮 product_change 首次到达 acceptance_plan，state.topics 为空，acceptance/索引.md 已写入本批全部新主题和填好的记录表。
- 触发动作：AI 执行 workflow gate acceptance_plan。
- 可检查结果：门禁校验集为索引中的全部新主题，第二道门按既有规则校验各主题文档并给出结论；第三道门 --confirmed 后 state.topics 写入这些主题。
- 通过标准：首轮行为与修复前一致：索引主题全部进入校验集，不混入其他轮次主题，主题名称与项目历史重名时仍按既有规则拒绝。
- 不通过标准：首轮校验集缺主题、混入历史主题，或重名主题不再被拒绝。
- 产品设计依据：[制定验收与测试计划 R10](../spec/功能_制定验收与测试计划.md#r-10)：每项来源至少被一个主题覆盖；[缺陷记录 第 6 节根因 BUG-01](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-06"></a>
### AC-06：同一 Run 重进实施环节沿用首次入场基线

- 开始前状态：一个 Run 已完整通过实施环节入场（第一次进入时代码基线已冻结、实施改动已发生并记录），随后 workflow return 退回上游并重走到实施环节。
- 触发动作：退回后第二次进入实施环节，AI 执行 workflow gate impl --discuss-done 入场，再执行 workflow gate impl 校验实际改动。
- 可检查结果：门禁读取的入场基线快照与第一次进入时冻结的快照一致（journal 中「实施入场基线」条目哈希不变）；第一次实施产生的文件改动仍出现在「入场以来实际改动」清单中。
- 通过标准：第二次入场不重新冻结基线、不覆盖首次快照；第一次实施的改动在第二次实施校验中仍可被检出，不再出现「已登记的实施项无实际变化」类误报。
- 不通过标准：第二次入场重新计算基线并把快照更新为含第一次改动的状态；或第一次实施登记的文件在第二次校验中被判为「记录但未变化」。
- 产品设计依据：[实施并保护项目修改](../spec/功能_实施并保护项目修改.md)：实施入场基线用于计算入场以来的实际改动；[缺陷记录 第 6 节根因 BUG-04](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-07"></a>
### AC-07：复用既有实现说明按提示操作即生效

- 开始前状态：实施结果中登记了一条「复用既有实现」的文件（该文件自入场基线以来没有新的实际改动），并在修改理由中写明这是复用的既有实现。
- 触发动作：AI 执行 workflow gate impl 进行实施结果校验。
- 可检查结果：门禁报告中该文件不再产生「实施结果列出的文件有实际变化，或明确说明这是复用的既有实现」报错；报告中如实列出该文件按复用豁免处理。
- 通过标准：带复用说明的登记条目校验通过；报错文案给出的处理路径（补充复用说明）与程序实际行为一致。
- 不通过标准：按报错提示补充复用说明后重跑门禁仍报同一错误；或不带复用说明的登记被错误豁免。
- 产品设计依据：[实施并保护项目修改](../spec/功能_实施并保护项目修改.md)：复用既有代码的实施记录规则；[缺陷记录 第 6 节根因 BUG-05](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-08"></a>
### AC-08：同一 Run 重走缺陷复现确认可幂等通过

- 开始前状态：一个 bugfix Run 已通过缺陷复现第三道门（验收主题已写入项目主题历史），随后 workflow return 退回缺陷复现环节并重走到第二遍第三道门。
- 触发动作：AI 执行 workflow gate reproduce --confirmed。
- 可检查结果：命令执行成功并进入下一环节；journal 记录主题确认信息；项目主题历史不因重复登记报错，也不出现重复条目。
- 通过标准：第二遍确认通过，state.topics 与缺陷记录中的主题一致；跨 Run 使用他轮已注册主题时仍按既有规则报「主题名称已经使用过」并拒绝。
- 不通过标准：第二遍确认报「主题名称已经使用过」并卡在缺陷复现环节；或跨 Run 重名主题被错误放行。
- 产品设计依据：[推进并确认工作环节](../spec/功能_推进并确认工作环节.md)：退回重走环节不等于从头重做，已成立结果复核后可继续使用；[缺陷记录 第 6 节根因 BUG-06](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-09"></a>
### AC-09：引用回补不覆盖已生成的机器事实

- 开始前状态：qa 测试结果文档已按当前机器记录生成且表内生成文档哈希与其一致；随后本主题验收结果文档真实生成，触发引用回补。
- 触发动作：AI 执行 workflow gate topic_acceptance（第二道门），程序按验收结果文档生成事件回补引用它的测试结果文档链接。
- 可检查结果：回补后的 qa 测试结果文档：头部仍为自动化测试结果：通过；每个 TC 小节仍含工作目录、命令、时间、退出码、输出哈希、报告哈希、精确匹配入口、产品代码哈希和测试代码哈希；表内生成文档哈希与文档一致。
- 通过标准：回补只把待生成占位改成真实链接，机器事实字段与回补前逐项一致；拿不到当前机器任务集时程序不重写该文档。
- 不通过标准：回补后文档出现自动化测试结果：未完成或任一 TC 小节只剩未执行一行；或表内生成文档哈希被指向缺机器字段的文档。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则)：固定字段与机器事实由程序按当前记录写入生成文档；[缺陷记录 第 6 节根因 BUG-09](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

<a id="ac-10"></a>
### AC-10：登记快照基线用登记范围比较不误报

- 开始前状态：一轮已完成 impl 第三道门，meta.registered_snapshots.impl 保存登记责任快照（无 impl_actual 键）；架构文档映射随后被合法更新，登记责任集合内容发生变化。
- 触发动作：AI 执行任一后续阶段门禁，程序运行 impl 绑定失效检查。
- 可检查结果：失效报告的核心代码差异只包含登记责任集合内真实变化的路径（该轮登记快照未变时为空），不出现登记快照外既有文件的幻影新增。
- 通过标准：基线为登记快照时当前值同样按登记责任范围计算；只有基线确实是完整观察快照时才用完整范围比较。
- 不通过标准：登记快照未变化而报告把安装脚本、依赖锁或未登记源码列为新增核心代码；或失效因无法归属主题而卡死后续阶段。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则)与[代码架构设计 5.17 登记责任快照与完整实施观察快照](../spec/代码架构设计.md#517-登记责任快照与完整实施观察快照)：登记责任快照用于阶段哈希与精确失效，两种范围不得交叉比较；[缺陷记录 第 6 节根因 BUG-10](../bug/缺陷_退回验收计划后新增主题能走通门禁与追踪表_2.md#6-根因)

## 5. 完成判定

- AC-01 至 AC-10 全部通过即本主题完成；其中 AC-01、AC-02、AC-03 为核心路径，AC-06、AC-07、AC-08 为退回重走路径的基线继承、复用豁免与幂等确认，AC-09、AC-10 为回补与失效检查对机器事实和登记范围的保护，AC-04、AC-05 为零破坏回归。
