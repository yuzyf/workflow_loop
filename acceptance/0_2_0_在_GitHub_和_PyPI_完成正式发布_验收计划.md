# 【验收主题】0.2.0 在 GitHub 和 PyPI 完成正式发布

- 验收主题：0.2.0 在 GitHub 和 PyPI 完成正式发布

## 1. 本次需求与验收目标

### 需求来源

- [产品总说明：当前正式版本和唯一版本号规则](../spec/产品总说明.md#6-产品通用规则)

- [更新已安装项目：更新到最新正式版本](../spec/功能_更新已安装项目.md#4-规则)

### 验收目标

用户能够从 GitHub 正式发布页和 PyPI（Python 公共软件包仓库）取得同一个 `workflow-loop 0.2.0`，使用公开安装入口或从 `0.1.0` 更新后得到版本身份为 `workflow-loop 0.2.0` 的命令和项目管理文件；发布任务、公开说明、元数据和六个维护脚本均属于同一个最终标签，已经发布的 `0.1.0` 保持不变。

## 3. 验收范围

### 本主题验收

- 源码、命令身份、项目安装标记、README、六个维护脚本和发布流水线使用同一个 `0.2.0`。
- 手动验证任务与 `v0.2.0` 标签正式发布任务的边界。
- 标签任务的完整测试、分发包构建，以及 Ubuntu、macOS、PowerShell 7 和 Windows PowerShell 5.1 验证结果。
- PyPI 与 GitHub Release 的版本、名称、说明、元数据和六个维护脚本附件。
- 从公网安装 `0.2.0`，以及从 `0.1.0` 更新到 `0.2.0` 后的版本身份和项目保留范围。

### 本主题不验收

- 新增产品功能或改变现有工作流规则。
- 覆盖、删除或重发已经公开的 `0.1.0`。
- `0.2.0` 之后的具体版本号和发布时间。
- GitHub、PyPI 之外的分发渠道。
- 要求用户手工准备不同操作系统；最终标签任务的托管环境记录作为跨平台依据。

## 4. 验收条件

### AC-01：全部发布身份统一为 0.2.0

- 条件与触发：本轮版本修改已经完成，准备提交最终代码并创建 `v0.2.0` 标签。
- 预期结果：源码分发版本、`workflow --version` 命令身份、项目安装版本、README 当前安装入口、安装脚本、更新脚本、卸载脚本和发布流水线全部使用 `0.2.0` 或对应标签 `v0.2.0`；GitHub、远端 Git 和 PyPI 在推送前均不存在该版本；历史 `v0.1.0` 标签、GitHub Release 和 PyPI 版本保持不变。任一位置不一致或版本已经存在时，正式发布必须停止。
- 产品设计依据：[产品总说明：每次公开发布使用唯一版本号](../spec/产品总说明.md#6-产品通用规则)、[安装到项目 R9 至 R11 和 R21](../spec/功能_安装到项目.md#4-规则)

### AC-02：只有 v0.2.0 标签可以公开发布

- 条件与触发：维护者执行手动验证任务、推送普通分支提交，或推送 `v0.2.0` 标签。
- 预期结果：手动任务和普通分支提交只允许执行版本核对、测试、构建和跨平台验证，不上传 PyPI 包，也不创建 GitHub Release；只有准确指向最终主分支提交的 `v0.2.0` 标签可以进入两个公开发布任务。
- 产品设计依据：[安装到项目 R10、R11 和 R21](../spec/功能_安装到项目.md#4-规则)

### AC-03：最终标签任务全部成功

- 条件与触发：维护者推送指向最终主分支提交的 `v0.2.0` 标签。
- 预期结果：标签任务依次完成版本身份核对、项目完整测试、分发包构建，以及 Ubuntu、macOS、PowerShell 7 和 Windows PowerShell 5.1 的安装、更新与卸载验证；全部前置任务通过后才上传 PyPI 并创建 GitHub Release，最终全部任务成功。任一前置任务失败时，后续公开发布任务不继续。
- 产品设计依据：[安装到项目 R11 和 R21](../spec/功能_安装到项目.md#4-规则)、[更新已安装项目 R18](../spec/功能_更新已安装项目.md#4-规则)、[卸载 Workflow Loop R18](../spec/功能_卸载_Workflow_Loop.md#4-规则)

### AC-04：两个公开渠道内容一致并提供六个脚本

- 条件与触发：最终标签任务完成 PyPI 和 GitHub Release 发布。
- 预期结果：PyPI 公开显示 `workflow-loop 0.2.0`，并保留中文说明、作者 `yuzyf`、MIT 许可证、项目简介和仓库链接；GitHub 正式发布名称为 `Workflow Loop 0.2.0`，发布说明写明三种操作系统、四种工作意图、完整研发三道门、无需开发任务简单流程、更新与卸载、需求追踪、机器执行记录、返回与回退能力及 Python 3.11 或更高版本要求，并附带 `install.sh`、`install.ps1`、`update.sh`、`update.ps1`、`uninstall.sh` 和 `uninstall.ps1`。
- 产品设计依据：[安装到项目 R19 至 R21](../spec/功能_安装到项目.md#4-规则)、[更新已安装项目 R18](../spec/功能_更新已安装项目.md#4-规则)、[卸载 Workflow Loop R18](../spec/功能_卸载_Workflow_Loop.md#4-规则)

### AC-05：公网安装和从 0.1.0 更新后得到 0.2.0

- 条件与触发：用户在不使用本地源码或本地构建缓存的环境中使用 `0.2.0` 公开安装入口，或在完整安装 `0.1.0` 的项目根目录更新到 `0.2.0`。
- 预期结果：执行 `workflow --version` 返回 `workflow-loop 0.2.0`，新安装或更新后的项目安装版本为 `0.2.0`；更新保留当前轮次状态、操作历史、回退资料、业务代码和正式产物；GitHub Release 的六个维护脚本均可公开下载。
- 产品设计依据：[安装到项目 R2、R3、R9、R15、R17 和 R21](../spec/功能_安装到项目.md#4-规则)、[更新已安装项目 R1 至 R18](../spec/功能_更新已安装项目.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-05 全部通过，并保存最终提交、`v0.2.0` 标签任务、PyPI 页面、GitHub Release、六个附件和公网安装或更新结果作为证据后，本主题才算完成。
- 任一版本身份不一致、自动任务失败、公开渠道缺失、附件不完整、历史 `0.1.0` 被改写，或者公网安装与更新没有得到 `workflow-loop 0.2.0`，都不能宣布本次正式发布完成。
