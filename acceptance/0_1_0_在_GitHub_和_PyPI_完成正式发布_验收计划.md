# 【验收主题】0.1.0 在 GitHub 和 PyPI 完成正式发布

- 验收主题：0.1.0 在 GitHub 和 PyPI 完成正式发布

## 1. 本次需求与验收目标

### 需求来源

- [产品总说明：公开安装和唯一版本号规则](../spec/产品总说明.md#6-产品通用规则)
- [安装到项目：本次正式发布规则](../spec/功能_安装到项目.md#4-规则)

### 验收目标

用户能够从公开的 GitHub（代码托管平台）正式发布页和 PyPI（Python 公共软件包仓库）取得同一份 `workflow-loop 0.1.0`（Python 分发包及版本），使用公开安装入口后得到版本身份为 `workflow-loop 0.1.0` 的命令行工具；两个公开渠道同时提供正确说明、元数据和安装附件，并有最终标签任务的真实成功记录。

## 3. 验收范围

### 本主题验收

- 最终 `v0.1.0`（版本 0.1.0 标签）与主分支最终提交的对应关系。
- 标签触发的完整测试、构建、三种操作系统安装验证和两个公开渠道的发布顺序。
- PyPI 项目页面和 GitHub 正式发布页的名称、版本、说明、元数据和两个安装附件。
- 从公开来源安装 `workflow-loop 0.1.0` 后得到的命令版本身份。
- 本次 `0.1.0` 发布完成的公开页面、任务和安装证据。

### 本主题不验收

- 下一个版本号、自动升级、版本迁移和多版本兼容。
- 删除、覆盖、重发或重复使用已经上传到 PyPI 的 `0.1.0`。
- 要求用户手工准备三种操作系统；最终标签任务的自动验证记录作为跨平台依据。
- 旧分支任务是否成功；旧记录只能作为发布链路基线，不能代替本次最终标签证据。
- 营销网站、英文文档和 GitHub、PyPI 之外的分发渠道。

## 4. 验收条件

<a id="ac-01"></a>
### AC-01：最终发布身份和前置条件一致

- 条件与触发：主题“公开项目身份和中文说明保持一致”对应的交付内容已经完成并通过发布前检查，最终源码已提交到新仓库主分支，准备推送 `v0.1.0`（版本 0.1.0 标签）。
- 预期结果：推送前 GitHub 正式发布页和 PyPI（Python 公共软件包仓库）均不存在本次版本；标签准确指向包含仓库改名、README（项目说明文档）、许可证、分发元数据和发布配置的最终主分支提交；源码发行版本、安装脚本、命令身份和项目安装标记全部为 `0.1.0`；普通分支提交和手动验证任务不会公开发布；文档不声称以后永久使用 `0.1.0`。任一公开渠道已存在该版本时必须停止，不覆盖或重发。
- 产品设计依据：[产品总说明：每次公开发布使用唯一版本号](../spec/产品总说明.md#6-产品通用规则)、[安装到项目 R10、R11 和 R21](../spec/功能_安装到项目.md#4-规则)

<a id="ac-02"></a>
### AC-02：最终标签任务全部成功

- 条件与触发：维护者推送指向最终主分支提交的 `v0.1.0`（版本 0.1.0 标签）。
- 预期结果：标签任务依次完成版本身份核对、项目完整测试、分发包构建，以及 Ubuntu、macOS、PowerShell 7（新版 Windows 命令行环境）和 Windows PowerShell 5.1（旧版 Windows 命令行环境）的安装验证；全部前置检查通过后才上传 PyPI（Python 公共软件包仓库）并创建 GitHub 正式发布页，最终全部任务成功。任一前置任务失败时，后续发布任务不继续。
- 产品设计依据：[安装到项目 R11 和 R21](../spec/功能_安装到项目.md#4-规则)

<a id="ac-03"></a>
### AC-03：两个公开渠道内容一致

- 条件与触发：最终标签任务完成两个公开渠道的发布。
- 预期结果：PyPI（Python 公共软件包仓库）公开显示 `workflow-loop 0.1.0`，并展示中文说明、作者 `yuzyf`、MIT 许可证、固定项目简介和新仓库链接；GitHub 正式发布名称为 `Workflow Loop 0.1.0`（用户可见产品名及版本），发布说明包含三个系统的一条命令安装、三种工作意图、三道门、需求追踪、机器执行记录、返回与回退能力及 Python 3.11 或更高版本要求，并附带 `install.sh`（macOS 和 Linux 安装脚本）和 `install.ps1`（Windows 安装脚本）。
- 产品设计依据：[安装到项目 R20 和 R21](../spec/功能_安装到项目.md#4-规则)

<a id="ac-04"></a>
### AC-04：公开安装得到正确版本

- 条件与触发：用户在没有使用本地源码或本地构建缓存的全新环境中，使用公开安装入口安装本次正式版本。
- 预期结果：公开来源提供并安装 `workflow-loop==0.1.0`（明确版本的 Python 分发包）；执行 `workflow --version`（查看命令行工具版本）返回 `workflow-loop 0.1.0`；GitHub 正式发布页上的两个安装脚本可以公开下载；三个操作系统的安装结果有最终标签任务的成功记录。
- 产品设计依据：[安装到项目 R2、R3、R9、R17 和 R21](../spec/功能_安装到项目.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-04 全部通过，并保存最终提交、标签任务、PyPI 页面、GitHub 正式发布页和公开安装结果作为证据后，本主题才算完成。
- 任一公开渠道缺失、标签未指向最终提交、自动任务失败、附件或元数据不完整，或者公开安装没有得到 `workflow-loop 0.1.0`，都不能宣布本次正式发布完成。
