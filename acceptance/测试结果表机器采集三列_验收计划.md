## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 2026-09-08 轮次 2026-09-08-0228 实证：AI 漏填 test_result 表通过三道门后到整体验收才发现，补填时机错误触发哈希失效退回重走全程。

### 验收目标

## 2. 产品设计依据

## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

### 本主题不验收

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01测试结果三列程序回填"></a>
### AC-01：测试结果三列程序回填

- 开始前状态：qa 环节测试任务已登记且真实执行完成，test_result 表存在但三列（测试项编号、执行结论、机器记录编号）尚未填写
- 触发动作：AI 在 qa 环节执行 workflow test run 后触发表同步（或执行 workflow gate qa 第二道门）
- 可检查结果：查看 .workflow_loop/records/<工作流编号>/test_result_<主题>.json 的测试结果行与 state.json 中该主题测试任务的当前记录
- 通过标准：每个已执行测试项的行自动出现：测试项编号与登记任务一致、执行结论为当前记录的 passed/failed、机器记录编号为当前有效 RUN 编号；AI 未手填时也有值
- 不通过标准：任一列缺失、与当前记录不一致、或需要 AI 手抄才出现值
- 产品设计依据：[工作记录表与正式文档生成 R26](../spec/功能_工作记录表与正式文档生成.md#r-26)

<a id="ac-02"></a>
<a id="ac-02重跑后三列随记录刷新"></a>
### AC-02：重跑后三列随记录刷新

- 开始前状态：测试代码或输入变化导致部分测试项重新执行，机器记录编号已更新
- 触发动作：AI 再次执行 workflow test run 完成重跑后触发表同步
- 可检查结果：查看 test_result 表对应行的机器记录编号
- 通过标准：重跑过的测试项编号变为新 RUN 编号，未重跑且记录仍有效的行保持原编号；不存在旧编号残留
- 不通过标准：重跑后仍是旧编号、或未重跑的有效行被误改
- 产品设计依据：[工作记录表与正式文档生成 R26](../spec/功能_工作记录表与正式文档生成.md#r-26)

<a id="ac-03"></a>
<a id="ac-03叙述列与格式不受采集影响"></a>
### AC-03：叙述列与格式不受采集影响

- 开始前状态：test_result 表已有 AI 填写的实际结果说明等叙述内容
- 触发动作：程序执行三列回填（含多次重复回填）
- 可检查结果：查看表内实际结果说明列与表结构
- 通过标准：实际结果说明等 AI 叙述列逐字保留；表版本、程序专用字段不变；三列格式与门禁校验口径一致
- 不通过标准：叙述列被清空或改写、程序字段被篡改、回填值被门禁格式校验拒绝
- 产品设计依据：[工作记录表与正式文档生成 R18](../spec/功能_工作记录表与正式文档生成.md#r-18)

<a id="ac-04"></a>
<a id="ac-04无任务时安全降级"></a>
### AC-04：无任务时安全降级

- 开始前状态：某主题没有已登记的测试任务（例如纯人工主题）或任务未执行
- 触发动作：程序对该主题的 test_result 表执行回填
- 可检查结果：查看该主题表的测试结果行与程序输出
- 通过标准：无任务的表保持空（由既有空表守卫报尚未填写），不伪造行、不报错崩溃；未执行任务的主题不被写入 passed
- 不通过标准：为无任务主题伪造通过行、或采集过程崩溃
- 产品设计依据：[工作记录表与正式文档生成 R11](../spec/功能_工作记录表与正式文档生成.md#r-11)
