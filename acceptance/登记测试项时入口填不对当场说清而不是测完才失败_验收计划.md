# 【验收主题】登记测试项时入口填不对当场说清而不是测完才失败

- 工作流编号：2026-09-03-0231-bugfix
- 验收主题：登记测试项时入口填不对当场说清而不是测完才失败

## 1. 本次需求与验收目标

### 需求来源

- 用户报告：在一个使用 vitest 适配器的真实轮次里，按填写说明字面填纯测试标题，13 个测试项登记无警告、测试全部真实通过，门禁仍全判失败。
- 本轮缺陷复现记录 [登记测试项时入口填不对当场说清而不是测完才失败](../bug/缺陷_登记测试项时入口填不对当场说清而不是测完才失败.md) 已确认现象、根因和影响面。

### 验收目标

- 本主题完成后，测试计划表里的“正式目标名称”一列有清楚可照抄的填法，填不对时在按表登记那一步就被拦下并说明该怎么改；一个测试项由多个测试函数覆盖时也能在这一格如实登记。真实通过的测试不会再因为这一格的写法被判失败。

## 2. 产品设计依据

- 工作记录表与正式文档生成 R20 要求每个填写说明写到让不了解背景的填写者一次填对的深度，并点名正式目标名称必须与报告适配器输出的目标名逐字一致。
- 工作记录表与正式文档生成 R15 要求表模式承接文档模式对固定事实的全部校验，不得因为走表而跳过任何原有检查；文档模式对测试入口本来就有形状校验。
- 编写并执行测试 R9 允许同一测试项的多个测试函数合并为一条命令，R10 要求实际执行的正式目标名称与登记名称一致才算通过。

## 3. 验收范围

### 本主题验收

- 测试计划工作记录表中“正式目标名称”和“测试入口”两列的填写说明文字。
- 按表登记测试项时对入口形状的检查，以及检查失败时输出的位置、实际值和正确形状。
- 测试验证环节第二道门的表校验对同一问题的报告。
- 一个测试项登记多个入口的能力，以及多入口在真实执行后的判定。
- 已经按正确形状填写的表在本次修改后的登记与执行结论。

### 本主题不验收

- 结构化报告的判定标准本身不改：报告里的目标必须与登记入口双向一一对应、跳过数和失败数必须为零这些要求保持原样。
- 没有启用工作记录表的旧轮次走的文档模式解析与校验，本轮不动。
- 同一个测试文件的测试项分属不同主题时并行执行相互干扰的问题，不在本主题范围内。
- 缺陷索引行不随工作记录表内容更新刷新的现象，不在本主题范围内。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
### AC-01：两列说明写清怎么填

- 开始前状态：一个启用工作记录表的轮次走到测试验证环节，程序刚生成测试计划工作记录表，表里带程序写入的填写说明。
- 触发动作：AI 打开该表，读“正式目标名称”和“测试入口”两列的填写说明。
- 可检查结果：这两条填写说明的实际文字。
- 通过标准：“正式目标名称”的说明同时写出四件事：必须写成 项目相对路径::报告里的目标名、一个可直接照抄的具体例子、一个测试项覆盖多个测试函数时怎样在这一格填多个入口、以及这一列是登记入口的唯一来源。“测试入口”的说明写明它只进入生成的测试计划文档，不作为登记入口。
- 不通过标准：任一条说明缺少必须形状、缺少多入口写法，或没有写明哪一列决定登记。
- 产品设计依据：[工作记录表与正式文档生成 R20](../spec/功能_工作记录表与正式文档生成.md#r-20)

<a id="ac-02"></a>
### AC-02：填不对当场被拒绝

- 开始前状态：测试计划工作记录表里某个自动化测试项的“正式目标名称”写成纯测试标题，没有用 :: 连接项目相对路径。
- 触发动作：AI 执行 workflow test prepare --from-tables 按表登记测试项；随后在同一份表上执行 workflow gate qa 做第二道门检查。
- 可检查结果：两条命令各自输出的问题清单，以及工作流状态文件里该测试项有没有被写入登记任务。
- 通过标准：登记命令以失败结束并列出该问题，写明验收主题、测试项编号、列名“正式目标名称”、实际填的值和正确形状；状态文件里没有为该测试项写入任何登记任务。第二道门的表校验把同一个问题作为格式问题报出，位置写到行清单名称、行号和列名。
- 不通过标准：登记命令成功返回；或问题文字里缺少列名、实际值或正确形状；或状态文件里仍写入了该测试项的登记任务；或第二道门放行这张表。
- 产品设计依据：[工作记录表与正式文档生成 R15](../spec/功能_工作记录表与正式文档生成.md#r-15)

<a id="ac-03"></a>
### AC-03：一个测试项能登记多个入口

- 开始前状态：一个自动化测试项由同一个测试文件里的两个测试函数覆盖，登记的命令一次运行这两个函数。
- 触发动作：AI 按“正式目标名称”的填写说明在这一格填入这两个入口，执行 workflow test prepare --from-tables，再执行 workflow test run。
- 可检查结果：该测试项登记的入口清单，以及执行后机器记录里的判定、精确匹配入口和实际执行数。
- 通过标准：登记的入口是两条，分别等于两个测试函数的 项目相对路径::标识，不是把两条并成的一个字符串；真实执行后该测试项判定 passed，机器记录的精确匹配入口同样是这两条，实际执行数为 2，跳过数、失败数和错误数都是 0。
- 不通过标准：登记入口只剩一条或仍是一个含分隔符的整串；或执行后判定 failed 并报未登记的原始测试入口。
- 产品设计依据：[编写并执行测试 R9](../spec/功能_编写并执行测试.md#r-9)

<a id="ac-04"></a>
### AC-04：已经填对的表不受影响

- 开始前状态：一份“正式目标名称”已经写成单个 项目相对路径::标识 的测试计划工作记录表，它对应的测试真实通过。
- 触发动作：AI 执行 workflow test prepare --from-tables，再执行 workflow test run。
- 可检查结果：该测试项登记的入口清单、执行判定和机器记录。
- 通过标准：登记入口仍是那一条原值，执行判定为 passed，机器记录的精确匹配入口与登记入口一一对应，与本次修改前的结论相同。
- 不通过标准：原本能通过的填法被新校验拒绝登记，或执行判定从 passed 变成 failed。
- 产品设计依据：[编写并执行测试 R10](../spec/功能_编写并执行测试.md#r-10)

## 5. 完成判定

- AC-01 至 AC-04 四条验收条件在一次真实执行中全部得到通过结论，本主题才算完成。
