## 4. 验收条件

<a id="ac-01"></a>
### AC-01：三类索引程序生成

- 开始前状态：新轮次各环节表已生成
- 触发动作：查看 acceptance/索引.md、impl/索引.md、qa/索引.md 的生成方式
- 可检查结果：索引由程序按各主题表汇总生成，主题关系从验收主题表继承，AI 不手写
- 通过标准：索引内容与表一致；删除索引后可重新生成
- 不通过标准：索引需 AI 手写固定表头，或与表不一致
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R9

<a id="ac-02"></a>
### AC-02：穿刺结论文档按表生成

- 开始前状态：spike 环节表已生成并填写
- 触发动作：AI 在表中填写穿刺结论后过第二道门
- 可检查结果：穿刺结论文档由程序按表生成，门禁查表
- 通过标准：表内容与文档一致；文档手改按 AC 手改规则处理
- 不通过标准：穿刺文档仍需手写全部固定结构且与表脱节
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R3

<a id="ac-03"></a>
### AC-03：表随轮次的生命周期

- 开始前状态：分别观察整轮作废、正式收工和从零清场三种结束方式
- 触发动作：分别执行作废、收工或清场对应命令后检查 .workflow_loop/records/ 目录
- 可检查结果：作废时本轮表被删除；收工后本轮表保留；从零清场保留旧轮次表
- 通过标准：三种场景下表的存在状态与规则一致
- 不通过标准：作废后表残留、收工后表丢失或清场误删旧表
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R10
<a id="ac-04"></a>
### AC-04：缺陷记录按表生成

- 开始前状态：修复缺陷轮次进入缺陷复现环节，程序已生成该缺陷的工作记录表。
- 触发动作：AI 在表中填写缺陷现象、复现步骤、预期行为和根因后执行缺陷复现第二道门。
- 可检查结果：缺陷记录文档由程序按表生成；门禁核对表栏目、内容完整性和文档未被手改。
- 通过标准：表填写完整时门禁通过且文档与表一致；栏目缺失或为空时一次列出全部问题。
- 不通过标准：文档固定结构需要 AI 手写，或文档与表不一致仍放行。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R3、R4。

<a id="ac-05"></a>
### AC-05：最终设计同步固定字段进表

- 开始前状态：最终设计同步环节的工作记录表已由程序生成。
- 触发动作：AI 在表中填写核对结论、设计影响和代码影响后执行该环节第二道门。
- 可检查结果：门禁读表核对固定字段完整并核对文档未被手改；同步结论文档由程序按表生成。
- 通过标准：表填写完整时门禁通过。
- 不通过标准：固定字段缺失仍放行，或要求手写固定结构。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R3、R4。

<a id="ac-06"></a>
### AC-06：产品功能清单进表

- 开始前状态：产品设计环节的工作记录表已生成，功能清单已由用户确认。
- 触发动作：AI 完成产品设计文档后执行 spec 第二道门。
- 可检查结果：产品总说明的功能清单由程序按表写入；每个功能链接目标由程序核对真实存在；清单与功能文档一一对应。
- 通过标准：清单与表一致且链接目标存在时门禁通过；不一致或缺失时按表检查失败列出。
- 不通过标准：清单与表不一致仍放行，或链接目标缺失未报告。
- 产品设计依据：[工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md#4-规则) R3、R4。
