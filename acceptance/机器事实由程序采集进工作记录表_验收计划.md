# 【验收主题】机器事实由程序采集进工作记录表

- 工作流编号：2026-09-08-0228-product_change
- 验收主题：机器事实由程序采集进工作记录表

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户核心诉求：AI 只填内容不碰格式，行号、编号、链接由代码采集（2026-09-08 产品总说明修改记录）。

<a id="验收目标"></a>
### 验收目标

- 实施改动的文件与行号、验收结果五列、编号引用格式、测试标识、穿刺资产引用全部由程序采集或生成写入工作记录表，AI 只填写叙述内容，抄错格式被门禁打回的反复从机制上消除。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- 工作记录表与正式文档生成功能 R25 至 R29。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- R25 实施改动采集（含计划外文件两种来源顺序与报错口径）。
- R26 验收结果五列程序回填与 failed/blocked 处理。
- R27 编号引用程序渲染、本主题限定、断档合法。
- R28 测试标识程序生成。
- R29 穿刺资产引用程序回填与表版本升 4。

<a id="本主题不验收"></a>
### 本主题不验收

- 无代码改动跳过全量回归（由主题 B 验收）。
- 门禁失败输出带机器事实（由主题 C 验收）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01实施改动程序采集"></a>
### AC-01：实施改动程序采集

- 开始前状态：一轮已通过实施环节第一道门，实施前回退基线已保存，AI 已完成代码修改但尚未填写实施记录表
- 触发动作：AI 在实施环节执行采集命令，请求程序按实施前基线与最终文件差异计算文件与代码位置
- 可检查结果：实施记录表中实际代码修改与实施动作记录行的文件列、代码位置列由程序写入，格式为程序生成的行号范围；表内同时记录采集时的文件内容指纹
- 通过标准：采集结果与门禁重算差异完全一致；采集后文件再变化时门禁报请重新采集；重新采集只刷新文件与代码位置两列，AI 已填的叙述列保持原值
- 不通过标准：门禁重算与表内不一致仍放行；重新采集清空或改写 AI 叙述列；采集后文件变化不报错
- 产品设计依据：[工作记录表与正式文档生成 R25](../spec/功能_工作记录表与正式文档生成.md#r-25)

<a id="ac-02"></a>
<a id="ac-02计划外文件明确处理"></a>
### AC-02：计划外文件明确处理

- 开始前状态：实施前回退基线已保存，代码修改计划登记路径之外的文件存在新建或修改
- 触发动作：AI 执行采集命令时，程序遇到不在计划登记路径内的文件
- 可检查结果：计划外新建文件登记为新文件全部行为新增；计划外修改文件按回退副本优先、无副本用进场 Git 基线提交号取改动前内容并算出行号；两种来源都取不到时报错
- 通过标准：新建文件按全部新增登记不报错；能取到改动前内容的文件算出行号；取不到时报错含文件名和下一步指引（补进代码修改计划重新准备基线，或恢复进场内容），不静默跳过、不填占位行号
- 不通过标准：取不到改动前内容时报错不含文件名或下一步；静默漏登记该文件；填 0 或假行号等占位值
- 产品设计依据：[工作记录表与正式文档生成 R25](../spec/功能_工作记录表与正式文档生成.md#r-25)

<a id="ac-03"></a>
<a id="ac-03验收结果五列程序回填"></a>
### AC-03：验收结果五列程序回填

- 开始前状态：主题验收环节已产生程序验收记录（含验收方式、结论、机器测试记录编号、用户实际回答、人工确认），AI 已填写验收结果表的验收说明栏
- 触发动作：AI 填写验收结果表时，程序从状态记录回填验收方式、验收结论、机器测试记录编号、用户实际回答、人工确认五列
- 可检查结果：验收结果表五列的值与状态记录中当前有效验收记录逐字段一致；纯自动化条件的不适用字段由程序按验收方式归并写入
- 通过标准：五列与状态记录精确一致才放行；AI 填写的叙述与记录不一致时以记录为准并报差异；验收结论为 failed 或 blocked 时程序清除该主题验收记录并把表行标记待重做，AI 叙述保留
- 不通过标准：五列允许 AI 手抄后通过与记录不一致的值；failed 或 blocked 清除时把 AI 叙述一并删除；标记待重做后叙述丢失
- 产品设计依据：[工作记录表与正式文档生成 R26](../spec/功能_工作记录表与正式文档生成.md#r-26)

<a id="ac-04"></a>
<a id="ac-04编号引用程序渲染校验"></a>
### AC-04：编号引用程序渲染校验

- 开始前状态：主题的验收计划表、测试计划表已存在，表内行由程序分配编号
- 触发动作：AI 在表内引用编号（对应验收条件、前置测试项、对应计划步骤）时只写编号本身，生成文档时由程序渲染完整格式
- 可检查结果：生成文档中的编号引用渲染为带链接和锚点的完整格式；门禁校验被引用编号在本主题对应表中真实存在
- 通过标准：引用本主题内真实存在的编号才通过；AI 删除中间行后编号保持已分配值不重排、断档合法；引用已删除编号时报该编号对应的行已删除并给出当前可用编号；跨主题引用不被编号引用支持，需要时走叙述栏
- 不通过标准：引用跨主题编号通过；断档编号被报错；引用不存在编号时通过或不提示当前可用编号
- 产品设计依据：[工作记录表与正式文档生成 R27](../spec/功能_工作记录表与正式文档生成.md#r-27)

<a id="ac-05"></a>
<a id="ac-05测试标识程序生成"></a>
### AC-05：测试标识程序生成

- 开始前状态：测试验证环节测试计划表已填写，测试入口列有值，AI 准备编写测试代码
- 触发动作：AI 登记测试任务时，程序按测试计划表生成 Workflow-Test 标识标准文本并输出
- 可检查结果：输出的标识文本含测试入口且与测试计划表一致；AI 复制粘贴到测试代码 docstring；门禁按原规则校验标识与计划一致
- 通过标准：标识由程序生成，一致性校验变为程序自校验；AI 移动测试函数或改文件名导致标识与实际位置不符时，门禁报位置不一致，AI 重新登记生成新标识替换
- 不通过标准：AI 逐字段手抄计划内容生成标识仍通过；位置变化后不报错
- 产品设计依据：[工作记录表与正式文档生成 R28](../spec/功能_工作记录表与正式文档生成.md#r-28)

<a id="ac-06"></a>
<a id="ac-06表版本升4旧轮次不迁移"></a>
### AC-06：表版本升4旧轮次不迁移

- 开始前状态：项目内存在 v1 至 v3 表版本的旧轮次记录和新开始的轮次
- 触发动作：新轮次进入环节加载材料时程序生成表，旧轮次记录保持原样
- 可检查结果：新轮次生成的表表版本为 4 并通过校验；旧轮次的表按开工时冻结的版本判定继续有效；需求交付追踪表穿刺列的机器事实由程序从状态记录回填
- 通过标准：v4 表通过校验；旧轮次 v1 至 v3 表不迁移、不报版本错误；穿刺资产引用由程序回填后，登记变化不使引用失效
- 不通过标准：旧轮次被强制迁移到 v4；旧版本表被报版本不符；穿刺资产引用仍需 AI 手抄
- 产品设计依据：[工作记录表与正式文档生成 R29](../spec/功能_工作记录表与正式文档生成.md#r-29)、[R11](../spec/功能_工作记录表与正式文档生成.md#r-11)
