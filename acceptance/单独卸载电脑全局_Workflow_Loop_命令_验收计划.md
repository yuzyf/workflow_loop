# 【验收主题】单独卸载电脑全局 Workflow Loop 命令

- 验收主题：单独卸载电脑全局 Workflow Loop 命令

## 1. 本次需求与验收目标

### 需求来源

- [产品总说明：全局卸载场景和通用规则](../spec/产品总说明.md)
- [卸载 Workflow Loop](../spec/功能_卸载_Workflow_Loop.md)
- [Windows 辅助进程穿刺结论](../spec/穿刺_Windows_辅助进程替换或删除正在运行的全局命令.md)

### 验收目标

项目维护者单独选择电脑全局卸载并确认影响后，电脑上的全局 `workflow` 命令和能够确认由 Workflow Loop 写入的命令搜索路径被删除；任何项目文件保持不变，来源不明或删除失败的内容被明确保留和报告。

- [卸载 Workflow Loop：全局卸载支持范围、规则、使用过程和异常情况](../spec/功能_卸载_Workflow_Loop.md)
- [Windows 辅助进程穿刺结论](../spec/穿刺_Windows_辅助进程替换或删除正在运行的全局命令.md#7-结论)

## 3. 验收范围

### 本主题验收

- `workflow uninstall --global` 的独立电脑级范围、一次确认和其它项目暂时不可运行的警告。
- 全局命令和来源明确的命令搜索路径删除，以及来源不明路径保留。
- 不扫描、不读取和不删除任何项目文件。
- Windows PowerShell 5.1 与 PowerShell 7 中正在运行命令完成全局卸载并准确报告结果。
- 部分失败后的真实清单、重试边界和 README（项目说明文档）中的全局卸载说明。

### 本主题不验收

- 当前项目或其它项目的 `AGENTS.md`、`.workflow_loop/`、业务代码和正式产物删除。
- 扫描电脑统计仍依赖全局命令的项目。
- 来源无法确认的命令搜索路径强制删除，或恢复已经删除的电脑级内容。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
### AC-01：全局范围单独确认并明确警告

- 条件与触发：用户执行 `workflow uninstall --global`，程序尚未取得用户确认。
- 预期结果：程序显示全局 `workflow` 命令、能够确认的命令搜索路径，并说明其它已安装项目将暂时不能执行 Workflow Loop；只询问一次，用户取消时不修改电脑或项目内容。
- 产品设计依据：[卸载 Workflow Loop R12](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-02"></a>
### AC-02：全局卸载绝不扩大到项目

- 条件与触发：用户确认电脑全局卸载，当前目录或电脑上存在一个或多个已经安装 Workflow Loop 的项目。
- 预期结果：程序不扫描这些项目，也不读取或删除当前项目及其它项目的任何文件；只处理电脑级全局命令和命令搜索路径。
- 产品设计依据：[卸载 Workflow Loop R13](../spec/功能_卸载_Workflow_Loop.md#4-规则)、[卸载 Workflow Loop：不支持范围](../spec/功能_卸载_Workflow_Loop.md#32-不支持范围)

<a id="ac-03"></a>
### AC-03：只删除来源明确的电脑级内容

- 条件与触发：用户确认全局卸载，检测到全局命令和一个或多个可能关联的命令搜索路径。
- 预期结果：程序删除全局 `workflow` 命令和能够确认由 Workflow Loop 安装写入的命令搜索路径；无法确认来源的路径不删除，并显示保留路径和原因。
- 产品设计依据：[卸载 Workflow Loop R13、R14](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-04"></a>
### AC-04：受支持的 Windows PowerShell 能完成自卸载

- 条件与触发：用户在 Windows PowerShell 5.1 或 PowerShell 7 中从正在运行的全局 `workflow` 命令确认电脑全局卸载。
- 预期结果：当前命令退出后，全局命令和能够确认的工具环境继续被删除；两种 PowerShell 都根据真实退出码返回结果，不把 uv 的正常进度文字误报为卸载失败。
- 产品设计依据：[产品总说明：支持原生 Windows PowerShell](../spec/产品总说明.md#41-支持范围)、[卸载 Workflow Loop R13、R16](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-05"></a>
### AC-05：部分失败可以核实和重试

- 条件与触发：全局命令或能够确认的命令搜索路径只有一部分删除成功，或者最终核对发现目标内容仍然存在。
- 预期结果：程序不恢复已经删除的内容，明确列出已删除项、未删除项和失败原因并允许重新执行；只有目标范围内能够确认的电脑级内容全部删除后才显示成功。
- 产品设计依据：[卸载 Workflow Loop R15、R16](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-06"></a>
### AC-06：公开说明区分项目卸载和全局卸载

- 条件与触发：维护者发布包含卸载功能的新正式版本，用户查看 README（项目说明文档）。
- 预期结果：README 分别说明项目卸载和 `workflow uninstall --global`；全局卸载说明明确写出不会删除项目文件，但会让依赖全局命令的项目暂时无法运行。
- 产品设计依据：[卸载 Workflow Loop R12、R13、R18](../spec/功能_卸载_Workflow_Loop.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-06 全部通过，本主题才算完成。
- 全局卸载扫描或删除项目、强制删除来源不明路径、Windows 把正常工具输出误报为失败，或者部分失败没有列出真实残留，本主题均不通过。
