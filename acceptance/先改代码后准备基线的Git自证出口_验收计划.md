# 【验收主题】先改代码后准备基线的Git自证出口

- 工作流编号：2026-09-08-1207-product_change
- 验收主题：先改代码后准备基线的Git自证出口

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 2026-09-08 轮次 1207 实证：先完成代码开发后执行 collect 与 --prepare-code 均被进场后变化拦截，无出口，行号被迫手算。

<a id="验收目标"></a>
### 验收目标

- 真实工作流中 AI 常先写代码后准备回退基线；此时只要 Git 能证明进场时内容，程序应自动补齐首次副本，让 prepare 和 collect 链路可自愈，不再要求人工恢复文件。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- 实施并保护项目修改的回退保护规则；第二次准备已实现的 _trusted_git_head_baseline（Git HEAD 补齐副本）逻辑延伸到首次准备。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 首次准备的 Git 自证放行、不可自证时拒绝、collect 链路打通三个行为。

<a id="本主题不验收"></a>
### 本主题不验收

- 未跟踪文件的进场内容推断（仍拒绝）；回退执行的恢复行为（既有规则不变）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01已修改文件可用git自证原内容"></a>
### AC-01：已修改文件可用Git自证原内容

- 开始前状态：impl 讨论已确认，AI 已直接修改代码（未先准备回退基线），修改的文件被 Git HEAD 跟踪
- 触发动作：AI 执行 workflow gate impl --prepare-code 准备回退基线
- 可检查结果：查看准备结果与回退清单副本内容
- 通过标准：对每个计划文件：若该文件被 Git HEAD 跟踪且进场观察快照时的内容等于 HEAD 版本，程序用 HEAD 字节作为实施前原内容存副本，准备成功；清单正常生成
- 不通过标准：可以自证却仍报 代码已经在回退基线保存前发生变化 拒绝；或用当前修改后内容冒充原内容
- 产品设计依据：[实施并保护项目修改 R5](../spec/功能_实施并保护项目修改.md#r-5)

<a id="ac-02"></a>
<a id="ac-02无法自证时保持原有拒绝"></a>
### AC-02：无法自证时保持原有拒绝

- 开始前状态：计划文件在进场后已修改，且不能用 Git HEAD 证明进场时内容（例如未跟踪文件或进场后才有提交）
- 触发动作：AI 执行 workflow gate impl --prepare-code
- 可检查结果：查看准备命令的输出结果与错误说明
- 通过标准：仍按原规则拒绝并说明缺少可信原内容；不降低回退安全性
- 不通过标准：无法自证却放行；副本内容与进场时不符
- 产品设计依据：[实施并保护项目修改 R5](../spec/功能_实施并保护项目修改.md#r-5)

<a id="ac-03"></a>
<a id="ac-03采集链路随之打通"></a>
### AC-03：采集链路随之打通

- 开始前状态：回退清单已通过 Git 自证方式生成，代码与清单内容存在差异
- 触发动作：AI 执行 workflow collect 采集实施改动
- 可检查结果：采集写入实施记录表的文件与代码位置列
- 通过标准：采集成功：文件行号由程序按副本与最终文件差异计算，采集指纹记录；与先准备后改代码的常规路径结果一致
- 不通过标准：采集仍报缺少回退清单；或行号与真实差异不符
- 产品设计依据：[工作记录表与正式文档生成 R25](../spec/功能_工作记录表与正式文档生成.md#r-25)
