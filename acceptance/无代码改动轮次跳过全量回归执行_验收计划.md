# 【验收主题】无代码改动轮次跳过全量回归执行

- 验收主题：无代码改动轮次跳过全量回归执行

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户需求：全量验收要能跳过步骤，小改动别走全套流程（2026-09-08 产品总说明修改记录）。

<a id="验收目标"></a>
### 验收目标

- 只改文档、不改代码的轮次不再空跑一次全量测试；省下的是执行时间，不省任何确认门。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- 验收并完成交付功能 R9、R9a。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- R9 差异判定跳过与依据记录。
- 差异无法确认时一律运行。
- R9a 跳过后整体验收与最终设计同步照常。

<a id="本主题不验收"></a>
### 本主题不验收

- 工作记录表机器采集（由主题 A 验收）。
- 门禁失败输出改进（由主题 C 验收）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01差异为空跳过并留依据"></a>
### AC-01：差异为空跳过并留依据

- 开始前状态：一轮全部主题验收通过，进入最终全量回归环节；本轮产品代码差异与测试代码差异均为空（可能只改了受管文档）
- 触发动作：AI 执行最终全量回归第二道门命令
- 可检查结果：程序按实施前基线与最终文件差异判定；判定依据（差异为空的机器事实、判定时间）写入状态记录；用户在第三道门可查看判定依据
- 通过标准：产品代码差异与测试代码差异都为空时不实际运行测试、第二道门通过；判定依据完整可查；仅测试代码变化时不跳过、照常运行；仅构建或依赖配置变化时不跳过；受管文档变化不影响判定
- 不通过标准：仅文档改动被误判为需要运行测试；跳过后状态记录中没有判定依据；仅测试代码变化被跳过
- 产品设计依据：[验收并完成交付 R9](../spec/功能_验收并完成交付.md#r-9)

<a id="ac-02"></a>
<a id="ac-02差异无法确认一律运行"></a>
### AC-02：差异无法确认一律运行

- 开始前状态：最终全量回归环节，Git 不可读且无可用快照，程序无法确认差异是否为空
- 触发动作：AI 执行最终全量回归第二道门命令
- 可检查结果：程序不凭猜测跳过，统一测试入口真实执行，以退出码判定第二道门
- 通过标准：无法确认差异时一律运行测试；运行结果与退出码如实记录
- 不通过标准：环境异常时静默跳过测试；或报错中断流程不让用户看到原因
- 产品设计依据：[验收并完成交付 R9](../spec/功能_验收并完成交付.md#r-9)

<a id="ac-03"></a>
<a id="ac-03跳过不免除确认门"></a>
### AC-03：跳过不免除确认门

- 开始前状态：最终全量回归按 AC-01 跳过测试执行
- 触发动作：AI 依次执行整体验收和最终代码设计同步环节
- 可检查结果：整体验收环节仍由用户判断需求是否完成并确认；最终设计同步环节核对架构与真实代码一致，无改动时结论为无需修改
- 通过标准：跳过只免除测试执行；整体验收用户确认门照常；最终设计同步照常完成且结论如实
- 不通过标准：跳过测试的同时整体验收或设计同步被自动略过；设计同步在无改动时仍报必须修改
- 产品设计依据：[验收并完成交付 R9a](../spec/功能_验收并完成交付.md#r-9a)

<a id="5-完成判定"></a>
## 5. 完成判定
