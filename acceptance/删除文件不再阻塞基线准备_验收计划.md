# 【验收主题】删除文件不再阻塞基线准备

- 工作流编号：2026-09-09-0901-product_change
- 验收主题：删除文件不再阻塞基线准备

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户在 2026-09-09 提出：实施中删除一些文件后，基线准备门禁总是卡住，这个困扰存在已久。

<a id="验收目标"></a>
### 验收目标

- 实施中删除文件是合法动作：准备实施前基线时不再因文件已被删除而拒绝，作废恢复时无副本文件如实告知，用户不再需要为过门禁去恢复文件或先提交 Git。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- [功能_实施并保护项目修改](../spec/功能_实施并保护项目修改.md) R36（删除文件放行）；[功能_整轮作废并恢复](../spec/功能_整轮作废并恢复.md) R22（无副本文件作废行为）。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 删除已提交文件和从未提交文件两种情况下的基线准备放行。
- 修改文件场景的既有行为不回归。
- 作废恢复时无副本文件的保持删除与告知。

<a id="本主题不验收"></a>
### 本主题不验收

- 临时文件的豁免（由主题“临时产物不再卡实施门禁”验收）。
- 机器采集对删除文件的行号登记（既有 R25 机制已支持“删除整个文件”，非本轮改动）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01删除已提交文件直接放行"></a>
### AC-01：删除已提交文件直接放行

- 开始前状态：被删文件在本轮进场快照中记录为存在，且该文件的内容已提交到 Git；实施过程中该文件被删除
- 触发动作：AI 执行实施前基线准备（workflow gate impl 的准备动作）
- 可检查结果：基线准备命令的完成输出，以及实施前回退清单（JSON）中该被删文件的登记条目内容
- 通过标准：准备成功完成；该文件的原内容副本取自 Git 提交内容（复用既有 Git 自证路径），回退清单登记该副本
- 不通过标准：报“不能把当前修改后内容当作基线”或同类错误；或要求先恢复被删文件
- 产品设计依据：[实施并保护项目修改 R36](../spec/功能_实施并保护项目修改.md#r-36)

<a id="ac-02"></a>
<a id="ac-02删除从未提交文件也放行"></a>
### AC-02：删除从未提交文件也放行

- 开始前状态：被删文件在本轮进场快照中记录为存在，但该文件从未提交过 Git；实施过程中该文件被删除
- 触发动作：AI 执行实施前基线准备（workflow gate impl 的准备动作）
- 可检查结果：基线准备命令的完成输出，以及实施前回退清单（JSON）中该被删文件的登记条目内容
- 通过标准：准备成功完成；回退清单该文件如实登记“无副本”；不要求恢复文件
- 不通过标准：因 Git 中没有该文件记录而拒绝准备（例如报 Git HEAD 不包含该路径）；或要求恢复文件后才能继续
- 产品设计依据：[实施并保护项目修改 R36](../spec/功能_实施并保护项目修改.md#r-36)

<a id="ac-03"></a>
<a id="ac-03修改文件行为不回归"></a>
### AC-03：修改文件行为不回归

- 开始前状态：进场后被修改（未删除）的代码文件，与本轮改动前相同的两种状态：能被 Git 自证（快照内容等于 HEAD）和不能自证（有未提交差异且快照对不上）
- 触发动作：AI 执行实施前基线准备（workflow gate impl 的准备动作）
- 可检查结果：基线准备命令的完成输出或错误信息，显示每个被修改文件被放行还是被拒绝的具体结论
- 通过标准：能 Git 自证的文件放行并用 HEAD 字节补副本；不能自证的按文件列出原因拒绝——两种结果均与本轮改动前的既有行为一致
- 不通过标准：已放行的修改文件场景开始报错；或已拒绝的场景被静默放行
- 产品设计依据：[实施并保护项目修改 R36](../spec/功能_实施并保护项目修改.md#r-36)

<a id="ac-04"></a>
<a id="ac-04作废时无副本文件告知"></a>
### AC-04：作废时无副本文件告知

- 开始前状态：回退清单中存在登记为“无副本”的删除文件（该文件删除时从未提交过 Git）
- 触发动作：用户确认整轮作废，程序执行恢复（workflow abort）
- 可检查结果：恢复输出全文和文件系统状态
- 通过标准：作废成功完成；无副本文件保持删除状态不被恢复；恢复输出列出无副本文件清单并说明实施前内容无法取得
- 不通过标准：因无副本阻塞作废使轮次卡在进行中；或恢复输出完全不提这些文件
- 产品设计依据：[整轮作废并恢复 R22](../spec/功能_整轮作废并恢复.md#r-22)

## 5. 完成判定
