# 【验收主题】最终同步按表更新架构并保护正文

- 工作流编号：2026-09-07-0700-product_change
- 验收主题：最终同步按表更新架构并保护正文

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户要求修复第十七号缺陷，最终同步不能只生成内部记录却要求手工修改正式架构。
- 用户授权 AI 代行本轮日常确认与核对；未要求本轮提交、推送或发布。

<a id="验收目标"></a>
### 验收目标

- AI 填完最终同步事实后，程序直接更新正式架构并通过同来源校验，不再手写第二套固定事实。

## 2. 产品设计依据

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 同步表结论、可选正文变更表、当前有效机器依据、正式架构出口、冲突保护与重复生成。

<a id="本主题不验收"></a>
### 本主题不验收

- 不在最终同步修改产品代码或降低验收标准，不迁移旧轮次的冻结记录表。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01同步正式架构与当前证据"></a>
### AC-01：同步正式架构与当前证据

- 开始前状态：全部主题、最终回归和整体验收已完成，最终同步表填写了完整且真实的核对结论。
- 触发动作：AI 原样执行最终同步阶段检查入口。
- 可检查结果：正式架构包含当前轮次、同步类型、核对结论、核对清单及完整有效机器记录集合。
- 通过标准：程序直接更新正式架构；表、生成文档和最终检查使用一致来源，不混入旧轮次或失效记录。
- 不通过标准：只生成内部记录、正式架构仍是旧轮次、机器依据缺少或串用旧记录均不通过。
- 产品设计依据：[维护代码设计 R25](../spec/功能_维护代码设计.md#r-25)、[R26](../spec/功能_维护代码设计.md#r-26)、[工作记录表 R23](../spec/功能_工作记录表与正式文档生成.md#r-23)、[R24](../spec/功能_工作记录表与正式文档生成.md#r-24)

<a id="ac-02"></a>
<a id="ac-02正文按指定事实更新且稳定"></a>
### AC-02：正文按指定事实更新且稳定

- 开始前状态：已有架构含需要更新的事实和必须保留的正文，可选正文变更表精确填写章节、原文、新文和依据。
- 触发动作：AI 通过最终同步入口生成，再次执行相同生成。
- 可检查结果：仅指定事实和固定同步结论变化，其他正文、标题、表格和已有定位保留。
- 通过标准：每行唯一定位，首次替换准确且重复生成不重复追加或替换；空正文表保留既有正文。
- 不通过标准：误改其他章节、重排表格、丢正文或重复执行产生新差异均不通过。
- 产品设计依据：[维护代码设计 R25](../spec/功能_维护代码设计.md#r-25)、[R26](../spec/功能_维护代码设计.md#r-26)、[工作记录表 R23](../spec/功能_工作记录表与正式文档生成.md#r-23)、[R24](../spec/功能_工作记录表与正式文档生成.md#r-24)

<a id="ac-03"></a>
<a id="ac-03缺证据或正文冲突不覆盖"></a>
### AC-03：缺证据或正文冲突不覆盖

- 开始前状态：同步结论不完整、存在未处理差异、缺少有效机器证据，或正文在生成后被另行修改。
- 触发动作：AI 通过最终同步检查入口尝试再次生成正式架构。
- 可检查结果：程序指出具体缺项或冲突位置，正式架构原文保持不变，不写入猜测的通过结论。
- 通过标准：任何缺项和定位冲突均明确拒绝；手工修改不被覆盖，修正事实后才允许生成。
- 不通过标准：缺证据仍写成一致、覆盖手改正文或用新文命中掩盖原文冲突均不通过。
- 产品设计依据：[维护代码设计 R25](../spec/功能_维护代码设计.md#r-25)、[R26](../spec/功能_维护代码设计.md#r-26)、[工作记录表 R23](../spec/功能_工作记录表与正式文档生成.md#r-23)、[R24](../spec/功能_工作记录表与正式文档生成.md#r-24)

<a id="5-完成判定"></a>
## 5. 完成判定

- 本主题 3 条验收条件全部通过，真实结果和当前机器证据一致后完成；不接受部分通过。
