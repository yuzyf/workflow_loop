# 【验收主题】从当前项目强制卸载 Workflow Loop

- 验收主题：从当前项目强制卸载 Workflow Loop

## 1. 本次需求与验收目标

### 需求来源

- [产品总说明：项目卸载场景和通用规则](../spec/产品总说明.md)
- [卸载 Workflow Loop](../spec/功能_卸载_Workflow_Loop.md)
- [安装到项目：区分后续管理](../spec/功能_安装到项目.md#4-规则)

### 验收目标

项目维护者从目标项目根目录确认卸载后，无论当前工作流轮次处于什么状态，Workflow Loop 项目管理内容都会被直接删除；项目业务代码、正式产物和电脑全局命令保留，重复卸载或部分删除失败时能够看到真实结果并继续清理。

## 3. 验收范围

### 本主题验收

- 从当前项目根目录发起项目卸载，显示一次确认并允许用户取消。
- 不受工作流轮次状态限制的强制卸载，以及与整轮作废的明确区别。
- `AGENTS.md`、整个 `.workflow_loop/` 和安装事务残留的固定删除范围。
- 业务代码、测试代码、版本控制文件、正式产物和电脑全局命令的固定保留范围。
- 旧版本卸载脚本、重复卸载、部分残留、删除失败、重新安装和公开卸载入口。

### 本主题不验收

- 电脑全局 `workflow` 命令和命令搜索路径的删除。
- 卸载前内容的备份、撤销卸载或恢复旧工作流状态和历史。
- 通过整轮作废恢复当前轮次修改的业务代码和正式产物。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
### AC-01：根目录检查和一次确认

- 条件与触发：用户从准备卸载的项目目录执行项目卸载命令，程序尚未取得用户确认。
- 预期结果：程序严格使用当前目录，显示项目绝对路径、实际存在的 `AGENTS.md`、`.workflow_loop/` 和安装残留、明确保留的业务代码、正式产物和全局命令，以及删除不可恢复的说明；只询问一次，用户取消时不删除任何文件。
- 产品设计依据：[卸载 Workflow Loop R1、R3、R4](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-02"></a>
### AC-02：任何轮次状态都能强制卸载

- 条件与触发：当前项目存在进行中、已完成或已作废的 Workflow Run（工作流轮次），用户确认项目卸载。
- 预期结果：轮次状态不阻止卸载，项目状态和历史随 `.workflow_loop/` 一起删除；卸载不执行 `workflow abort`（整轮作废），不恢复当前轮次已经修改的业务代码或正式产物。
- 产品设计依据：[卸载 Workflow Loop R2、R5](../spec/功能_卸载_Workflow_Loop.md#4-规则)、[卸载 Workflow Loop：不支持范围](../spec/功能_卸载_Workflow_Loop.md#32-不支持范围)

<a id="ac-03"></a>
### AC-03：项目管理内容按固定范围删除

- 条件与触发：用户确认项目卸载，项目中存在完整或部分 Workflow Loop 管理内容。
- 预期结果：程序整份删除根目录 `AGENTS.md`，不保留其中的项目定制；删除整个 `.workflow_loop/` 及其中的项目状态、轮次状态、追加历史、模板、规范、回退资料和其它内容；同时删除安装事务残留。
- 产品设计依据：[卸载 Workflow Loop R5、R6、R7](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-04"></a>
### AC-04：项目业务和正式产物保持不变

- 条件与触发：用户确认项目卸载，项目根目录还有业务代码、测试代码、版本控制文件或 `.workflow_loop/` 之外的正式产物。
- 预期结果：这些内容全部保留，电脑全局 `workflow` 命令也不删除；项目卸载不会扩大到项目固定管理路径之外。
- 产品设计依据：[卸载 Workflow Loop R8](../spec/功能_卸载_Workflow_Loop.md#4-规则)、[卸载 Workflow Loop：不支持范围](../spec/功能_卸载_Workflow_Loop.md#32-不支持范围)

<a id="ac-05"></a>
### AC-05：旧版本无需先升级即可卸载

- 条件与触发：项目使用没有 `workflow uninstall` 命令的旧版 Workflow Loop。
- 预期结果：用户从项目根目录执行当前操作系统的 `uninstall.sh` 或 `uninstall.ps1` 后可以直接卸载项目，不要求先更新全局命令或当前项目。
- 产品设计依据：[卸载 Workflow Loop R9](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-06"></a>
### AC-06：重复卸载和失败结果可以继续处理

- 条件与触发：项目已经完全卸载、只剩部分管理内容，或者删除过程中遇到权限或文件占用错误。
- 预期结果：完全没有管理内容时按成功处理且不修改文件；有残留时确认前列出并在确认后删除；中途失败不恢复已删除内容，列出已删除项、未删除项和原因并允许重试；只有目标管理内容全部删除后才显示成功。
- 产品设计依据：[卸载 Workflow Loop R10、R11、R15、R16](../spec/功能_卸载_Workflow_Loop.md#4-规则)

<a id="ac-07"></a>
### AC-07：重新安装和公开卸载入口符合边界

- 条件与触发：已卸载项目重新执行正式安装，或者维护者发布包含卸载功能的新正式版本。
- 预期结果：重新安装创建全新项目管理骨架，不恢复卸载前状态和历史；对应 GitHub Release 同时提供 `uninstall.sh` 和 `uninstall.ps1`，README 明确给出项目卸载入口和不可恢复范围。
- 产品设计依据：[卸载 Workflow Loop R17、R18](../spec/功能_卸载_Workflow_Loop.md#4-规则)、[安装到项目 R22](../spec/功能_安装到项目.md#4-规则)

## 5. 完成判定

- AC-01 至 AC-07 全部通过，本主题才算完成。
- 轮次状态阻止用户卸载、固定保留范围被误删、项目卸载连带删除全局命令、失败结果没有列出残留或重新安装恢复旧状态，本主题均不通过。
