# 【验收主题】修复缺陷经过主题验收和全量回归后关闭

## 1. 本次需求与验收目标

### 需求来源

- [缺陷复现与主题规则](../spec/功能_复现产品缺陷.md#4-规则)
- [缺陷状态与关闭规则](../spec/功能_验收并完成交付.md#4-规则)

### 验收目标

修复后的缺陷能够按照原复现条件得到产品设计规定的预期结果，并且只有在主题验收、最终全量回归和整体验收都通过后，缺陷才被标记为“已修复并验收”。

## 2. 产品设计依据

- [修复缺陷的主题规则](../spec/功能_复现产品缺陷.md#4-规则)：一份缺陷记录对应一个验收主题。
- [不同工作类型的验收依据](../spec/功能_制定验收与测试计划.md#4-规则)。
- [缺陷修复结果与关闭](../spec/功能_验收并完成交付.md#4-规则)。

## 3. 验收范围

### 本主题验收

- 缺陷复现阶段确定验收主题。
- 主题验收通过后不能直接关闭 bug。
- 最终全量回归和整体验收通过后才能关闭 bug。
- 回归失败时必须记录失败状态和原因。

### 本主题不验收

- 缺陷根因怎样分析。
- 修复代码怎样实现。
- 穿刺怎样验证技术不确定性。

## 4. 验收条件

<a id="ac-01"></a>
### AC-01：缺陷复现记录与验收主题一一对应

- 条件与触发：进入修 bug 工作流并完成缺陷复现讨论。
- 预期结果：每份缺陷记录包含一个验收主题；验收计划只能使用该主题，不能重新创造、改名、拆分或合并。
- 产品设计依据：[修复缺陷的主题规则](../spec/功能_复现产品缺陷.md#4-规则)。

<a id="ac-02"></a>
### AC-02：主题验收通过后保留待回归状态

- 条件与触发：该缺陷对应的主题验收通过，但最终全量回归尚未通过。
- 预期结果：缺陷记录追加实施、测试和主题验收结果链接，状态为“主题验收通过，待全量回归”。
- 产品设计依据：[缺陷状态与关闭规则](../spec/功能_验收并完成交付.md#4-规则)。

<a id="ac-03"></a>
### AC-03：只有最终整体验收通过后才能关闭缺陷

- 条件与触发：主题验收、最终全量回归和整体验收都已完成。
- 预期结果：只有全部通过时，缺陷记录和 `bug/索引.md` 才标记为“已修复并验收”；如果最终全量回归失败，状态改为“回归失败，重新处理中”。
- 产品设计依据：[缺陷状态与关闭规则](../spec/功能_验收并完成交付.md#4-规则)。

## 5. 完成判定

- AC-01、AC-02、AC-03 全部通过。
- 缺陷记录中的原复现条件、实际结果、期望结果和根因没有被改写。
- 缺陷状态与最终全量回归、整体验收结果一致。
