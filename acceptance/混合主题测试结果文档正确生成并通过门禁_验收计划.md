# 【验收主题】混合主题测试结果文档正确生成并通过门禁

- 工作流编号：2026-09-10-0804-bugfix
- 验收主题：混合主题测试结果文档正确生成并通过门禁

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 缺陷 BUG-2026-09-10-A：混合主题"自动化测试结果"永远显示"未完成"，整体验收门禁报"必须明确写自动化测试结果：通过"无法通过；缺陷记录见 bug/ 目录本轮两份缺陷记录。
- 缺陷 BUG-2026-09-10-B：第 3 节渲染人工项导致校验器报"测试项结果必须正好覆盖"，同样卡死整体验收。

<a id="验收目标"></a>
### 验收目标

- 修复后，任何同时含自动化测试项和人工验收项的主题，测试结果文档能正确生成（自动化汇总只算自动化项、人工项有明确的呈现方式），测试验证门禁和整体验收门禁不再因这两个缺陷报错。
- 用户在 kg-app 这类项目里做混合主题验收时，不再需要临时改源码才能走完轮次。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- [编写并执行测试 R12](../spec/功能_编写并执行测试.md#r-12)：程序从当前机器记录判定每条测试项执行结论并据实生成总览，不写死通过。
- [编写并执行测试 R14](../spec/功能_编写并执行测试.md#r-14)：混合主题只写自动化通过和"待主题验收"。
- [工作记录表与正式文档生成 R18](../spec/功能_工作记录表与正式文档生成.md#r-18)：正式文档固定字段由程序按表生成，不手抄。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 测试结果文档生成器对混合主题的汇总判定与字段取值（BUG-2026-09-10-A 的修复）。
- 测试结果文档第 3 节的渲染口径与门禁校验口径的统一，含人工项的合法呈现（BUG-2026-09-10-B 的修复）。
- 生成器与校验器共用的"哪些测试项算自动化项"取数逻辑收敛为单一数据源。
- 正向闭环自动化测试（生成器产出喂校验器）的建立。

<a id="本主题不验收"></a>
### 本主题不验收

- 主题验收阶段的人工确认流程和验收结果文档（由主题验收环节负责）。
- 测试计划表对人工验收项的登记支持（R6 已实现并有既有测试）。
- 纯人工主题不生成测试结果文档的行为（R14 已实现并有既有测试）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01混合主题汇总结果正确"></a>
### AC-01：混合主题汇总结果正确

- 开始前状态：一个验收主题的测试计划表中同时存在自动化测试项和人工验收项；全部自动化测试项已执行通过并登记当前有效机器记录；当前源码生成该主题测试结果文档时，文档头"自动化测试结果"显示"未完成"
- 触发动作：AI 在测试验证环节执行结果生成，程序从测试结果表和当前机器记录生成 qa/主题文件标识_测试结果.md
- 可检查结果：打开生成的测试结果文档，查看文档头"自动化测试结果"字段和"人工验收状态"字段
- 通过标准：全部自动化测试项通过且至少存在一个人工验收项时，"自动化测试结果"为"通过"；"人工验收状态"为"待主题验收"；两种字段同时成立
- 不通过标准："自动化测试结果"显示"未完成"或"失败"；或"人工验收状态"为"无需人工验收"但主题实际含人工项
- 产品设计依据：[编写并执行测试 R12](../spec/功能_编写并执行测试.md#r-12)：一个主题的全部自动化和混合测试项通过后，程序据实生成总览结论；[编写并执行测试 R14](../spec/功能_编写并执行测试.md#r-14)：混合主题只写自动化通过和"待主题验收"

<a id="ac-02"></a>
<a id="ac-02第三节口径两端一致"></a>
### AC-02：第三节口径两端一致

- 开始前状态：混合主题的测试结果文档第 3 节"测试项结果"渲染了人工验收项小节，小节内写"自动化测试结果：未执行"；而门禁校验要求第 3 节正好覆盖自动化测试项集合，多渲染一个人工项即报"测试项结果必须正好覆盖"
- 触发动作：AI 生成混合主题测试结果文档后，程序执行测试验证门禁，校验第 3 节的测试项覆盖
- 可检查结果：查看混合主题测试结果文档第 3 节的小节构成，并查看测试验证门禁对第 3 节覆盖的校验结果
- 通过标准：生成器渲染的第 3 节小节集合与校验器期望的集合一致：自动化测试项每个一节且带机器事实字段；人工验收项每项一节，内容标注测试方式为人工验收并指向第 4 节人工验收交接，不出现"自动化测试结果：未执行"这类把人工项当自动化未执行的表述；门禁不再报"必须正好覆盖"
- 不通过标准：第 3 节遗漏自动化测试项；或人工项小节仍写"自动化测试结果：未执行"；或门禁仍报"测试项结果必须正好覆盖"
- 产品设计依据：[编写并执行测试 R12](../spec/功能_编写并执行测试.md#r-12)：程序从当前机器记录判定每条测试项的执行结论；[工作记录表与正式文档生成 R18](../spec/功能_工作记录表与正式文档生成.md#r-18)：test_result 增加人工验收交接栏，混合测试必填，生成器按模板渲染

<a id="ac-03"></a>
<a id="ac-03纯自动化主题不受影响"></a>
### AC-03：纯自动化主题不受影响

- 开始前状态：纯自动化主题（测试计划表全部测试项为自动化测试，无人工验收项）在当前源码下文档生成与门禁校验均正常通过
- 触发动作：修复后对纯自动化主题执行同样的测试结果生成与门禁校验
- 可检查结果：查看纯自动化主题测试结果文档头字段与第 3 节小节，并查看测试验证门禁结果
- 通过标准：纯自动化主题文档头"自动化测试结果"为"通过"且"人工验收状态"为"无需人工验收"；第 3 节每个自动化项一节；门禁照常通过；修复没有改变纯自动化主题的既有行为
- 不通过标准：纯自动化主题文档头字段值变化；或第 3 节小节增减；或门禁对原本通过的场景开始报错
- 产品设计依据：[编写并执行测试 R14](../spec/功能_编写并执行测试.md#r-14)：纯人工主题不生成测试结果文件、混合主题只写自动化通过；本条件保护相邻场景不回归

<a id="ac-04"></a>
<a id="ac-04生成到校验正向闭环"></a>
### AC-04：生成到校验正向闭环

- 开始前状态：当前测试目录没有任何"生成器产出直接喂给校验器"的正向闭环测试；测试结果文档生成函数无直接测试；两个缺陷因此活到真实轮次才被发现
- 触发动作：AI 在测试验证环节运行本轮新增的正向闭环自动化测试
- 可检查结果：查看测试运行结果：混合主题场景（自动化项全通过加至少一个人工项）和纯自动化主题场景各至少一个用例，生成器产出经校验器口径检查
- 通过标准：两类场景的正向闭环测试全部通过：生成器产出的文档喂给校验器不报"自动化测试结果"或"必须正好覆盖"错误；同时保留至少一个负向用例证明校验器仍拒绝缺少自动化项覆盖的错误文档
- 不通过标准：正向闭环测试缺失或失败；或负向用例丢失导致校验器对错误文档放行
- 产品设计依据：[工作记录表与正式文档生成 R18](../spec/功能_工作记录表与正式文档生成.md#r-18)：固定字段由程序按表生成，门禁按同一口径校验；本条件把该口径固化为自动化测试

<a id="5-完成判定"></a>
## 5. 完成判定

- AC-01、AC-02、AC-03、AC-04 全部通过后本主题完成。
- 全部验收条件由自动化测试验证，无人工验收步骤。
