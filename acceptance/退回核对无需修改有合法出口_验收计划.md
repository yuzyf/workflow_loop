# 【验收主题】退回核对无需修改有合法出口

- 工作流编号：2026-09-09-0901-product_change
- 验收主题：退回核对无需修改有合法出口

<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户在 2026-09-09 提出：做到实施或测试验收阶段发现要增加或改需求，退回核对后发现无需修改，门禁却无出口，这个困扰已久。

<a id="验收目标"></a>
### 验收目标

- 任何环节退回后核对确认“现有产物不用改”时，在工作记录表填声明加核对依据就能通过第二道门；声明有依据要求，不能被滥用成免检通道。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- [功能_推进并确认工作环节](../spec/功能_推进并确认工作环节.md) R47（无需修改声明的门禁口径）；[功能_返回上游重新处理](../spec/功能_返回上游重新处理.md) R25（退回后核对无需修改不要求制造无意义修改）；[功能_工作记录表与正式文档生成](../spec/功能_工作记录表与正式文档生成.md) R30（声明行字段）。

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 全环节通用的“核对结论：无需修改”声明（核对对象、核对依据两项必填）。
- 声明存在且依据有实质内容且产物无变化时第二道门放行。
- 声明缺依据时的拒绝行为。
- 产物实际变化时声明不干扰普通流程。
- 声明在生成文档中的渲染留痕。

<a id="本主题不验收"></a>
### 本主题不验收

- 退回时序提示（既有 R25 已上线）。
- 门禁报错质量（既有 R46 已上线）。
- 主题一、二、四的验收内容。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01声明加依据通过第二道门"></a>
### AC-01：声明加依据通过第二道门

- 开始前状态：product_change 轮次从下游退回 spec，AI 重新核对后确认现有产品设计无需修改；产物文件相对基线无变化；当前环节工作记录表填有“核对结论：无需修改”声明，核对对象和核对依据两项都有实质内容
- 触发动作：AI 执行 workflow gate spec（第二道门）
- 可检查结果：门禁命令的完整输出文本，包含是否通过、问题清单（如有）和校验凭据的全部内容
- 通过标准：第二道门通过；不报“修改产品时，产品总说明必须更新并记录本轮变化”或“相关文件与讨论完成时相同”类错误
- 不通过标准：仍要求产品总说明必须发生变化，或要求制造无意义修改才能过门
- 产品设计依据：[推进并确认工作环节 R47](../spec/功能_推进并确认工作环节.md#r-47)

<a id="ac-02"></a>
<a id="ac-02声明缺依据被拒绝"></a>
### AC-02：声明缺依据被拒绝

- 开始前状态：同 AC-01 场景，但声明的核对依据为空或只有占位词（例如只有“暂无”）
- 触发动作：AI 执行 workflow gate spec（第二道门）
- 可检查结果：门禁命令的完整输出文本，包含是否通过、问题清单（如有）和校验凭据的全部内容
- 通过标准：按内容问题拒绝，指出声明缺少核对依据，要求写清核对了什么和为什么现有产物仍成立
- 不通过标准：缺依据的声明被放行
- 产品设计依据：[推进并确认工作环节 R47](../spec/功能_推进并确认工作环节.md#r-47)

<a id="ac-03"></a>
<a id="ac-03产物实际变化不走声明"></a>
### AC-03：产物实际变化不走声明

- 开始前状态：AI 填了“核对结论：无需修改”声明，但产物文件相对基线实际发生了修改
- 触发动作：AI 执行第二道门（workflow gate spec）
- 可检查结果：门禁命令的完整输出文本，包含是否通过、问题清单（如有）和校验凭据的全部内容
- 通过标准：按普通修改流程校验产物变化；声明行不作为放行依据，也不干扰产物变化的正常校验
- 不通过标准：声明导致实际变化的产物跳过校验被放行
- 产品设计依据：[推进并确认工作环节 R47](../spec/功能_推进并确认工作环节.md#r-47)

<a id="ac-04"></a>
<a id="ac-04生成文档渲染核对记录"></a>
### AC-04：生成文档渲染核对记录

- 开始前状态：“核对结论：无需修改”声明已通过第二道门
- 触发动作：程序按工作记录表生成正式文档（第二道门自动执行）
- 可检查结果：生成的产物文档全文
- 通过标准：文档中存在核对记录一节，包含核对对象和核对依据的实质内容，正式留痕
- 不通过标准：声明只存在于表里，生成的正式文档没有任何痕迹
- 产品设计依据：[工作记录表与正式文档生成 R30](../spec/功能_工作记录表与正式文档生成.md#r-30)

## 5. 完成判定

- AC-01 至 AC-04 全部通过。
