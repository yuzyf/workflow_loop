<a id="1-本次需求与验收目标"></a>
## 1. 本次需求与验收目标

<a id="需求来源"></a>
### 需求来源

- 用户要求修复第十四号缺陷，避免正式发布后产品文档继续显示旧版本。
- 用户授权 AI 代行本轮日常确认与核对；未要求本轮提交、推送或发布。

<a id="验收目标"></a>
### 验收目标

- 用户从产品说明进入同一个正式版本和安装来源，不再被多份文档中滞后的版本数字误导。

<a id="2-产品设计依据"></a>
## 2. 产品设计依据

- [发布正式版本 R11](../spec/功能_发布正式版本.md#r-11)、[安装到项目 R10](../spec/功能_安装到项目.md#r-10)

<a id="3-验收范围"></a>
## 3. 验收范围

<a id="本主题验收"></a>
### 本主题验收

- 当前产品规则和安装入口改为统一引用，同时保留旧发布、修改记录和验收中的历史版本事实。

<a id="本主题不验收"></a>
### 本主题不验收

- 本轮不实际提交、推送或发布新版本，不更改当前包版本及安装行为。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
<a id="ac-01当前引用统一且历史保留"></a>
### AC-01：当前引用统一且历史保留

- 开始前状态：产品说明包含当前安装和发布规则，也保留历史版本记录。
- 触发动作：用户阅读当前产品和安装说明，维护者按已有发布入口准备后续新版本。
- 可检查结果：当前说明只引用项目说明和正式发布来源，历史修改记录仍保存发生时的版本。
- 通过标准：当前规则不写死特定产品版本，安装入口仍指向正式来源；历史版本不被批量替换。
- 不通过标准：当前规则残留固定旧版本、统一入口不可达或历史事实被当作当前版本改写均不通过。
- 产品设计依据：[发布正式版本 R11](../spec/功能_发布正式版本.md#r-11)、[安装到项目 R10](../spec/功能_安装到项目.md#r-10)

## 5. 完成判定

- 本主题 1 条验收条件全部通过，真实结果和当前机器证据一致后完成；不接受部分通过。
