# 【验收主题】修复轮验收重做验证

- 工作流编号：2026-08-29-2338-product_change
- 验收主题：修复轮验收重做验证

## 1. 本次需求与验收目标

### 需求来源

- 用户需求（2026-08-30）：验收计划文档质量缩水、说不清要验收什么；先修代码再用重做验收计划实证修复效果（见 [产品总说明](../spec/产品总说明.md)）。
- 用户决定（2026-08-30）：本轮先用够用版验收计划登记施工单，代码修复完成后用 workflow return 退回验收计划环节重做。

### 验收目标

- 表模式代码修复完成后，用户把工作流退回验收计划环节，对本轮全部 5 个主题用新版工作记录表重新填写并重新生成验收计划文档；重做后的文档要像引入工作记录表之前的高质量时代一样，每个主题把需求来源、验收范围、每条验收条件的状态、动作、检查和判定写清楚，且从填写到门禁全程不再退回文档模式、不再出现同类卡壳。

## 2. 产品设计依据

- [R16](../spec/功能_工作记录表与正式文档生成.md#r-16)、[R18](../spec/功能_工作记录表与正式文档生成.md#r-18)：生成文档必须渲染模板全部章节且内容来自表栏位。

## 3. 验收范围

### 本主题验收

- 重做后的 5 份验收计划文档逐主题对照验收计划模板：六节齐全、每条验收条件六个固定字段可检查、无占位句。
- 重做过程本身走新版表的填写、生成和门禁全流程，记录是否出现退回文档模式或同类问题反复。

### 本主题不验收

- 各修复项代码本身的正确性（由对应主题的验收条件和测试验证环节负责）。
- 全量回归与整体验收（由最终回归和整体验收环节负责）。

<a id="4-验收条件"></a>
## 4. 验收条件

<a id="ac-01"></a>
### AC-01：重做文档说清验收什么

- 开始前状态：表模式代码修复已通过测试验证环节；工作流已用 workflow return 退回验收计划环节；5 个主题的旧粗版验收计划文档仍在 acceptance/ 目录。
- 触发动作：AI 按新版验收计划工作记录表逐主题重新填写需求来源、验收目标、验收范围、每条验收条件的六个固定字段和完成判定，然后用户执行第二道门 workflow gate acceptance_plan。
- 可检查结果：acceptance/ 目录下 5 份重做后的验收计划文档正文；对照验收计划模板逐节检查：六个章节齐全、每条 AC 小节有锚点和直白名称、六个固定字段与标签同行且内容是具体事实。
- 通过标准：5 份文档每一节内容都来自表栏位；不看代码和历史对话，只读文档就能回答：这个主题验收什么行为、执行前后是什么状态、到哪里看什么结果算通过；文档中不出现占位句、空词（如“栏目定义”“门禁结果”）或只指向本轮内部代号的表述。
- 不通过标准：任何一份文档缺章节、缺字段、字段值是占位词或空词，或者读者必须了解施工单编号、源码文件名等内部信息才能理解验收条件。
- 产品设计依据：[工作记录表与正式文档生成 R16](../spec/功能_工作记录表与正式文档生成.md#r-16)、[R18](../spec/功能_工作记录表与正式文档生成.md#r-18)

<a id="ac-02"></a>
### AC-02：重做全程走表不卡壳

- 开始前状态：新版表栏位与生成器已启用（表版本 2），重做用的 5 张验收计划工作记录表已生成。
- 触发动作：AI 和用户从验收计划环节继续走完实施、测试验证、主题验收各环节，全程只通过填写工作记录表和 workflow gate 命令推进。
- 可检查结果：各环节第二道门的执行记录（journal 与门禁输出），以及各环节按表生成的正式文档。
- 通过标准：全流程未出现退回文档模式的校验错误；同类门禁失败没有在同一环节反复出现 3 次以上；每次失败输出都点名具体表和栏目并给出修改方法。
- 不通过标准：任何环节再次出现文档模式校验错误（如缺少编号章节、解析生成文档报错），或同类问题在未经表内容变化的情况下反复被门禁拒绝。
- 产品设计依据：[工作记录表与正式文档生成 R11](../spec/功能_工作记录表与正式文档生成.md#r-11)、[R18](../spec/功能_工作记录表与正式文档生成.md#r-18)、[R20](../spec/功能_工作记录表与正式文档生成.md#r-20)

## 5. 完成判定

- 重做后的 5 份验收计划文档全部满足 AC-01，且后续环节满足 AC-02 时，本主题完成。
- 任一主题重做后仍说不清验收对象、仍需靠文档模式退回或同类门禁失败反复出现时，本主题不通过，返回实施环节继续修复。
