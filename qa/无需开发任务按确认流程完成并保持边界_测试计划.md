## 2. 针对性回归范围

- 回归从零创建、修改产品和修复缺陷三种完整研发流程的阶段路径、三道门、返回上游和整轮作废，新增简单流程不能改变这些行为。
- 回归开始、状态查询和正式收工命令，确保同一项目仍只允许一个进行中轮次，已结束轮次允许开始下一轮。
- 回归安装器生成的 AI 契约文件和公开项目说明，确保新规则在安装后可见且用户仍不需要手工执行日常工作流命令。
- 保留现有项目全量测试入口 `scripts/test_all.sh`（运行项目全部测试的脚本）；本阶段只核对入口，不执行测试。

## 3. 测试条件要求

- Python 3.11 或更高版本、`pytest`（Python 自动化测试工具）和可创建临时目录的权限。
- 自动化测试使用隔离的临时项目和临时 Git 仓库，不修改当前真实工作流轮次，不连接真实远程仓库或发布平台，不执行真实远程推送、发布或删除。
- 计划新增 `tests/test_light_task.py`（无需开发任务测试文件）；具体测试函数、执行命令和证据文件位置在实施后确认。
- 人工部分只阅读代表性的路线、逐题讨论、难撤销操作、结果说明和安装后文档，不要求用户手工执行 `workflow`（工作流管理命令）。

## 4. 未决测试条件

- 当前已经确定但尚未执行：七个测试项的自动化部分，以及四类代表性输出和文档的人工验收。
- 只有实施代码完成后才能确定：具体测试函数、命令输出文本和机器记录编号。
- 验收条件本身无法由程序单独判断：AI 是否真正做到一次只问一个问题、推荐是否清楚和结果说明是否易懂，需要用户在主题验收时判断。
