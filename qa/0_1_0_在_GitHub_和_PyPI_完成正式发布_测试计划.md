## 2. 针对性回归范围

- 回归现有发布任务的标签触发、手动任务不发布、测试与构建顺序、三平台矩阵和失败阻断，避免补充发布说明时放宽发布条件。
- 回归 macOS、Linux、PowerShell 7 和 Windows PowerShell 5.1 安装流程中的确认、取消、完整安装和只补缺失部分行为。
- 回归安装脚本、命令身份、项目安装标记和 Python 包版本，确认公开分发仍安装同一份 `workflow-loop 0.1.0`。
- 发布前公共版本空缺检查属于本次一次性时点测试，必须显式执行并保存记录，但不能被项目默认全量测试在发布后重复执行。
- 其它工作流命令、状态、门禁、返回和回退行为由最终全量回归统一检查。

## 3. 测试条件要求

- GitHub 目标仓库已经改名并保持公开，最终源码和测试已提交到主分支；远程标签尚未推送时先执行 TC-01、TC-02 和 TC-03。
- TC-02 需要真实 GitHub、PyPI、网络、最终主分支提交和本地 `v0.1.0` 标签；用户必须在看到空缺查询和标签对应关系后明确批准远程推送。
- GitHub 仓库具备推送标签和创建正式发布页的权限；PyPI Trusted Publisher（可信发布者）已配置为仓库 `yuzyf/workflow_loop`、任务 `release.yml`，环境名称不限。
- TC-04、TC-05、TC-06 和 TC-07 在标签推送后执行；公开索引存在传播延迟时可以在限定时间内轮询，超时仍视为未满足。
- TC-06 使用全新的临时安装位置并禁用本地包查找配置与缓存，不能用本地 wheel（二进制分发包）代替公开 PyPI。
- 最终标签任务使用 GitHub 托管的 Ubuntu、macOS 和 Windows 环境；Windows 作业分别执行 PowerShell 7 与 Windows PowerShell 5.1，不要求用户准备三种操作系统。
- 一次性外部状态测试由正式测试执行显式调用，不由项目默认全量 `pytest` 自动发现；具体测试函数、执行命令、轮询时间和证据文件位置：实施后确认。

## 4. 未决测试条件

- 当前已经确定但尚未开始执行：仓库改名、最终主分支提交、本地标签准备、推送前公开版本空缺检查、用户标签推送批准、最终标签任务、公开页面传播和公网安装。
- 只有实施代码完成后才能确定：最终提交编号、标签任务编号、具体测试函数与命令、公开分发文件摘要、轮询时间和机器记录编号。
- 验收条件本身无法验证：暂无。
