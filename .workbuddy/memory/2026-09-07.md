### journal 数据分析结果

- 门禁代码校验失败共 319 次。文档模式时代（8 月中）最大连败 38 次（update_code_design），原因是"架构文档代码映射格式"（反引号、行号、符号定位）反复试错。
- 表模式时代（9 月三个轮次）失败大幅下降但仍有反复，失败类型变为：
  1. **L起始-L结束格式**：AI 填 'L7、L49-L50'、'L192-L246、L282-L285' 被拒——多段行号写法没有明确指引（records.py:361 说明只给了单段格式）
  2. **"目标不是现有普通文件"**：impl 环节 L117-121 的上下游链接指向尚未生成的测试结果/验收结果文档。机制：_downstream_cell 只在文件存在时写链接，否则写"(待生成)"；但 kg-app 09-07 的案例是退回重跑后文件被删、链接还留着旧链接（refresh_references_after_removal 只在 workflow return 和失效自动删除时触发）
  3. **占位词/最小信息量**：'暂无。'、'无' 被拒（9-04 轮，模板明文允许写暂无但白名单没盖全）
  4. **npx 路径不一致**：环境问题（nvm v25 vs workbuddy v22）
- 核心发现（对应已确认缺陷 BUG-01~06，见 bug/缺陷_按程序指引填表和修链接都能一次过关_修复结果不被程序自己抹掉.md）：
  - 反复的第一根因不是"空表骨架"，而是**格式约束写在门禁代码里、不写在表填写说明里**——指引与校验脱节（BUG-01 模式），AI 按说明填了也被拒
  - 第二根因是**跨文档一致性靠"生成时机"隐式维护**：上游文档的下游链接是程序按"文件是否存在"实时判定的，但退回/失效删文件后链接刷新不彻底，同一批链接问题跨环节复发（BUG-04 的变体）
  - repair-links 插的锚点会被重渲染抹掉（BUG-04，已修复：锚点改为渲染器稳定生成物）
- 结论：机制缺陷集中在"门禁要求与填写说明不同步"和"生成时机依赖"，不是 AI 填表能力问题。当前轮次 2026-09-07-0700（product_change, qa 环节）未动。

## token 费用分析与方案调研（2026-09-07 晚）

- kg-app 实测：单轮产物文档 200KB+，10 环节 × 每环节 1-1.5 万 token 规范文档 = 每轮 10 万+ 输入；门禁失败重试是最大浪费（一轮 7-24 次失败）。
- GitHub 对比调研结论：
  - spec-kit（github/spec-kit，10 万+ star）：同物种重流程，社区实测每功能比直接写码多花 3-5 倍 token，Reddit 吐槽"eating my tokens alive"。教训：重流程费 token 是通病。
  - Anthropic harness 模式（官方工程博客）：小进度文件 + 机器可查任务清单 + 每会话新上下文只读这两样，不背历史。workflow_loop 的 journal/表/追踪表已是这个形态。
- 省 token 优化方向（与已定改造同向）：机器采集事实（治抄写）、预检门禁（错在正式门禁前暴露）、表即指引/环节简报（有表的环节不读全文规范）、每环节新会话（零代码，立即可用）。
- **用户否决了上述治标方案**，要求根治。第二轮调研（GitHub 省 token 项目盘点）：
  - 共同核心思路：**对话不是系统的记忆，文件才是**。AI 会话 = 短命工人，领一份程序渲染的小任务书 → 干活 → 结果落文件 → 会话扔掉。
  - 代表项目：OpenViking（字节，三级加载 L0摘要/L1概览/L2全文，实测输入砍 91%）、Symphony（OpenAI，状态全在任务板、每任务新上下文 agent、任务书由程序渲染）、Anthropic harness（进度文件+任务清单，2000 万 token 任务实际未命中输入仅 26 万）、Claude Code 前缀缓存（命中 92%，读 0.1 倍价）、memory-management-skill（分层记忆，省 89%）。
  - workflow_loop 现状：状态文件化已达标（state/journal/表），缺的是"执行拆分会话"——整轮在一个对话里滚，后期每句话为前期全部上下文付费；以及"程序渲染任务书"——现在 AI 进环节要亲自读全量规范。
  - 根治方向候选：程序合成环节任务书（只含该环节必需事实+表指引）、每环节/每主题独立会话执行、小模型干采集大模型干判断。
  - **用户否决"手动开新窗口"方案**（对使用者太复杂）。最终方向：**主对话当调度员 + subagent 干活**——用户体验零变化（一个窗口聊到底说"继续"），每个环节派 subagent 领任务书执行，只带摘要回主对话，环节细节随 subagent 丢弃。Agent 工具是现成的，AGENTS.md 加约定即可先行；产品开发只剩"程序合成精简任务书"一项，与已定待办同一轮做。
