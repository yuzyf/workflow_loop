## 下午：混合主题测试结果两 bug 核实 + 根因讨论（未开轮，纯核实）

用户报告两个 bug（只报告不动手），逐条核实成立：

- **Bug 1：混合主题"自动化测试结果"永远"未完成"**。机制链：`test_result_columns`（machine_collect.py:556）把 qa 阶段全部测试任务回填进测试结果表（人工项不登记任务，但用户报告实测人工项行在表里，来源待修时再查）→ `_generate_test_result_document_v2`（records.py:3015）的 `_outcomes` 遍历全部表行，人工项无机器记录 → `_test_outcome(None)`="未执行"（records.py:2893）→ `all(通过)` 不成立 → `_overall="未完成"` → 校验器要求"自动化测试结果：通过"（artifact_validation.py:2545）必挂。
- **Bug 2：第 3 节渲染口径不一致**。生成器把全部表行渲染进"3. 测试项结果"；校验器 `set(sections) != expected_ids`（artifact_validation.py:2561）要求正好覆盖自动化项（`automated_test_items` 只取 requires_test_code=True，test_mapping.py:605）。人工项多渲染一个就报"必须正好覆盖"。
- **共同根因（用户判断正确）**：生成端与校验端对"人工项在第 3 节怎么表达"没有统一约定。
- **测试覆盖缺口（核实）**：`_generate_test_result_document_v2` 在 tests/ 零直接测试；"生成器产出→校验器接受"的正向闭环无任何端到端测试。
- 源码干净（git status src/ 为空），"修复已回滚"属实。

### "为什么一直修 bug"根因回答要点

1. **观察者效应**：这个项目的功能是"验证别人的开发"，自己的 bug 直接变门禁失败，用户必撞见；普通项目的 bug 用户看不到。
2. **双端同步税**：生成器和校验器是同一规则的两份实现，每加一种表达（人工项/混合/纯人工）就要两边同步，漏一边就是 bug。BUG-01→L 格式→表版本→本轮人工项，同根因四连。
3. **测试写在了 bug 不在的地方**：628 项测试全在测"校验器拒绝坏的"，没有"生成器产出喂给校验器必须通过"的自产自销测试。
