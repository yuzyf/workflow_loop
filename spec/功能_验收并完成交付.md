# 【功能】验收并完成交付

## 1. 背景

实施和主题测试通过，只能说明代码已经按计划完成并获得测试证据，不能直接代表整项需求已经交付。Workflow Loop 还要逐条完成主题验收，在最新完整代码上运行最终全量回归，由用户判断所有主题合在一起是否完成需求，并把最终代码同步回代码架构设计。

本功能负责从主题验收到 `done`（正式收工）的完整交付尾段。自动化已经证明的内容不要求用户重复测试；人工结论必须来自用户实际回答；最终全量回归保存机器记录而不重复生成结果文档；最后一个环节的用户确认就是整轮最后一次确认。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 验收纯自动化主题 | 项目负责人、验收人 | 全部条件都能由当前有效自动化测试证明 | 核对机器证据覆盖完整 | 不要求用户重复执行或判断自动化测试 |
| 验收人工或混合主题 | 验收人 | 条件包含必须由用户观察或判断的部分 | 按明确步骤完成剩余验收 | 用户回答、实际结果和证据形成主题验收结果 |
| 执行最终全量回归 | 项目维护者 | 全部主题都有正式通过结果 | 在最新完整代码上运行项目统一测试入口 | 组合修改和原有功能通过项目约定的全部测试 |
| 完成整体验收 | 项目负责人 | 主题验收和最终回归全部通过 | 判断组合结果是否完成本次需求 | 用户的交付决定被程序记录 |
| 同步最终代码设计 | 项目维护者 | 整体验收通过 | 用最终代码和验证结果更新架构文档 | 架构文档准确描述当前真实实现 |
| 关闭已修复缺陷 | 项目负责人、项目维护者 | 修复缺陷轮次的整体验收已经通过 | 把缺陷状态更新为已修复并验收 | 缺陷关闭依据包括主题验收、最终全量回归和整体验收 |
| 正式收工 | 项目负责人、项目维护者 | 最终代码设计同步已经确认 | 登记本轮完成 | `done` 只记录收工并清理临时回退副本，不再修改缺陷文档或重复询问验收 |

## 3. 功能边界

### 3.1 支持范围

- 按验收计划完成纯自动化、混合和纯人工主题验收。
- 记录用户实际回答、确认时间、结果和证据，并生成 `acceptance/<主题文件标识>_验收结果.md`。
- 允许独立主题分别验收，并按已确认前置关系等待。
- 在全部主题通过后执行项目统一测试入口，并把最终回归事实保存到机器状态、追加历史和 `需求交付追踪表.md`。
- 由用户完成整体验收。
- 根据最终产品设计、代码、实施、测试和验收结果同步 `spec/代码架构设计.md`。
- 最后一个环节确认后正式收工，记录完成时间并清理本轮临时回退副本和未登记临时输出；已登记的可复用穿刺资产继续保留。

### 3.2 不支持范围

- 不在主题验收中重复运行已经完成的自动化测试。
- 不让 AI 代替用户回答人工验收或整体验收。
- 不接受“部分通过”“带条件通过”或“基本完成”。
- 不为失败、阻塞或无法验证的主题生成正式通过结果。
- 不生成独立的最终全量回归或整体验收结果文档。
- 不在最终设计同步时修改生产代码或改变产品规则。
- 不把正式收工当成第二次整体验收，也不删除正式产物。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| R1 | 开始主题验收 | 必须读取验收计划、实施记录、产品设计和当前程序记录；自动化或混合主题还必须有当前有效测试结果，纯人工主题读取测试计划和人工交接状态，不要求生成测试结果文档。自动化证据缺失、失效或未通过时不得验收对应条件。 |
| R2 | 纯自动化或混合条件 | 纯自动化条件直接使用当前有效测试记录；混合条件只把自动化不能判断的部分交给用户，不重复询问已证明内容。 |
| R3 | 纯人工条件 | AI 先展示验收对象、开始条件、具体操作、观察内容、预期结果、已有证据和用户需要回答的问题，不能只问“是否通过”。 |
| R4 | 保存人工验收 | 用户回答后，AI 执行记录动作；程序按当前工作流、主题和 `AC-xx` 验收条件编号保存用户原话、结果、时间和证据，用户不另填机器状态或正式文档。 |
| R5 | 判断主题通过 | 全部验收条件都完成、可验证且通过时才生成正式主题结果；文档必须与当前程序记录一致。纯人工主题不伪造测试结果。 |
| R6 | 验收发现问题 | AI 先调查问题来源并提出返回环节，用户确认后由 AI 先执行返回命令，再修改上游。修改产品或从零创建时可定向取消一个功能；修复缺陷必须改产品时作废本轮后另开修改产品轮次。 |
| R7 | 进入最终全量回归 | 当前工作流全部主题都必须已有当前有效的主题验收通过结果；自动化或混合主题还必须有当前有效测试结果，纯人工主题以人工验收记录作为测试结果文档的例外。主题测试和验收不能代替最终全量回归。 |
| R8 | 最终回归第一道门 | `workflow gate regression_test --discuss-done` 表示“统一测试入口和运行条件已经准备好”。AI 执行后只记录准备完成，不运行测试，也不代表结果通过。 |
| R9 | 最终回归第二道门 | `workflow gate regression_test` 表示“在当前完整代码上执行最终全量回归”。程序实际运行统一入口并保存机器记录，退出码只有为 `0` 才通过。 |
| R10 | 最终回归第三道门 | `workflow gate regression_test --confirmed` 表示“用户确认刚才的回归结果可以用于继续交付”。它只复核当前有效记录并推进，不重复运行测试。 |
| R11 | 显示工作流命令 | AI 必须同时说明命令做什么、不做什么、由谁执行、执行后去哪一步以及用户是否需要参与，不能只显示英文命令。 |
| R12 | 最终回归失败、超时或无法启动 | 不进入整体验收。产品代码问题经用户确认返回实施环节；测试环境、工具链或统一入口问题返回测试验证环节；修正后重新经过受影响环节并重跑回归。 |
| R13 | 执行整体验收 | 用户只判断所有主题组合后是否完成需求，不重复主题验收。结果写入状态、追加历史和需求交付追踪表，不另建结果文档。 |
| R14 | 同步最终代码设计 | 只把经过验证的真实代码结构写回架构文档。发现产品行为变化时返回产品设计；修复缺陷必须改产品时作废后另开修改产品轮次；发现实现遗漏时返回实施。 |
| R15 | 修复缺陷的状态变化 | 主题验收后写“主题验收通过，待全量回归”，最终回归后写“全量回归通过，待整体验收”，回归失败写“回归失败，重新处理中”，整体验收通过后才写“已修复并验收”。 |
| R16 | 最后一个环节通过第三道门 | 这已经是整轮最后一次用户确认。AI 随后执行 `workflow done` 正式收工；程序记录完成时间、清理临时回退副本和未登记临时输出，但保留已登记的可复用穿刺资产并允许下一轮，不再重复询问，也不删除正式产物。 |
| R17 | 记录验收人信息 | 验收记录不要求姓名或角色，也不保存 AI 猜测的身份。程序只保存用户实际回答、确认结果、时间和证据；AI 不得从系统用户名、Git 用户名或聊天账号推断验收人。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 程序、AI | 程序列出必读材料绝对路径，AI 读取验收计划、实施记录和程序记录；自动化或混合主题再读取测试结果，纯人工主题读取测试计划和人工交接状态 | 每条验收条件都有与测试方式匹配的当前依据 |
| 2 | AI、验收人、程序 | 程序整理纯自动化条件；AI 展示人工步骤；验收人实际检查并回答；程序保存记录 | 自动化不重复，人工结论来自用户 |
| 3 | AI、程序 | 主题全部条件通过后，AI 生成主题结果，程序检查文档与记录一致 | 独立主题可以先形成正式结果 |
| 4 | 用户、AI、程序 | 用户确认回归入口和环境后，AI 执行第一道门；程序在第二道门实际运行统一入口 | 准备动作和测试执行不会混淆 |
| 5 | AI、用户 | AI 解释回归结果；用户确认后，AI 执行第三道门 | 当前回归记录得到确认且不会重复执行 |
| 6 | 项目负责人 | 根据全部主题结果和最终回归完成整体验收 | 交付决定写入程序状态和追踪表 |
| 7 | AI、程序、用户 | AI 更新代码架构设计，程序检查固定条件，用户确认最终同步 | 架构文档与最终实现一致 |
| 8 | AI、程序 | AI 执行正式收工，程序登记完成并清理临时回退副本和未登记临时输出 | 正式产物和已登记穿刺资产保留，项目可以开始下一轮 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 自动化证据失效 | 直接依据、代码或测试发生有效变化 | 删除直接受影响主题的当前结果并重做必要环节 | 旧结果不会继续支持交付 |
| 人工回答含糊或未通过 | 回答无法判断，或实际结果与条件不一致 | 继续澄清；未通过时不生成正式主题结果，调查后返回对应环节 | 不会擅自记录通过或失败 |
| 主题只有部分条件通过 | 至少一条条件未通过、未执行或缺少证据 | 整个主题不形成正式通过结果 | 不出现部分通过或带条件通过 |
| 最终回归缺少入口 | 没有已确认入口或当前系统没有适用命令 | 经用户确认返回测试验证补充环境和入口 | 门禁不临时猜测或生成脚本 |
| 最终回归失败或超时 | 退出码非零或超过时限 | 保存失败事实并阻止整体验收；修复缺陷时更新为重新处理中 | 显示命令、退出码或超时及建议返回环节 |
| 修正后没有重跑回归 | 上游已修改却试图复用旧记录 | 旧记录失效，拒绝进入整体验收 | 必须在最新完整代码上重跑 |
| 整体验收未通过 | 用户认为组合结果仍未完成需求 | 调查是原条件未满足还是新产品要求，再按工作意图返回或作废 | 不会因测试曾通过而强制收工 |
| 最终设计发现变化或遗漏 | 代码改变产品行为，或没有实现已确认要求 | 分别返回产品设计或实施；修复缺陷需要改产品时作废另开 | 不把错误现状写成最终设计 |
| 正式收工条件不足 | 仍有未完成环节或最后环节未确认 | 拒绝收工并说明真实下一步 | 进行中轮次不会被错误标记完成 |
