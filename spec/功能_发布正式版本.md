# 【功能】发布正式版本

## 1. 背景

项目维护者已经能够通过远程发布流程把 Workflow Loop 发布到公开渠道，但每次发布都要手工修改多处版本、更新依赖锁定结果、提交、推送并创建版本标签。维护者希望用一条命令直接发布当前仓库内容，并明确自行承担跳过本地发布检查的风险。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 直接发布当前代码 | 项目维护者 | 当前仓库内容已经由维护者自行判断可以发布，并已决定一个新的版本号 | 用一条命令完成发布准备和远程触发 | 当前全部未忽略修改进入远程默认分支，新版本标签触发现有公开发布流程 |
| 处理发布中途失败 | 项目维护者 | 提交、推送或标签操作中的任一步失败 | 看清失败位置并自行决定恢复或重试 | 脚本立即停止，不继续执行剩余发布动作，也不声称发布成功 |

## 3. 功能边界

### 3.1 支持范围

- 接收维护者指定的新版本号。
- 把当前发布身份统一更新为新版本，并更新依赖锁定结果。
- 把当前仓库全部未被忽略的修改纳入一个发布提交。
- 把默认分支推送到远程仓库，再创建并推送对应版本标签。
- 由版本标签触发现有远程公开发布流程。
- 任一步实际操作失败时立即停止，并保留清楚的失败输出。

### 3.2 不支持范围

- 不在本地运行测试、构建或发布前状态检查。
- 不查询新版本号是否已在公开渠道发布，也不替维护者选择版本号。
- 不在执行前再次询问确认；运行命令本身就是确认。
- 不自动回滚已经完成的版本修改、提交、分支推送或标签操作。
- 不强制覆盖已有标签或远程历史。
- 不批量改写历史发布记录、历史验收文档或其它只记录过去事实的内容。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| R1 | 维护者准备发布 | 必须在 Workflow Loop 源码仓库中执行 `uv run python scripts/release.py <新版本号>`；新版本号由维护者明确提供。 |
| R2 | 命令开始执行 | 命令调用本身表示维护者确认按当前仓库内容发布，并接受不做本地发布检查的风险；程序不再二次询问。 |
| R3 | 更新发布身份 | 当前用于正式发布、安装和版本展示的位置统一使用新版本；历史记录中已经发生的旧版本事实保持不变。 |
| R4 | 更新依赖锁定结果 | 版本身份更新后同步当前依赖锁定结果，再进入提交。 |
| R5 | 建立发布提交 | 当前仓库全部未被忽略的新增、修改和删除都进入同一个发布提交，不只包含版本文件。 |
| R6 | 推送分支 | 发布提交先进入远程默认分支；分支推送失败时不创建或推送版本标签。 |
| R7 | 创建版本标签 | 分支推送成功后创建 `v<新版本号>` 标签并推送；本地已经存在同名标签时由版本控制工具拒绝，程序不强制覆盖。 |
| R8 | 触发公开发布 | 标签推送成功后，由现有远程发布流程执行其已配置的构建、测试和公开发布动作；脚本不重复执行这些动作。 |
| R9 | 任一步失败 | 立即停止并返回失败；已经成功完成的动作保持原状，由维护者根据输出决定怎样恢复，不自动回滚或继续重试。 |
| R10 | 判断脚本完成 | 只有版本更新、依赖锁定、提交、默认分支推送、标签创建和标签推送都成功，脚本本身才报告完成；公开渠道最终是否成功仍以远程发布流程结果为准。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 项目维护者 | 自行判断当前仓库内容可以发布，并决定一个新版本号 | 维护者承担跳过本地发布检查的风险 |
| 2 | 项目维护者 | 在源码仓库执行 `uv run python scripts/release.py <新版本号>` | 程序直接开始发布，不再询问确认 |
| 3 | 程序 | 更新当前发布身份和依赖锁定结果 | 本次发布使用同一个新版本号 |
| 4 | 程序 | 纳入当前全部未忽略修改并创建发布提交 | 当前仓库内容成为本次发布提交 |
| 5 | 程序 | 推送默认分支 | 远程仓库取得本次发布提交 |
| 6 | 程序 | 创建并推送版本标签 | 现有远程发布流程被触发 |
| 7 | 项目维护者 | 查看远程发布流程结果 | 以远程结果判断公开发布是否最终完成 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 版本号无法用于发布 | 提供的内容不能形成有效的新版本身份 | 在产生发布提交前停止 | 显示版本参数问题，不创建标签 |
| 依赖锁定更新失败 | 当前环境无法更新依赖锁定结果 | 立即停止 | 显示实际命令错误，后续提交和推送不执行 |
| 没有可提交变化 | 版本更新没有产生可以提交的内容 | 提交操作失败并停止 | 不创建空发布提交或版本标签 |
| 分支推送失败 | 网络、权限或远程分支状态阻止推送 | 立即停止，不创建版本标签 | 显示分支推送失败；本地发布提交保留 |
| 同名标签已经存在 | 本地已有相同版本标签 | 标签创建失败并停止，不强制覆盖 | 显示标签冲突；已经推送的分支提交保留 |
| 标签推送失败 | 网络、权限或远程状态阻止标签进入远程仓库 | 立即停止 | 显示标签推送失败；本地标签和已推送分支保留 |
| 远程发布失败 | 标签已推送，但远程构建、测试或公开发布失败 | 脚本不自动删除标签或回滚分支 | 维护者在远程发布记录中查看失败原因并自行处理 |
