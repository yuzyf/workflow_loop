# 【功能】卸载 Workflow Loop

## 1. 背景

项目安装 Workflow Loop 后，会在项目根目录保存 `AGENTS.md` 和 `.workflow_loop/` 管理目录，并在电脑上共享一个全局 `workflow` 命令。用户不再需要某个项目的 Workflow Loop 时，需要一条明确的项目卸载命令；用户不再需要电脑上的共享命令时，还需要一个与项目卸载分开的全局卸载入口。

本功能允许用户不受当前工作流轮次状态限制，确认后强制删除当前项目的 Workflow Loop 管理内容。项目业务代码和正式产物保留。电脑全局命令只有在用户单独选择全局卸载时才删除。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 强制卸载当前项目 | 项目维护者 | 当前项目不再使用 Workflow Loop | 不管工作流处于什么状态都从项目中移除 | `AGENTS.md`、`.workflow_loop/` 和安装残留删除，业务代码和正式产物保留 |
| 从没有卸载命令的旧版卸载 | 项目维护者 | 当前项目版本没有 `workflow uninstall` | 使用当前操作系统的一条卸载脚本 | 不先升级也能卸载当前项目 |
| 卸载电脑全局命令 | 项目维护者 | 这台电脑不再需要共享的 `workflow` 命令 | 只删除电脑级命令和命令搜索路径 | 所有项目文件保持不变 |
| 重复卸载 | 项目维护者 | 当前项目已经卸载或只剩部分管理内容 | 确认项目处于未安装状态或清理残留 | 完全未安装时成功退出；有残留时删除检测到的管理内容 |
| 卸载后重新安装 | 项目维护者 | 已卸载项目后来再次需要 Workflow Loop | 重新执行官方安装命令 | 项目得到全新管理骨架，旧工作流状态和历史不恢复 |

## 3. 功能边界

### 3.1 支持范围

- `workflow uninstall` 从当前项目根目录强制卸载项目，不向上查找项目根。
- 项目卸载不检查 Workflow Run（工作流轮次）处于进行中、已完成还是已作废。
- 项目卸载删除项目根目录的 `AGENTS.md`、整个 `.workflow_loop/` 和安装事务残留目录。
- 项目卸载保留业务代码和 `.workflow_loop/` 之外的 `spec/`、`acceptance/`、`qa/`、`impl/`、`bug/` 等正式产物。
- `workflow uninstall --global` 只删除电脑上的全局 `workflow` 命令和由 Workflow Loop 安装写入的命令搜索路径。
- 每个正式版本提供 `uninstall.sh`（macOS 和 Linux 卸载脚本）和 `uninstall.ps1`（Windows 卸载脚本），供旧版本直接卸载。
- 项目卸载和电脑全局卸载各自只询问一次确认。
- 已完全卸载时重复执行按成功处理；只剩部分管理内容时允许清理残留。

<a id="32-不支持范围"></a>
### 3.2 不支持范围

- 不恢复安装或更新前的 `AGENTS.md`、模板、规范、状态和历史记录。
- 不保存被删除内容的备份，也不提供撤销卸载。
- 项目卸载不删除电脑全局命令；全局卸载不删除任何项目文件。
- 不删除项目业务代码、版本控制文件或 `.workflow_loop/` 之外的正式产物。
- 不扫描电脑查找哪些项目仍然依赖全局命令。
- 不把项目卸载等同于 `workflow abort`（整轮作废）；卸载不会恢复当前轮次修改的业务代码和正式产物。

<a id="4-规则"></a>
## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| <a id="r-1"></a>R1 | 用户准备卸载当前项目 | 用户必须进入目标项目根目录；命令严格使用当前目录。 |
| <a id="r-2"></a>R2 | 项目有进行中轮次 | 仍然允许卸载，不要求先正式收工或整轮作废。 |
| <a id="r-3"></a>R3 | 请求项目卸载确认 | 显示项目绝对路径、将删除的 `AGENTS.md`、`.workflow_loop/` 和安装残留，以及明确保留的业务代码、正式产物和全局命令；只询问一次。 |
| <a id="r-4"></a>R4 | 用户取消项目卸载 | 不删除任何文件。 |
| <a id="r-5"></a>R5 | 用户确认项目卸载 | 直接删除全部项目管理内容，不保存备份，不恢复安装前文件。 |
| <a id="r-6"></a>R6 | 删除 `AGENTS.md` | 不检查文件是否含有项目定制内容；存在时整份删除。 |
| <a id="r-7"></a>R7 | 删除 `.workflow_loop/` | 删除其中的项目状态、轮次状态、追加历史、模板、规范、回退资料和其它内容。 |
| <a id="r-8"></a>R8 | 保留项目内容 | 不删除 `.workflow_loop/` 之外的业务代码、测试代码和正式产物。 |
| <a id="r-9"></a>R9 | 旧版本没有卸载命令 | 用户从目标项目根目录运行对应操作系统的卸载脚本；脚本不要求先升级。 |
| <a id="r-10"></a>R10 | 项目已经完全卸载 | 不修改文件，显示当前项目未安装 Workflow Loop，并按成功处理。 |
| <a id="r-11"></a>R11 | 项目只剩部分管理内容 | 确认前列出实际检测到的残留，确认后删除这些残留。 |
| <a id="r-12"></a>R12 | 请求电脑全局卸载 | 显示全局命令和命令搜索路径，并说明其它项目将暂时不能执行 Workflow Loop；只询问一次。 |
| <a id="r-13"></a>R13 | 用户确认电脑全局卸载 | 只删除电脑全局命令和由 Workflow Loop 写入的命令搜索路径，不删除任何项目文件。 |
| <a id="r-14"></a>R14 | 无法确定命令搜索路径是否由 Workflow Loop 写入 | 不删除该路径，只删除能够确认的全局命令并报告保留项。 |
| <a id="r-15"></a>R15 | 卸载中途失败 | 不恢复已经删除的内容；明确列出已删除项、未删除项和失败原因，用户可以重新执行清理残留。 |
| <a id="r-16"></a>R16 | 卸载完成 | 只有目标范围内能够确认的管理内容全部删除后才显示成功。 |
| <a id="r-17"></a>R17 | 卸载后重新安装 | 重新安装按干净新安装处理，不恢复卸载前状态和历史。 |
| <a id="r-18"></a>R18 | 发布新正式版本 | GitHub Release 必须同时提供 `uninstall.sh` 和 `uninstall.ps1`，README 必须提供项目卸载和电脑全局卸载说明。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 用户 | 进入需要卸载 Workflow Loop 的项目根目录 | 当前目录成为唯一项目卸载目标 |
| 2 | 用户 | 执行 `workflow uninstall`，或旧版本对应的操作系统卸载脚本 | 程序检查实际存在的管理内容，不检查工作流轮次状态 |
| 3 | 程序 | 显示项目绝对路径、删除范围、保留范围和不可恢复说明 | 用户能够判断是否选对项目并了解后果 |
| 4 | 用户 | 确认或取消 | 取消时零修改；确认时开始强制删除 |
| 5 | 程序 | 删除 `AGENTS.md`、`.workflow_loop/` 和安装事务残留 | 当前项目不再受 Workflow Loop 管理 |
| 6 | 程序 | 核对目标范围 | 全部删除时显示成功；有失败项时列出真实残留 |
| 7 | 用户 | 需要删除电脑全局命令时单独执行 `workflow uninstall --global` | 程序不把项目卸载自动扩大到电脑级卸载 |
| 8 | 程序、用户 | 程序显示全局命令影响范围，用户确认或取消 | 确认后只删除电脑级命令和能够确认的命令搜索路径 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 当前项目有进行中轮次 | `state.json` 记录仍在进行 | 不阻止卸载，确认后连同状态和历史一起删除 | 明确提示进行中的轮次将永久消失 |
| 项目已经卸载 | `AGENTS.md`、`.workflow_loop/` 和安装残留都不存在 | 不修改任何文件，按成功处理 | 显示无需卸载 |
| 项目只有部分残留 | 只存在部分管理文件或安装事务目录 | 列出实际残留，确认后删除 | 用户知道本次只清理检测到的内容 |
| `AGENTS.md` 含有项目定制 | 文件在安装后被项目修改 | 仍按确认范围整份删除，不保存副本 | 确认提示明确说明内容不可恢复 |
| 文件权限阻止删除 | 部分管理文件不可删除 | 保留未能删除的内容，不恢复已删除项 | 列出已删除、未删除和失败原因 |
| 全局命令仍被其它项目使用 | 用户选择电脑全局卸载 | 不扫描项目，确认前说明所有依赖项目会暂时不能运行 | 用户决定是否继续删除全局命令 |
| 命令搜索路径来源不明 | 无法证明某个路径是 Workflow Loop 安装时加入 | 保留该路径，只删除能够确认的全局命令 | 显示保留路径及原因 |
| 卸载后执行旧工作流命令 | 项目管理目录已经删除 | 命令按未安装项目处理 | 用户需要重新安装后才能继续使用 Workflow Loop |
