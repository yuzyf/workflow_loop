# 【功能】复现产品缺陷

## 1. 背景

修复缺陷不能从“猜一个可能原因并改代码”开始。只有先确认产品原本应该怎样工作，再在真实场景中复现错误结果并查明根因，后续验收计划、实施、测试验证和验收才有稳定依据。

因此，本功能把用户报告转成可复核的缺陷记录：保存真实环境、输入、操作步骤、期望与实际结果、根因位置和证据，并在用户确认时确定修复后必须恢复的验收主题。缺陷只有在后续主题验收、最终全量回归和整体验收全部通过后才能关闭。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 复现已有产品缺陷 | 项目维护者 | 用户报告现有行为偏离已经确认的产品设计 | 在真实环境和真实输入下重现错误并找到根因 | 缺陷现象、期望行为和根因都有可复核证据 |
| 缺少项目设计时先初始化 | 项目维护者 | 修复缺陷时，项目设计架构尚未初始化 | 先建立当前产品与代码设计，再判断什么是缺陷 | 缺陷期望结果来自已经确认的产品设计，不靠修复人员猜测 |
| 用户报告混有多个无关缺陷 | 项目维护者 | 一组描述包含多个不同现象、原因或预期结果 | 识别边界并选择当前轮次只处理的一个缺陷 | 当前记录只对应一个明确缺陷，其它缺陷分别开始独立修复轮次 |
| 复现需要外部系统 | 项目维护者 | 缺陷依赖真实接口、账号、设备、文件或外部数据 | 在说明实际影响并取得必要确认后复现 | 证据来自真实场景，同时避免未经授权的扣费、发送、写入或删除 |

## 3. 功能边界

### 3.1 支持范围

- 使用现有产品设计确定期望行为，并检查用户报告的现象是否确实偏离该行为。
- 使用产品实际会遇到的环境、输入、入口、数据特征、操作路径和故障条件复现缺陷。
- 为确认根因执行针对性的代码调查、日志检查、命令、测量或最小诊断试验。
- 生成或更新 `bug/索引.md` 和当前轮次唯一的 `bug/缺陷_<缺陷文件标识>.md`，并保存当前工作流编号。
- 在缺陷记录中保存原始现象、环境与前置条件、复现步骤、期望结果、实际结果、证据、影响范围、根因位置和根因证据。
- 一份缺陷记录对应一个修复后必须恢复的验收主题；用户确认复现记录时登记该主题。
- 后续按主题验收、最终全量回归和整体验收的真实结果更新缺陷状态，同时保留原始复现事实。

### 3.2 不支持范围

- 不在复现环节修改正式产品代码或直接实施修复方案。
- 不用模拟返回、理想样本或脱离目标环境的玩具场景证明真实缺陷。
- 不把“可能是某段代码有问题”当成已经确认的根因。
- 不在修复缺陷流程中改变产品行为、产品规则、功能边界或用户可见结果。
- 不用复现记录代替后续技术穿刺、验收计划、测试验证、主题验收或最终全量回归。
- 不在缺陷复现成功、代码修改完成或主题测试通过时提前把缺陷标记为已修复。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| R1 | 开始复现缺陷 | 必须先确认项目设计架构已经初始化，并读取现有产品设计中与缺陷有关的预期行为。 |
| R2 | 判断实际结果是否为缺陷 | 必须对照已经确认的产品设计；现有设计没有定义预期结果时，不能由复现人员补产品规则。 |
| R3 | 选择复现材料 | 使用真实环境、真实输入和真实产品入口；脱敏或裁剪不能改变本次缺陷依赖的格式、结构、规模或故障特征。 |
| R4 | 记录复现步骤 | 写清环境与版本、前置条件、输入、操作顺序、实际结果和证据，使另一位维护者能够重复执行。 |
| R5 | 记录期望结果 | 说明产品应该出现的具体、可观察结果，并链接对应产品设计；不能只写“应该正常”或“符合预期”。 |
| R6 | 确认根因 | 必须写清根因所在文件、类、函数、类型、配置或外部约定，说明它怎样产生实际错误，并提供代码、日志、运行或测量证据。 |
| R7 | 区分复现和穿刺 | 复现环节必须完成缺陷和根因确认；后续 `spike`，中文含义为“技术不确定性穿刺”，只验证修复办法仍未确定且必须实际运行才能确认的技术事实。 |
| R8 | 复现会产生外部副作用 | 执行前说明操作对象、实际影响、预计费用和能否撤销，并取得用户明确确认；凭据不能写入缺陷记录或保留输出。 |
| R9 | 生成正式缺陷文件 | 使用稳定、安全的中文文件标识，正式路径为 `bug/缺陷_<缺陷文件标识>.md`；显示名称仍保留用户确认的完整中文描述。 |
| R10 | 更新缺陷索引 | `bug/索引.md` 必须链接本轮全部缺陷记录，并保存当前状态；旧工作流记录不能冒充本轮产物。 |
| R11 | 用户报告包含多个无关缺陷 | 当前 `bugfix` 修复缺陷轮次只处理一个具体缺陷。用户确认本轮要处理哪一个；其它缺陷不写入本轮记录，之后分别开始独立修复轮次。 |
| R12 | 确定验收主题 | 当前缺陷记录对应一个修复后必须恢复的用户结果；主题名称使用中文，在项目历史中永久唯一，并在复现记录确认时登记。后续验收计划必须覆盖恢复行为及其直接受影响行为，并逐项写清前提、触发、可观察结果和通过或不通过边界。 |
| R13 | 修复需要改变产品行为 | 停止当前修复缺陷流程；用户决定改产品时整轮作废，再以 `product_change`，中文含义为“修改产品”，开始新一轮。 |
| R14 | 更新缺陷处理结果 | 只能按验收计划、实施、测试验证和验收的实际进展追加后续结果，不能覆盖原始现象、复现条件、期望结果、实际结果和根因。 |
| R15 | 更新缺陷状态 | 主题验收通过后写“主题验收通过，待全量回归”；全量回归通过后写“全量回归通过，待整体验收”；回归失败写“回归失败，重新处理中”；整体验收通过后才写“已修复并验收”。 |
| R16 | 当前轮次未完成或已经作废 | 缺陷不能标记为已修复；用户取消修复缺陷等于放弃整轮，必须整轮作废。 |
| R17 | 推进缺陷复现环节 | 程序检查索引、文件变化、工作流编号、复现字段、根因字段和固定状态；用户检查证据是否真实、根因是否可信。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 程序 | 检查项目设计初始化状态，并指出缺陷复现环节必须读取的材料路径 | 设计尚未初始化时先进入项目设计架构初始化，不会直接猜期望行为 |
| 2 | 智能体 | 读取用户报告、现有产品设计、相关代码、测试、日志和已有运行证据 | 明确已经知道什么、需要实际复现什么以及产品规定的期望结果 |
| 3 | 智能体、用户 | 确认真实环境、输入、入口、前置条件、可能的外部副作用和允许执行的范围 | 复现条件与产品实际场景一致，高风险动作得到单独授权 |
| 4 | 智能体 | 执行复现步骤，保存实际输出、日志、截图、测量或其它可复核证据 | 错误结果被真实观察，不用推测或模拟结果代替 |
| 5 | 智能体 | 沿真实调用过程调查根因；需要时执行最小诊断试验 | 根因位置、产生错误的过程和证据得到确认 |
| 6 | 智能体、用户 | 核对是否混有多个无关缺陷，选择本轮只处理的一个缺陷，并确认修复后必须恢复的用户结果 | 当前轮次只有一份缺陷记录和一个验收主题；其它缺陷留给独立轮次 |
| 7 | 用户 | 确认缺陷现象、期望结果、根因和主题已经聊清楚 | 程序允许生成或更新缺陷索引与缺陷记录 |
| 8 | 程序、智能体 | 程序检查固定字段、链接和本轮变化；智能体对抗性检查复现是否可重复、证据是否支持根因 | 缺失条件、空泛根因和旧记录复用会被阻止 |
| 9 | 用户 | 阅读缺陷记录和检查结果并明确确认 | 程序登记验收主题，完成必要技术不确定性判断后依次进入验收计划、实施和测试验证 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 缺陷无法复现 | 按当前掌握的真实条件执行后没有出现报告现象 | 继续核对环境、输入、版本和操作差异；证据不足时停留在复现环节 | 不会把“偶尔可能发生”写成已经复现 |
| 缺少真实环境或输入 | 需要的设备、接口、文件、账号或数据暂时不可用 | 说明缺少条件和无法确认的内容，不用模拟材料替代 | 用户知道还需要准备什么，流程不会带着假证据推进 |
| 复现会产生未获同意的外部副作用 | 操作可能扣费、发送内容、创建、修改或删除外部数据 | 在执行前停止并请求明确确认；用户不同意且无其它真实方法时保持未确认 | 不会把同意调查缺陷当成同意实际外部操作 |
| 产品设计没有定义期望行为 | 无法判断报告现象是缺陷还是未定义行为 | 停止修复缺陷；需要定义或改变产品时整轮作废并启动修改产品流程 | 产品要求先由用户正式确认 |
| 根因尚未确认 | 只能确定错误现象，无法说明哪个真实位置怎样产生错误 | 继续调查或诊断，不进入后续穿刺和计划 | 后续不会围绕猜测的根因制定修复方案 |
| 用户报告混有多个无关问题 | 不同现象具有不同期望结果或不同根因 | 选择一个作为当前轮次缺陷，其它问题分别开始新的修复轮次 | 每轮修复只追踪、测试和验收一个具体缺陷 |
| 主题名称与历史重复 | 修复后结果名称已经在项目主题历史中使用 | 请用户确认一个不重复且仍准确表达结果的中文主题名称 | 后续文档不会把两次不同交付混成同一主题 |
| 索引或记录属于旧工作流 | 文件存在，但工作流编号与当前轮次不一致 | 旧文件只作参考，本轮必须更新索引并形成当前记录 | 不能用历史缺陷记录直接通过当前门禁 |
| 最终全量回归失败 | 主题验收已经通过，但完整项目测试未通过 | 把状态改为“回归失败，重新处理中”，调查原因并返回对应上游环节 | 缺陷不会提前关闭，原始复现事实保持不变 |
| 用户取消缺陷修复 | 当前修复不再继续 | 整轮作废并恢复本轮受管修改 | 缺陷保持未关闭，不会用取消冒充修复成功 |
