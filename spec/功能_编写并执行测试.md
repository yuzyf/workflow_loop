# 【功能】编写并执行测试

## 1. 背景

实施代码完成后，Workflow Loop 需要把验收条件和测试计划落实为真实测试代码，再由程序实际执行并保存机器事实。测试代码存在、AI 口头说明运行过，或者一次全量测试通过，都不能代替当前主题、当前测试项的正式执行证据。

本功能把测试代码编写和正式测试执行分开。编写期间可以运行直接相关的局部测试作为开发反馈；正式执行时，程序只运行已经登记并得到用户确认的命令，为每个测试项保存独立记录，AI 再据此生成可复核的主题测试结果。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 编写自动化测试 | 项目维护者 | 实施代码和测试计划已经确认 | 根据真实产品入口编写测试 | 每个自动化测试项都有可定位、可重复运行的测试代码 |
| 执行主题测试 | 项目维护者 | 测试代码和执行范围已经确认 | 按主题和测试项正式运行测试 | 程序保存与当前代码、测试代码和命令绑定的执行记录 |
| 处理混合测试 | 项目维护者、验收人 | 一个条件同时有自动化和人工判断部分 | 先证明自动化部分，再交接人工部分 | 自动化通过不会被误写成整条验收条件通过 |
| 重测受影响主题 | 项目维护者 | 上游计划、代码或测试发生有效变化 | 只重做直接受影响的测试 | 受影响主题获得新记录，独立主题的有效记录按规则保留 |
| 在原生 Windows 执行 | 项目维护者 | 项目在 Windows PowerShell 终端运行 | 使用 Windows 命令、路径和进程清理方式执行 | 命令无需经过 Unix 命令解释器，超时后不遗留测试进程 |

## 3. 功能边界

### 3.1 支持范围

- 读取当前验收计划、测试计划、实施记录、代码设计、产品代码、现有测试和测试配置。
- 根据真实产品入口选择单元、模块、集成、命令、接口或端到端测试。
- 在测试代码中保存验收主题、验收条件、测试项、测试目标、测试入口和产品代码入口的追踪标识。
- 编写测试代码和测试专用配置，并运行直接相关的局部测试作为开发反馈。
- 使用参数数组在 macOS、Linux 和原生 Windows 上正式执行已经登记的主题测试。
- 保存当前有效机器记录和历次执行历史，并生成 `qa/<主题文件标识>_测试结果.md`。
- 允许互不依赖且环境隔离的主题受控并行执行。

### 3.2 不支持范围

- 不重新制定产品规则、验收条件或测试范围。
- 不在测试代码环节修改产品代码。
- 不把局部开发测试写成正式测试结果。
- 不用临时代码、无关成功命令、固定返回值或无依据模拟数据冒充通过。
- 不用项目统一全量测试入口代替主题测试，也不执行人工验收或最终全量回归。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| R1 | 开始测试代码环节 | AI 必须使用文件读取和代码搜索工具核对上游文档、真实代码、现有测试和配置，不能只根据文件名猜测试写法。 |
| R2 | 编写自动化或混合测试 | 每个测试函数、测试类或测试场景都要带 `Workflow-Test`（工作流测试追踪标识），写清主题、`TC-xx` 测试项、`AC-xx` 验收条件、测试方式、测试层级、测试目标、测试入口和产品代码入口。 |
| R3 | 一个测试项有多个测试函数 | 每个测试函数只绑定一个主要测试项和一条主要验收条件；同一测试项可以由多个测试函数覆盖，共同准备过程使用测试夹具或辅助函数。 |
| R4 | 编写期间需要反馈 | 可以运行单个测试或单个测试文件等局部测试，但结果不进入正式成功记录，也不生成主题测试结果。 |
| R5 | 测试代码仍符合更新后的计划 | 用户确认复用后，AI 记录复用决定，不为制造变化而改空格、注释或增加无意义断言；后续正式测试仍须重跑。 |
| R6 | 登记正式测试 | 用户确认执行范围后，AI 只为自动化和混合测试项按一个 `TC-xx` 一组登记测试入口、运行目录、超时和 `argv`（命令参数数组）；纯人工测试项不登记命令。用户不手动输入工作流命令。登记只保存待执行任务，不运行测试或生成结果。 |
| R7 | 确认登记完整 | AI 执行测试执行环节的第一道门；程序检查全部自动化和混合测试项的主题、测试项、入口、命令和依赖已经登记完整，并确认纯人工测试项不需要执行任务。第一道门不运行测试。 |
| R8 | 启动正式测试 | 第一道门通过后，AI 执行统一测试运行命令；程序直接使用参数数组启动，不经过 Shell（命令解释器），也不接受管道、重定向、命令串联或命令替换。Windows 使用 Windows 进程树终止方式，macOS 和 Linux 使用对应进程组方式。 |
| R9 | 建立执行记录 | 每条执行记录只绑定一个 `TC-xx`。同一测试项的多个函数可以合并为一条命令或拆成多条命令；不同测试项不能混用一条记录。 |
| R10 | 判断测试项通过 | 当前测试项的全部测试函数和登记命令都已执行、退出码均为 `0`，并绑定执行时的产品代码和测试代码，才建立当前有效成功记录。 |
| R11 | 正式测试失败或超时 | 清除该测试项以前的当前成功记录，不生成通过结果；状态快照只保存当前有效成功记录，追加历史保存全部尝试。 |
| R12 | 生成主题测试结果 | 一个主题的全部自动化和混合测试项通过后，AI 只能根据机器记录写测试文件、测试函数、命令、环境、时间、时长、退出码、实际结果和证据，不能改写机器事实。 |
| R13 | 检查主题测试结果 | AI 执行测试执行环节的第二道门；程序核对结果文档与当前机器记录一致。用户确认整理完整后，第三道门才进入主题验收；第二、第三道门都不重新运行测试。 |
| R14 | 纯人工或混合主题 | 纯人工主题不生成测试结果文件；混合主题只写自动化通过和“待主题验收”，并说明仍需用户判断什么。 |
| R15 | 修正后确定重测范围 | 只重测当前主题和用户确认的直接受影响主题；不能只因整项目哈希变化删除独立主题记录，更广影响由最终全量回归检查。 |
| R16 | 环境、工具链或统一入口有问题 | AI 调查并给出建议，用户确认后先返回测试计划环节再修改。第一版不留在测试执行环节另建环境恢复分支。 |
| R17 | 项目需要全量测试入口 | 测试计划环节按 Python、Qt、Node 或其它真实技术栈确认项目专属入口；安装器不下发通用全量脚本，实施前也不强制运行修改前全量测试。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 程序、AI | 程序列出必读材料绝对路径，AI 逐份读取并调查相关代码和测试 | 测试工作建立在当前依据和真实代码上 |
| 2 | AI | 逐项说明产品入口、测试层级、测试文件、场景、断言、依赖和隔离方式 | 用户能够判断准备怎样证明验收条件 |
| 3 | 用户、AI | 用户确认测试落点后，AI 记录讨论完成并编写测试代码 | 第一道门只允许开始写代码，不代表测试通过 |
| 4 | AI、程序、用户 | AI 编写并局部检查测试；程序检查追踪标识和修改范围；用户确认测试代码 | 确认后的测试代码成为正式执行依据 |
| 5 | AI、用户 | AI 说明每个自动化或混合测试项的全部入口、命令、依赖和超时，并说明哪些纯人工测试项直接留给主题验收；用户确认范围 | 正式执行内容和人工交接在运行前可审查 |
| 6 | AI、程序 | AI 只为自动化和混合测试项登记待执行命令，再执行第一道门 | 程序确认应执行任务登记完整，并确认纯人工测试项无需命令；不运行测试 |
| 7 | AI、程序 | 第一道门通过后，AI 执行正式测试运行命令 | 程序逐项运行并保存绑定唯一主题和测试项的机器记录 |
| 8 | AI | 根据当前有效记录生成各主题测试结果 | 文档能够回查实际命令、测试函数和证据 |
| 9 | 程序、用户 | 第二道门核对结果与记录一致，用户确认整理完整后执行第三道门 | 门禁不重复运行测试；全部主题满足要求后进入主题验收 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 必读材料无法读取 | 文件不存在或读取失败 | 停止当前工作，不把路径清单当成已阅读 | 显示失败路径和需要修复的问题 |
| 计划与真实代码不一致 | 计划中的入口、方式或预期结果无法落实 | 调查后经用户确认返回测试计划或更上游环节 | 不用方便实现的测试替换已确认要求 |
| 产品代码缺少测试接缝 | 无法控制必要输入或观察结果 | 返回实施环节补充合理接缝 | 测试代码环节不偷偷改产品代码 |
| 登记记录混合多个测试项 | 一条记录同时绑定不同 `TC-xx` | 拒绝登记并按测试项拆开 | 每条机器事实只证明一个测试项 |
| 同一测试项漏跑函数 | 当前追踪标识下仍有函数未覆盖 | 不判定通过，补齐后重跑 | 一个通过函数不会代表整个测试项 |
| 测试失败或超时 | 退出码非零或超过确认时限 | 清除旧成功记录，停止相关依赖并输出错误摘要；超时时终止进程树 | 不生成伪造的通过结果 |
| 环境或工具链不可用 | 运行时、依赖、设备或入口无法启动 | 经用户确认返回测试计划环节 | 不在测试执行环节反复尝试未定义恢复 |
| 上游内容变化 | 计划、实施代码或测试代码变化 | 使直接受影响主题记录和结果失效 | 用户看到需要重测的主题和具体依据 |
