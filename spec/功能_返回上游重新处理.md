# 【功能】返回上游重新处理

## 1. 背景

计划、实施、测试或验收发现问题时，真正需要修改的位置可能在更早的环节。若直接修改已经确认的上游文档或代码，旧计划、旧测试和旧验收仍可能被误当成有效结果。

因此，智能体必须先调查问题来源，向用户说明应返回哪里和为什么。用户确认后，产品统一切换当前环节、清除实际受影响的旧结果并记录原因，然后才允许修改上游内容。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 验收条件有遗漏或矛盾 | 产品提出者、项目维护者 | 测试或验收时发现完成标准本身不正确 | 返回验收计划重新确认 | 旧测试计划及受影响后续结果不再冒充有效 |
| 测试范围或环境不正确 | 项目维护者 | 测试无法覆盖验收条件，或统一测试入口、工具链、环境有问题 | 返回测试验证调整 | 测试入口和范围重新确认，相关测试重新执行 |
| 产品实现不符合要求 | 项目维护者 | 测试或验收发现产品代码问题 | 返回实施环节修正 | 受影响主题重新测试和验收 |
| 已确认的核心代码变化 | 项目维护者 | 后续门禁发现已登记核心代码与确认时不同 | 看清具体变化后返回正确环节 | 一次看到所有新增、修改、删除或类型变化路径和受影响结果 |
| 测试代码或执行有问题 | 项目维护者 | 测试实现错误，或登记、执行、结果整理不正确 | 返回测试验证环节 | 无效机器记录和正式结果被清除；只需重做受影响的内部步骤 |
| 出现新的技术不确定性 | 产品提出者、项目维护者 | 后续工作发现必须通过真实运行确认的新事实 | 返回本轮较早的穿刺环节 | 原跳过状态被清除，正式完成技术验证 |
| 产品要求发生变化 | 产品提出者、项目维护者 | 从零做或修改产品时，后续发现需要改变产品规则、边界或用户行为 | 返回产品设计 | 新产品决定重新经过后续计划、实施和验证 |
| 取消一个功能或主题 | 产品提出者 | 从零做或修改产品时，只取消本轮的一部分 | 返回产品设计并处理受影响内容 | 其它不受影响功能保留，本轮不被整轮作废 |

## 3. 功能边界

### 3.1 支持范围

- 支持从当前环节返回本轮路径中任意更早的真实环节。
- 由智能体调查问题来源并提出建议，由用户确认最终返回目标。
- 切换当前环节，清除目标环节和实际受影响的下游门禁、校验凭据、机器记录及正式结果。
- 保存返回原因、来源环节、目标环节和受影响主题。
- 只重做当前主题和有具体证据表明确实受影响的其它主题。
- 支持复用仍符合最新上游依据的计划、代码或测试代码，但必须重新核对和确认。
- 支持返回此前跳过的穿刺环节并正式执行。
- 验证失效前比较已确认的逐文件快照，按新增、修改、删除和类型变化列出全部具体核心代码路径。
- 失效输出同时说明使用的快照范围、受影响环节、会清除的结果和会保留的内容。

### 3.2 不支持范围

- 不根据退出码、错误文字或自然语言原因自动猜测返回目标。
- 不维护脱离本轮真实环节路径的固定返回选项表。
- 不允许返回当前环节、后续环节或本轮路径中不存在的环节。
- 不允许先修改已确认上游内容，再补做返回登记。
- 不因“可能有关”自动让全部主题或全部间接依赖主题失效。
- 不遍历整个项目或按文件后缀猜测代码变化；未在现状架构基线、本轮代码计划或代码结果中登记的路径变化不触发实施失效。
- 不用无意义的文字、注释或空修改制造“重新完成”的痕迹。
- 修复缺陷流程不通过返回动作改变产品要求；确需改产品时应作废修复轮次并开始修改产品。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| <a id="r-1"></a>R1 | 后续环节发现问题 | 智能体先检查产品设计、现状架构基线、验收计划、代码计划、代码结果、产品代码、测试代码、测试结果和环境，确定问题实际产生在哪一层。 |
| <a id="r-2"></a>R2 | 智能体提出返回建议 | 必须向用户说明具体问题、现有依据、建议返回的中文环节、返回后哪些结果失效以及哪些内容可能复用。 |
| <a id="r-3"></a>R3 | 用户尚未确认 | 不执行返回命令，也不修改已确认的上游文档、代码、测试或配置。 |
| <a id="r-4"></a>R4 | 用户确认返回 | 智能体执行 `workflow return --to <阶段> --reason <具体原因>`；该命令表示“把当前轮次退回指定上游环节并记录原因”，不是让用户手工输入。 |
| <a id="r-5"></a>R5 | 检查返回目标 | 目标必须存在于当前轮次的 `stage_path` 环节路径中，并且位于当前环节之前；程序不根据原因文字推断目标。 |
| <a id="r-6"></a>R6 | 返回跳过的穿刺环节 | 清除“已经跳过”状态，把穿刺作为正式当前环节重新讨论、验证和确认。 |
| <a id="r-7"></a>R7 | 返回成功 | 更新当前环节，清除目标及受影响下游的旧门禁和验证状态，在状态快照、流水日志和需求交付追踪表中记录返回。 |
| <a id="r-8"></a>R8 | 验收计划变化 | 返回验收计划；受影响实施先重新核对，随后依据最新真实代码重新进入测试验证和验收。 |
| <a id="r-9"></a>R9 | 测试范围、环境、工具链或统一测试入口变化 | 返回测试验证环节并重新确认范围；已确认实施在没有代码或实施记录变化证据时保持有效。公共入口变化使全部主题的旧测试结果失效，其它变化只清除有具体影响证据的主题结果。 |
| <a id="r-10"></a>R10 | 产品代码或实施记录变化 | 返回实施环节；当前主题和有具体证据的直接受影响主题重新核对实施，原测试验证结果和验收结果失效，其它主题结果可以保留，最终全量回归必须失效。 |
| <a id="r-11"></a>R11 | 测试代码或测试专用配置变化 | 返回测试验证环节；只让当前主题和确认直接受影响的主题重新检查测试代码、执行测试和验收，最终全量回归必须失效。 |
| <a id="r-12"></a>R12 | 测试执行记录或结果有问题 | 留在或返回测试验证环节；清除受影响的当前成功记录和正式结果，再使用当前有效代码重新执行。固定结果字段与机器记录不一致时，优先由程序重新生成文档，不因抄写错误退回代码实施。 |
| <a id="r-13"></a>R13 | 判断直接受影响主题 | 智能体检查共享产品行为、代码、数据、状态、输入输出约定、实施记录和测试标识，说明每个主题受到的具体影响；仍无法判断时由用户决定是否加入重测范围。 |
| <a id="r-14"></a>R14 | 只存在间接依赖 | 不因依赖关系本身自动扩大失效范围；没有具体影响证据时保留当前结果，最终全量回归负责检查组合后的完整项目。 |
| <a id="r-15"></a>R15 | 重新进入计划或代码环节 | 现有内容仍符合最新上游时可以复用并保存对应依据，不要求制造文件变化；测试验证中的失效执行记录、主题验收和最终全量回归必须重新执行。 |
| <a id="r-16"></a>R16 | 产品要求变化 | 从零做或修改产品返回产品设计；修复缺陷不能返回本轮不存在的产品设计，用户决定改产品时整轮作废，再开始修改产品。 |
| <a id="r-17"></a>R17 | 取消本轮一个功能 | 从零做或修改产品返回产品设计并指定受影响主题；删除只服务于该功能的内容，保留其它功能和仍被共享的代码，随后重做受影响验证。 |
| <a id="r-18"></a>R18 | 显示返回结果 | 成功时说明已经返回哪里、清除了什么、接下来由谁做什么；失败时说明目标为什么无效和当前正确环节，不能只显示英文标识。 |
| <a id="r-19"></a>R19 | 核心代码摘要与确认值不同 | 程序必须先用确认时保存的逐文件快照与当前文件比较，一次列出全部新增、修改、删除和类型变化；不得只输出“实施代码或实施记录已改变”。 |
| <a id="r-20"></a>R20 | 判定核心代码范围 | 只使用当前现状架构基线、用户确认的代码计划和最终代码结果中的明确文件路径。程序不自动扩大范围。 |
| <a id="r-21"></a>R21 | 只有安装、构建、缓存或运行产物变化 | 只要路径没有被明确登记为核心代码，就忽略该变化，不退回实施、不清除测试或验收结果。 |
| <a id="r-22"></a>R22 | 执行失效处理 | 先完成全部可靠比较并展示具体证据，再按最早失效源一次清理相应状态和结果；检查与清理不能边遇到第一项边提前结束。 |
| <a id="r-23"></a>R23 | 判断计划是否变化 | 只比较该计划负责的范围、入口、步骤和通过标准。后续结果链接、执行状态、机器记录编号、时间和验收状态变化不算计划变化，不能因此清除成功测试记录。 |
| <a id="r-24"></a>R24 | 用户确认前检查当前结果 | 校验凭据仍匹配时直接复用第二道门结果；凭据绑定依据变化时只列出具体变化并要求重新校验，不无条件重复完整检查。 |

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 智能体 | 在计划、实施、测试或验收发现实际问题后停止继续推进 | 旧结果不会在问题未处理时继续通过后续门禁 |
| 2 | 智能体 | 调查问题来源、当前环节路径、相关主题和共享影响；涉及快照变化时核对逐文件差异 | 区分产品、验收条件、测试范围、实现、测试代码、执行或环境问题，并得到具体变化路径 |
| 3 | 智能体 | 用直白中文向用户说明建议返回位置、原因、失效范围和可复用内容 | 用户知道返回是为了解决什么，而不是只看到一条技术命令 |
| 4 | 用户 | 确认返回目标和直接受影响主题 | 产品获得明确决定，不自行扩大或缩小处理范围 |
| 5 | 智能体 | 调用返回命令 | 程序验证目标属于本轮较早环节 |
| 6 | 产品 | 切换当前环节，清除受影响门禁、执行记录、正式结果和追踪状态，并追加流水日志 | 状态与用户确认的处理范围保持一致 |
| 7 | 智能体、用户 | 按最新上游依据重新讨论、修改或复核现有内容 | 一致的内容可复用；确实失效的测试和验收重新执行 |
| 8 | 产品 | 重新经过原有后续环节，并在最新完整代码上执行最终全量回归 | 局部复用不会绕过最终整体检查 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| 返回目标不在本轮路径 | 例如修复缺陷试图返回本轮不存在的产品设计 | 拒绝返回，状态不变 | 显示本轮路径和可调查的正确处理方式 |
| 返回目标不是更早环节 | 目标是当前环节或后续环节 | 拒绝返回 | 说明返回只能指向当前轮次已经经过或可重新进入的上游 |
| 轮次已经结束 | 当前轮次已正式收工或作废 | 拒绝修改旧轮次状态 | 说明需要开始新轮次 |
| 原因或影响范围不清楚 | 智能体尚未查清问题来源 | 继续调查和讨论，不执行返回 | 用户不会被迫在没有依据时选择阶段 |
| 上游内容已经被提前修改 | 未先返回就改了确认内容 | 不把这条绕过流程的修改当成合法返回结果 | 要求先恢复正确流程；第一版不声称自动侦测所有外部手工修改 |
| 环境问题被当成代码问题 | 测试工具链、运行时或统一入口缺失 | 留在或返回测试验证，不固定退到实施 | 用户重新决定环境和测试方式 |
| 依赖主题被无依据清除 | 只有主题依赖关系，没有具体行为或代码影响 | 保留该主题当前结果 | 最终全量回归仍检查完整组合 |
| 复用内容不再符合新依据 | 重新核对时发现旧计划、代码或测试已过时 | 修改并重新确认，不允许直接推进 | 用户看到具体不一致和需要重做的部分 |
| 测试结果链接更新被误判为计划变化 | 计划正文没有变化，只是索引中的结果链接或执行状态更新 | 忽略这些下游字段，不清除计划、测试代码、成功记录或结果文档 | 正常生成结果不会把流程退回上游 |
| 只有范围外文件变化 | 依赖安装、构建、开发服务、缓存或其它未登记路径产生文件 | 核心代码快照忽略这些路径，不执行失效处理 | 工作流保持当前环节和有效结果 |
| 只有总摘要不同但没有文件证据 | 旧状态没有保存逐文件快照，无法证明具体变化 | 不用笼统理由直接清零；明确报告证据缺失并要求重建可解释快照 | 用户知道程序无法确认哪些文件变化，不会看到伪造的确定结论 |
