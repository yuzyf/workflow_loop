# 【功能】安装到项目

## 1. 背景

Workflow Loop 必须先把全局命令、智能体契约、产物模板和阶段工作规范完整安装到目标项目，才能管理后续开发流程。用户不应先手工安装多个工具，再执行第二条项目接入命令。

因此，产品为 macOS、Linux 和原生 Windows 分别提供一条官方安装命令。安装器先说明将要修改什么，用户确认后一次完成电脑侧和项目侧安装；任一步失败，都恢复到确认前的状态。

## 2. 场景

| 场景 | 使用者 | 发生条件 | 想完成的事情 | 预期结果 |
|---|---|---|---|---|
| 首次安装 | 项目维护者 | 电脑和当前项目都没有安装 Workflow Loop | 用一条命令完成全部安装 | 全局 `workflow` 命令可用，当前项目得到完整安装骨架 |
| 只安装当前项目 | 项目维护者 | 电脑已有身份和版本正确的全局命令，当前项目尚未安装 | 把流程安装到当前项目 | 复用全局命令，只新增当前项目需要的文件 |
| 只安装全局命令 | 项目维护者 | 当前项目骨架来自复制或克隆，内容完整，但当前电脑没有全局命令 | 让本机能够运行已安装项目 | 项目文件保持不变，只安装全局命令和必要的命令搜索路径 |
| 重复执行安装 | 项目维护者 | 电脑和当前项目都已经完整安装版本 `0.1.0` | 确认当前状态，不破坏项目定制内容 | 安装器说明两侧均已安装，不修改任何文件 |
| 在原生 Windows 安装 | Windows 项目维护者 | 已安装 Python 3.11 或更高版本，并可运行 Windows PowerShell 5.1（系统自带脚本环境）或 PowerShell 7（新版脚本环境） | 不依赖 Windows Linux 子系统完成安装 | 使用可用的 PowerShell 环境完成安装并运行后续命令 |

## 3. 功能边界

### 3.1 支持范围

- 支持 macOS、Linux，以及具备 Windows PowerShell 5.1 或 PowerShell 7 和 Python 3.11 或更高版本的原生 Windows 环境。
- macOS 和 Linux 使用 Bash 安装脚本；原生 Windows 使用 PowerShell 安装脚本。
- 安装前检查 Python 3.11 或更高版本、已有同名命令、目标项目、全局工具目录和命令搜索路径。
- 在一次确认后完成全局命令安装、必要的命令搜索路径修改、`AGENTS.md` 智能体契约写入和 `.workflow_loop/` 项目骨架安装。
- 把产物文档模板仓库和阶段工作规范仓库复制到当前项目，使后续讨论读取项目内材料。
- 安装失败或用户取消时，不让电脑或项目停留在只完成一部分的状态。
- 支持完整项目被复制到另一台电脑后，只补装电脑侧全局命令。

### 3.2 不支持范围

- 不自动下载或安装 Python。
- 不把尚未单独验证的某个 Windows 桌面版本写成已确认的支持范围。
- 不提供 `workflow attach` 之类要求用户再次执行的项目接入命令。
- 不公开允许绕过安装确认的项目写入命令。
- 不升级、迁移或修复版本异常、文件缺失的旧安装。
- 不覆盖同版本项目已经定制的模板、规范或智能体契约。
- 不给所有项目安装当前仓库专用的 `scripts/test_all.sh` 全量测试脚本；每个项目的测试环境和统一测试入口在测试计划阶段确定。
- 不自动创建正式产物目录、工作流状态文件或版本控制忽略规则。

## 4. 规则

| 编号 | 条件 | 规则 |
|---|---|---|
| R1 | 用户准备安装 | 用户必须先进入目标项目根目录；安装器不向上猜测项目根。 |
| R2 | macOS 或 Linux 安装 | 官方命令固定使用版本 `0.1.0` 的 Bash 脚本，完整命令见本表后。 |
| R3 | 原生 Windows 安装 | 官方命令固定使用版本 `0.1.0` 的 PowerShell 脚本，完整命令见本表后；临时放行执行策略只影响本次进程，不永久降低系统策略。 |
| R4 | 检查运行环境 | 必须在任何下载和写入前找到 Python 3.11 或更高版本；找不到时说明所需版本和安装方法并停止。 |
| R5 | 检查已有 `workflow` 命令 | `workflow` 是 Workflow Loop 的全局命令。安装器必须用 `workflow --version` 核对产品身份和版本；其它软件的同名命令或不兼容版本不能复用，也不能静默覆盖。 |
| R6 | 确定写入范围 | 安装器必须先完成无写入预检，确定项目根、全局工具环境、全局命令实际路径、需要新增的命令搜索路径或需要修改的终端配置文件。无法提前确定时停止。 |
| R7 | 请求安装确认 | 只询问一次，但确认前必须完整列出项目绝对路径、`AGENTS.md`、`.workflow_loop/`、全局工具环境、命令路径及命令搜索路径修改；用户确认的是全部持久修改。 |
| R8 | 用户取消 | 不下载临时工具，不安装全局命令，不修改命令搜索路径、终端配置、`AGENTS.md` 或 `.workflow_loop/`。 |
| R9 | 安装全局命令 | 正式发行包固定为 Python 公共软件包仓库中的 `workflow-loop==0.1.0`。安装器使用版本和文件摘要都固定的临时 `uv` 安装工具，不能覆盖用户已有的其它版本，也不能让该工具自动下载 Python。 |
| R10 | 固定产品版本 | 源码发行版本、GitHub 发布标签、安装脚本、全局工具要求、`workflow --version` 和项目安装标记必须全部严格等于 `0.1.0`；当前产品不设计其它版本或兼容范围。 |
| R11 | 正式发布 | GitHub 正式发布页和 Python 公共软件包仓库必须提供同一个 `0.1.0`；三个操作系统的真实安装测试全部通过后才能公开发布。已经发布的 `0.1.0` 不能覆盖或重新发布。 |
| R12 | 写入当前项目 | 未安装项目在用户确认后新建或整份覆盖 `AGENTS.md`，并安装 `.workflow_loop/`、模板、规范、版本标记和 `project.json` 项目状态；项目设计初始化状态初始为否。 |
| R13 | 保持安装骨架精简 | 安装时不创建 `state.json` 当前轮状态，也不预建 `spec`、`acceptance`、`qa`、`impl` 或 `bug` 正式产物目录。 |
| R14 | 保证安装原子性 | 第一次持久写入前保存原内容和“原本不存在”记录；任一步失败时只撤销本次安装动作，恢复原文件和原命令搜索路径。全部成功后删除临时副本。 |
| R15 | 处理重复安装 | 项目骨架完整且版本严格等于 `0.1.0` 时，项目侧保持零修改；电脑侧缺少全局命令时只补装电脑侧。骨架不完整、版本缺失或版本不同则在写入前停止，不当成首次安装。 |
| R16 | 生成正式产物 | 安装下发的模板和规范必须要求面向用户的正式产物使用中文文件名；英文目录名、程序命令、状态文件和代码标识保持不变，并在中文正文首次出现时解释含义。 |
| R17 | 安装后核对 | 必须直接调用实际安装位置中的命令确认产品身份和版本，再完成项目写入；不能要求用户重开终端后执行第二条命令。 |

macOS 和 Linux 的官方安装命令：

```bash
curl -fsSL https://github.com/yuzyf/workflow_loop_spike/releases/download/v0.1.0/install.sh | bash
```

原生 Windows 的官方安装命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://github.com/yuzyf/workflow_loop_spike/releases/download/v0.1.0/install.ps1 | iex"
```

## 5. 使用过程

| 步骤 | 执行者 | 操作或行为 | 产品响应或结果 |
|---|---|---|---|
| 1 | 用户 | 进入目标项目根目录，执行当前操作系统对应的一条官方安装命令 | 安装器开始只读预检，不立即修改电脑或项目 |
| 2 | 安装器 | 检查 Python、已有同名命令、项目安装状态、全局工具位置和命令搜索路径 | 得到本次实际需要修改的完整范围；条件不满足时在写入前停止 |
| 3 | 安装器 | 向用户显示项目绝对路径和全部持久修改 | 用户能够在写入前判断目录和影响范围是否正确 |
| 4 | 用户 | 确认或取消本次安装 | 取消时零写入；确认时建立可恢复的安装事务 |
| 5 | 安装器 | 准备并校验固定版本的临时安装工具，安装或复用全局命令 | 全局命令身份和版本得到核对，不覆盖无关同名软件 |
| 6 | 安装器 | 在临时位置准备完整项目骨架，再写入 `AGENTS.md` 和 `.workflow_loop/` | 项目获得最小智能体契约、模板、规范和项目级状态 |
| 7 | 安装器 | 调用实际命令路径执行版本核对，并检查项目骨架 | 全部成功后提交事务并删除临时文件；失败时恢复确认前状态 |
| 8 | 用户 | 启动支持的智能体并直接提出开发需求 | 智能体读取 `AGENTS.md` 后自动检查并开始或继续工作流 |

## 6. 异常情况

| 异常情况 | 发生条件 | 产品处理 | 用户看到的结果 |
|---|---|---|---|
| Python 不兼容或不存在 | 没有 Python 3.11 或更高版本 | 在任何下载和写入前停止，不替用户安装 | 明确显示所需版本和安装方法 |
| 当前目录错误 | 用户发现显示的项目根不是目标项目 | 用户取消，切换目录后重新执行 | 错误目录不产生任何修改 |
| 同名命令不是 Workflow Loop | 命令搜索路径中已有其它 `workflow` | 停止安装，不调用项目写入能力 | 显示实际命令位置、检测到的身份或版本和处理方法 |
| 企业策略禁止脚本 | Windows 组织策略仍阻止 PowerShell 脚本 | 明确停止，不绕过组织策略 | 项目保持未安装 |
| 下载失败或文件摘要不符 | 临时安装工具或发行包无法可信取得 | 删除临时内容并停止 | 全局命令和项目文件保持原状 |
| 项目骨架不完整或版本异常 | 已存在部分 `.workflow_loop/`，但不符合完整的 `0.1.0` | 在写入前停止，不删除或覆盖现有内容 | 明确列出检测到的问题；当前版本不自动修复 |
| 安装中途失败 | 全局命令、命令搜索路径或项目写入任一步失败 | 根据事务清单恢复本次修改 | 只有全部恢复成功才说明安装失败但环境已还原 |
| 强制终止或断电 | 安装器来不及完成恢复 | 保留临时事务记录；下次安装先继续恢复，恢复完成后才能重试 | 不把半套安装当成成功 |
| 重复安装 | 电脑和项目都已经完整安装 `0.1.0` | 不修改项目或电脑 | 明确说明两侧均已安装、未修改任何文件 |
