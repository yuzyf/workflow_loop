# 实施文档模板

本模板定义实施阶段最终生成的两类文档：

1. `impl/索引.md`：继承验收主题关系，并提供各主题实施文档入口。
2. `impl/<主题文件标识>_实施记录.md`：记录一个验收主题的代码计划、实际实施过程和最终代码结果。

文档标题保留完整中文主题名称；文件名使用程序生成并保存的稳定中文文件标识，与该主题的验收计划使用同一个标识。

本模板只规定实施记录的章节、字段、表格、链接和内容边界。代码计划记录本轮实施决定和最低实现设计；最终代码设计文档只记录代码、测试和验收完成后的真实结构。

## 一、`impl/索引.md` 模板

```markdown
# 实施索引

## <workflow_id>

### 主题关系

| 展示顺序 | 验收主题 | 前置主题 | 验收计划 | 实施文档 |
|---|---|---|---|---|
| 1 | <主题 A> | 无 | [主题 A 验收计划](../acceptance/<主题 A 文件标识>_验收计划.md) | [主题 A 实施记录](./<主题 A 文件标识>_实施记录.md) |
| 2 | <主题 B> | <主题 A> | [主题 B 验收计划](../acceptance/<主题 B 文件标识>_验收计划.md) | [主题 B 实施记录](./<主题 B 文件标识>_实施记录.md) |
```

规则：

- `impl/索引.md` 必须继承 `acceptance/索引.md` 的展示顺序和前置主题，不能重新制定主题关系。
- `展示顺序`只用于阅读；真正的等待关系由“前置主题”表达。
- 每个主题必须且只能出现一次。
- `验收主题`列写完整中文主题名称；链接路径使用程序保存的稳定中文文件标识。
- 索引只保存主题关系和文档入口，不复制代码修改逻辑、运行状态、测试结果或验收结果。

## 三、内容边界

- `impl/索引.md` 不能写具体代码修改步骤；这些内容写在对应主题文档中。
- `impl/<主题文件标识>_实施记录.md` 必须写到具体文件、类、函数或新增位置，不能只写模块名称。
- 固定顺序是“代码计划 -> 代码实施 -> 代码结果”。用户只确认代码计划和代码结果；代码实施按已确认计划连续完成，不增加逐步确认。
- “实施前计划（代码计划）”写修改前已经确认的方案；“实施后记录（代码实施与代码结果）”先按实际顺序记录动作和反馈，再根据最终代码填写结果，不能复制计划或过程记录代替事实。固定章节包括“实施前计划”“实施后记录”“未决问题”和“未完成内容”，工作顺序是代码计划、代码实施、代码结果。
- 从零开发的最低实现设计和修改产品的本轮实现决定都写进代码计划；本轮实际架构变化在最终代码设计同步阶段依据真实代码更新。
- 代码计划、实施动作、真实代码差异集合和代码结果必须一一一致；代码结果必须写具体文件、精确位置、真实逻辑，以及数据、状态或输出变化。
- 实施文档只绑定验收条件，不依赖尚未生成的测试计划或 `TC`（测试项编号）。
- 不建立“计划与实际差异”章节。实施需要偏离当前确认计划时，应先停止、更新代码计划并重新取得用户确认；不能先改完再把偏差包装成结果。
- 实施文档可以记录语法、类型、静态检查或局部运行等开发检查反馈，但这些反馈不是正式测试，不能填写正式测试通过、正式测试失败或主题验收通过。
- 尚未生成的下游文档只写反引号包裹的普通相对路径和“（待生成）”，文件真实存在后才改成 Markdown 链接。
- 没有相关内容时写“暂无”，不得编造内容填满表格。
