# 主题测试结果文档模板

本模板只定义测试执行完成后，由 AI 根据程序执行事实写入的 `qa/<topic>_result.md` 结构。
它不是测试计划，也不是测试代码模板。测试命令、测试函数和测试结果必须来自真实执行，不能根据计划猜测。

```markdown
# 【主题测试结果】<主题名称>

- 工作流编号：<workflow_id>
- 验收主题：<主题名称>
- 自动化测试结果：通过
- 人工验收状态：无需人工验收 | 待主题验收
- 测试完成时间：<实际完成时间>

## 1. 测试依据

- [验收计划](../acceptance/<topic>_plan.md)
- [测试计划](./<topic>_plan.md)
- [实施计划和记录](../impl/<topic>.md)
- [需求交付追踪表](../traceability.md)

## 2. 测试环境和执行说明

- 执行环境：<平台、解释器或测试运行环境>
- 本主题执行范围：<本次实际执行的测试项>
- 执行顺序：<按照测试计划中的前置测试项说明>
- 未执行项：暂无

## 3. 测试项结果

### TC-01：<测试项名称>

- 对应验收条件：[AC-01：<验收条件名称>](../acceptance/<topic>_plan.md#ac-01)
- 测试方式：自动化测试 | 自动化测试 + 人工验收
- 测试入口：<测试函数、测试类或测试场景的真实入口>
- 执行命令：<程序实际执行的命令>
- 退出码：0
- 实际结果：<实际观察到的结果>
- 自动化测试结果：通过
- 证据：<别人可以复核的证据>

## 4. 人工验收交接

纯自动化测试填写“无需人工验收”。混合测试必须填写：

- 人工验收对象：<用户需要观察或判断的对象>
- 人工检查方法：<用户按什么步骤检查>
- 自动化已经证明：<自动化测试已经证明的部分>
- 还需要用户确认：<不能由自动化替代的部分>
- 人工结果填写位置：`acceptance/<topic>_result.md`

## 5. 未通过或阻塞

暂无

## 6. 上下游文档

| 关系 | 文档 | 说明 |
|---|---|---|
| 上游 | [验收计划](../acceptance/<topic>_plan.md) | 说明什么算完成 |
| 上游 | [测试计划](./<topic>_plan.md) | 说明本次覆盖哪些测试项 |
| 上游 | [实施记录](../impl/<topic>.md) | 说明本次代码怎样实现 |
| 全局 | [需求交付追踪表](../traceability.md) | 查看完整链路 |
| 下游 | [主题验收](../acceptance/<topic>_result.md) | 混合测试在这里接收人工确认 |
```

## 完成前检查

- 只在所有要求执行的自动化测试项实际执行且退出码为 `0` 后生成正式结果。
- `TC`、测试入口、命令、退出码和自动化结果必须能与程序登记的当前测试执行记录对应。
- 混合测试必须保留人工验收交接内容；不能把自动化通过写成整条验收条件已经通过。
- 不能写“功能正常”“符合预期”这类没有实际观察内容的结论。
- 测试失败、超时、阻塞或未执行时，不生成“自动化测试结果：通过”的正式结果。
- 不在本结果文档中新增产品规则、验收条件或代码实现方案。
