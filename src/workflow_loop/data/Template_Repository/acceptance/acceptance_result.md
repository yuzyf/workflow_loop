# 主题验收结果文档模板

本模板定义 `acceptance/<topic>_result.md` 最终记录什么。只有当前主题的全部验收条件都已经通过时，才生成正式结果文件；未通过、无法验证或受到阻塞时，不生成正式结果。

```markdown
# 【主题验收结果】<主题名称>

- 工作流编号：<当前 workflow_id>
- 验收主题：<主题名称>
- 验收结果：通过
- 验收完成时间：<实际时间>

## 1. 验收依据

| 关系 | 文档 | 说明 |
|---|---|---|
| 上游 | [主题验收计划](./<topic>_plan.md) | 本主题全部验收条件 |
| 上游 | [主题测试结果](../qa/<topic>_result.md) | 自动化或混合主题使用；纯人工主题整行改为“无自动化测试项” |
| 上游 | [实施记录](../impl/<topic>.md) | 本主题实际实施内容 |
| 全局追踪 | [需求交付追踪表](../traceability.md) | 当前验收条件的完整上下游关系 |

## 2. 验收条件结果

### AC-01：<验收条件名称>

- 验收方式：自动化测试 | 人工验收 | 自动化测试 + 人工验收
- 验收条件：<写出具体条件，并链接到主题验收计划中的对应位置>
- 自动化依据：<对应 qa/<topic>_result.md 中的测试项和结果；纯人工验收写“不适用”>

#### 人工验收步骤

- 验收对象：<用户实际检查什么>
- 开始前条件：<执行验收前必须具备的状态或数据>
- 操作步骤：
  1. <具体操作>
  2. <具体操作>
- 观察内容：<用户实际观察什么>
- 预期结果：<验收条件要求看到的明确结果>
- 用户需要回答：<要求用户确认的具体问题>

纯自动化验收条件不需要人工操作时，本小节写“不适用”。

- 用户实际回答：<用户最终回答；纯自动化写“不适用”>
- 人工确认：通过 | 不适用
- 确认时间：<程序记录的确认时间；纯自动化写“不适用”>
- 实际结果：<自动化结果、人工观察结果或两者组合>
- 判定：通过
- 验收证据：<实际观察说明、测试记录、运行输出、截图或文件；没有独立文件时写具体观察说明>
- 程序记录：<State Snapshot 中当前有效记录的 record_id>

## 3. 上下游文档

| 关系 | 文档 | 说明 |
|---|---|---|
| 上游 | [主题验收计划](./<topic>_plan.md) | 验收标准来源 |
| 上游 | [主题测试结果](../qa/<topic>_result.md) | 自动化或混合主题使用；纯人工主题整行改为“无自动化测试项” |
| 上游 | [实施记录](../impl/<topic>.md) | 被验收的实际实现 |
| 全局追踪 | [需求交付追踪表](../traceability.md) | 本主题在完整交付链路中的位置 |
| 下游 | 最终全量回归 | 所有主题通过后执行 |
```

## 完成前检查

- 是否绑定当前工作流编号和当前验收主题。
- 是否覆盖验收计划中的全部适用验收条件，没有遗漏或增加条件。
- 每条条件是否写明验收方式、实际结果、判定、验收证据和程序记录。
- 实际结果、验收证据、用户回答、确认时间和程序记录编号是否与 State Snapshot 完全一致。
- 自动化验收条件是否引用当前有效的主题测试结果。
- 需要人工验收时，是否写清验收对象、开始条件、操作、观察内容和预期结果。
- 人工条件是否记录用户实际回答和程序确认时间，且内容与当前有效程序记录一致。
- 纯自动化条件是否把用户回答、人工确认和确认时间写为“不适用”。
- 是否所有条件都明确通过，总结果固定为“通过”。
- 是否在存在未通过、无法验证或阻塞时错误生成了正式结果文件。
- 是否用“功能正常”“符合预期”等空泛结论代替实际结果。
- 是否混入新的产品规则、代码方案或实施步骤。
