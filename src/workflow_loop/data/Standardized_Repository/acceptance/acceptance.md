# 主题验收阶段工作规范

## 目的

在某个验收主题的实施和测试完成后，按照已经确认的主题验收计划核对实际结果，并让用户确认是否达到验收条件。正式阶段名是 `topic_acceptance`，最终结果使用 `Template_Repository/acceptance/acceptance_result.md`。

本阶段不修改需求、产品规则、验收主题或验收条件。

## 一、开始前调查

读取：

1. 当前工作流编号和当前验收主题。
2. `acceptance/<topic>_plan.md` 中的验收目标、范围和全部验收条件。
3. `qa/<topic>_result.md` 中的测试结果和证据。
4. 与本主题有关的实施记录、产品设计和 `traceability.md`。

测试没有通过、测试结果已经失效、实施记录缺失或验收计划本身不能判断时，不开始主题验收。

## 二、执行验收

逐条按照验收条件核对实际结果：

- 使用已经确认的触发条件。
- 观察用户可见或可核实的实际结果。
- 保存别人可以复核的证据。
- 明确写出通过、未通过或阻塞原因。

能自动核实的内容先实际核实。需要用户主观确认或业务判断的内容，把实际结果和证据展示给用户，由用户决定是否通过。AI 不能替用户验收。

## 三、发现问题时的处理

- 实现没有达到验收条件：记录未通过，返回 `impl` 修正代码，然后重新经过 `test_code` 和 `test_execution`。
- 测试结果已经失效：先重新测试，再执行验收。
- 验收计划遗漏、矛盾或不能判断：返回验收计划阶段修正，不能在验收结果中临时改标准。
- 出现新的产品要求：不加入当前验收结果，按新的产品变更处理。

## 四、形成结果

完成后向用户说明每条验收条件的实际结果、证据和未通过项。用户确认后，按照主题验收结果文档模板生成 `acceptance/<topic>_result.md`。

固定状态字段、工作流编号检查、追踪表更新和阶段推进由程序处理，本规范不重复程序门禁。
