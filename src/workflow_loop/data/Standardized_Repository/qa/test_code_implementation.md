# 测试代码开发规范

## 1. 阶段职责

本规范只规定测试代码怎样写。测试代码阶段怎样调查、讨论、退回上游和通过门禁，由 `Standardized_Repository/qa/test_code.md` 规定。

本阶段开始前，必须已经完成：

- `acceptance/<主题文件标识>_验收计划.md`：已经写清什么算完成。
- `qa/<主题文件标识>_测试计划.md`：已经写清每条验收条件要覆盖的测试项。
- `impl/<主题文件标识>_实施记录.md`：已经写清本次代码实施内容，并且实施代码已经完成。

本阶段可以做静态检查、语法检查、类型检查和 lint 检查，也可以运行与当前正在编写内容直接相关的局部测试作为开发反馈，但不写 `qa/<主题文件标识>_测试结果.md`，不写 `acceptance/<主题文件标识>_验收结果.md`，也不修改产品代码。

## 2. 测试代码要求

- 每个具体测试函数、测试类或测试场景都要写完整 `Workflow-Test` 标识，不能只写 `TC-01` 或 `AC-01` 编号。标识必须逐字复用测试计划中的产品入口、代码入口、测试入口、准备数据、执行动作、预期结果和证据要求，其中预期结果写入“关键断言”，证据要求写入“预期证据”。
- 一个测试函数只绑定一个主要验收条件和一个主要测试项；一个测试项需要多个场景时拆成多个测试函数。
- 测试优先检查产品对外可观察的结果，不为了覆盖代码行数去测试私有实现细节。
- 测试必须调用测试计划登记的真实产品入口并观察登记位置；只检查角色常量、手工设置的属性或对象形状，不算验证产品行为。
- 预期结果必须来自验收计划和产品设计，不能把当前错误实现当成正确答案。
- 需要外部服务、文件或真实样本时，优先使用项目已经确认的测试接缝；不能用自造数据假装验证真实外部行为。
- 至少覆盖验收计划中已经确认的成功结果；验收条件明确要求的边界、拒绝和失败结果也必须有测试代码。
- 测试代码应保持可重复运行，测试之间不能依赖上一个测试留下的未说明状态。
- 多个测试需要相同准备过程时使用 fixture、测试数据工厂或测试辅助函数，不复制大段准备代码。
- mock、stub 和 fake 只能替代已经确认的外部依赖或测试接缝，不能替代本次真正要验证的产品逻辑。
- 断言必须对应测试目标，失败信息应让开发者看出哪个实际结果不符合要求。
- 测试代码阶段只能修改测试代码和测试配置。发现产品代码需要继续修改时，返回 `impl`，不能在本阶段直接改。

## 3. 复用既有测试

项目里已经有测试覆盖当前测试项时，可以复用，但必须先做两件事：

1. 逐项核对既有测试的入口、断言和预期结果是否真的对应当前 `AC-xx` 和 `TC-xx`，并把核对结果说给用户听。
2. 由用户确认复用哪些既有测试。用户没有确认前，不把既有测试当成本次测试项的覆盖。

复用的测试仍必须补齐完整 `Workflow-Test` 标识。既有测试过去跑通过，不代表本次通过：正式测试必须在 `test_execution` 阶段用当前代码重新执行一遍，旧执行记录一律不能沿用。

## 4. 允许的局部运行

可以运行与当前正在编写内容直接相关的单个测试函数、单个测试类或单个测试文件，确认刚写的测试能不能跑起来、断言是否成立。

这类运行只是开发反馈：

- 只跑当前正在写的那部分，不跑整个测试目录，不跑项目全量测试入口。
- 结果在聊天中说明，用来决定下一步怎样改测试代码；需要留痕时写进实施记录的开发检查记录，不写进任何正式测试结果。
- 不用 `workflow test prepare` 登记，不用 `workflow test run` 执行，不生成机器记录。
- 局部跑通不等于测试项通过，也不能据此写任何验收结论。

## 5. 本阶段不做的事

- 不运行项目全量测试入口；最终全量回归只由 `regression_test` 执行。
- 不生成正式测试机器记录；正式执行只发生在 `test_execution` 阶段。
- 不根据局部运行结果修改测试计划或验收条件。
- 不填写“测试结果：通过”或“验收结果：通过”。
- 不把测试代码能运行等同于产品已经完成。

## 6. 完成判断

代码门禁必须同时确认：

1. 本阶段相对开始时确实新增或修改了测试代码。
2. 本阶段没有修改产品代码。
3. 当前测试代码仍然对应当前工作流的验收主题、验收条件和测试计划。
4. 每个自动化或混合测试项至少有一个完整、可读的 `Workflow-Test` 标识；全部标识字段与测试计划逐字一致，测试入口可以被测试执行器直接定位。
5. 测试配置和统一测试入口已经计入测试代码哈希。

通过后进入 `test_execution`。测试代码没有变化，或者产品代码发生变化时，不能进入测试执行阶段。
