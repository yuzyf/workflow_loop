## 2. 实施前计划
<a id="2-实施前计划"></a>

### 2.1 预期产品结果

项目维护者执行 `uv run python scripts/release.py <新版本号>` 后，脚本直接把当前发布身份更新为新版本，更新依赖锁定结果，把当前全部未忽略修改放入一个发布提交，先推送远程默认分支，再创建并推送新版本标签。脚本不执行本地测试、构建、远程版本查询或二次确认。任一步失败时，输出明确失败步骤并停止，不强推，也不自动回滚已经完成的动作。

### 2.2 代码修改计划

| 顺序 | 文件 | 类、函数或配置项 | 当前逻辑 | 计划修改的具体逻辑 | 数据、状态或输出变化 | 对应验收条件 | 前置步骤 |
|---|---|---|---|---|---|---|---|
| 1 | `scripts/release.py` | 新增 `CURRENT_VERSION_FILES`（当前版本文件清单）、`read_current_version()`（读取当前版本函数）、`normalize_release_version()`（规范新版本函数）、`update_release_identity()`（更新当前发布身份函数）、`run_command()`（执行单个命令函数）、`run_release()`（编排发布函数）和 `main()`（命令入口函数） | 当前没有人工发布脚本；维护者需要手工修改版本、更新锁定、提交、推送和创建标签。 | 只在固定当前身份文件中把从 Python 打包配置读取的旧版本替换成新版本；项目状态通过 JSON（结构化数据）读取，只更新 `installer_version`（项目安装版本字段）。然后用参数数组依次执行 `uv lock`、`git add -A`、发布提交、`git push origin HEAD:main`、创建带说明的版本标签和推送标签。每一步先显示中文步骤与真实命令，底层命令非零或无法启动时抛出包含步骤名的错误并停止。 | 当前版本身份、项目安装版本和依赖锁定结果更新；当前全部未忽略修改进入发布提交；远程默认分支和版本标签依次取得同一提交。历史主题和历史正式产物不被脚本扫描或替换。成功只报告远程发布流程已触发；失败保留当时实际文件和 Git 状态。 | AC-01、AC-02、AC-03 | 无 |
