## 2. 实施前计划
<a id="2-实施前计划"></a>

### 2.1 预期产品结果

新建轮次和已经开始的旧轮次最终只使用一套顺序：“验收计划 → 实施计划确认 → 保存修改前内容 → 实施代码 → 实施记录与代码一致性核对 → 测试计划 → 测试代码 → 测试执行”。用户只查看状态时不会暗中改文件或状态；真正继续旧轮次时，程序先显示并校验迁移影响，再一次性保留仍有效的验收和代码、清除实施前旧测试计划及其后续结果。迁移任一步失败时恢复原状态并报告失败，不留下已经换顺序却没有审计记录的半完成状态。

验收计划变化会使受影响实施及所有测试结果失效；代码或实施记录变化会使原测试计划及其后续失效；只有测试计划变化且没有实施变化时，已确认实施保持有效。实施阶段不再依赖尚未生成的测试计划，测试计划阶段反过来要求当前实施、真实代码和实施记录已经确认。`qa/索引.md` 的“测试结果”列和 `acceptance/索引.md` 的“主题验收结果”列都属于下游状态，从“待生成”变为真实结果链接时不能反过来使已确认上游计划失效；索引中的主题、前置关系和上游文档位置仍必须参与对应计划绑定。
