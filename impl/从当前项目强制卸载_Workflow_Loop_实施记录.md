## 2. 实施前计划

### 2.1 预期产品结果

用户在项目根目录执行 `workflow uninstall` 后看到绝对路径、实际存在的删除项、明确保留项和不可恢复提示，只确认一次即可强制卸载。进行中、已完成、已作废、完整安装和部分残留都不能阻止卸载；已经删除的项目管理内容不恢复，删除失败时准确列出未删项并允许重试。没有公开卸载命令的旧版本可直接运行正式发布的 `uninstall.sh` / `uninstall.ps1`，不先升级全局命令。业务代码、测试、Git 数据、正式产物和电脑全局命令保持不变。

|---|---|---|---|---|---|---|---|
| 1 | `uninstall.sh` | macOS/Linux 项目和全局卸载脚本的项目分支 | 文件不存在，旧版本项目没有独立卸载入口 | 新增默认项目卸载模式：严格使用当前工作目录，不向上查找；通过固定 `uv 0.11.33` 临时运行正式包的内部范围扫描，显示固定删除与保留清单并确认一次，再调用内部强制删除入口；完全未安装按成功处理，部分失败不恢复已删内容；不安装或卸载电脑全局命令 | 旧版完整或残留项目可一条脚本直接卸载；临时 uv 和临时包结束后删除 | AC-01 至 AC-07；TC-01 至 TC-08 | 更新主题完成共用 Python 内部入口 |
| 2 | `uninstall.ps1` | Windows PowerShell 5.1/7 项目和全局卸载脚本的项目分支 | 文件不存在，旧版本项目没有独立卸载入口 | 实现与 Bash 相同的项目范围、一次确认和临时目标包调用；使用 UTF-8 无 BOM 事务参数，标准输出/错误分开捕获并按退出码判断；项目模式不需要等待或删除正在运行的全局命令 | Windows 旧版项目可直接强制卸载，正常 uv 输出不会被误报为失败 | AC-01 至 AC-07；TC-01 至 TC-08 | 更新主题完成共用 Python 内部入口 |

共用的 `src/workflow_loop/cli.py::cmd_uninstall`（卸载命令）、内部 `_uninstall-project`（项目卸载入口）、`src/workflow_loop/installer.py::inspect_uninstall_scope`（卸载范围扫描）和 `uninstall_project`（固定范围删除）由“已安装项目一条命令更新到目标正式版本”主题完整登记并建立回退基线。本主题只实现旧版本可直接调用的两个发布脚本，避免同一公共文件重复归属。测试执行返回实施阶段后，只修正更新主题拥有的 `.github/workflows/release.yml`（GitHub 发布流程配置）：让发布冒烟使用本地固定正式版本元数据，确保更新步骤成功后能继续执行本主题的项目卸载步骤；本主题的卸载范围和产品代码不变。
