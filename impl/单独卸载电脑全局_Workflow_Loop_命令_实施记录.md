## 2. 实施前计划

### 2.1 预期产品结果

用户在任何目录执行 `workflow uninstall --global`，都会先看到全局命令、工具环境、可确认的 `PATH`（命令搜索路径）来源和其它项目受影响警告，并只确认一次。确认后辅助脚本等待当前命令退出，再删除 Workflow Loop 的 uv 全局工具；只有来源记录能证明由 Workflow Loop 添加的 PATH 项才删除，预先存在或来源不明的路径保留并报告。整个过程不查找、扫描、读取或删除任何项目目录，部分失败不恢复已删除内容并可重试。

### 2.2 代码修改计划

| 顺序 | 文件 | 类、函数或配置项 | 当前逻辑 | 计划修改的具体逻辑 | 数据、状态或输出变化 | 对应验收条件和测试项 | 前置步骤 |
|---|---|---|---|---|---|---|---|
| 1 | `install.sh` | 全局命令安装成功后的来源记录 | 可能向 shell 配置写入带版本注释的工具目录，但没有独立记录该 PATH 项原先是否存在 | 在全局工具身份和 PATH 修改成功后，原子写入电脑侧安装来源 JSON：产品、版本、工具目录、命令目录、是否由本次安装添加 PATH、配置文件和精确写入行；已有兼容命令且未写 PATH 时不伪造来源 | 后续全局卸载能区分“Workflow Loop 添加”和“预先存在/未知来源”；项目目录不增加电脑状态 | AC-03、AC-05；TC-03、TC-05 | 无 |
| 2 | `install.ps1` | Windows 用户 PATH 修改后的来源记录 | 可能把工具目录追加到注册表用户 PATH，但没有留下可证明来源的记录 | 写入与 Bash 同义的电脑侧来源 JSON，记录用户 PATH 修改前后必要事实和是否由本次安装添加；使用原子 UTF-8 无 BOM 文件写入，安装失败时按现有回退逻辑删除本次来源记录 | Windows 全局卸载只删除有可靠记录且仍精确匹配的用户 PATH 项，旧安装或记录不一致时保留 | AC-03、AC-05；TC-03、TC-05 | 无 |

共用的 `workflow uninstall --global` 参数与一次确认、辅助脚本下载/交接，以及 `uninstall.sh` / `uninstall.ps1` 的全局分支，由前两个主题登记的 `cli.py` 和卸载脚本实现。本主题只完整登记安装时新增的 PATH 来源记录；README 和发布配置也依赖更新主题的公共修改，不重复列为本主题文件。测试执行返回实施阶段后，只修正更新主题拥有的 `.github/workflows/release.yml`（GitHub 发布流程配置）：让发布冒烟使用本地固定正式版本元数据，确保前置更新和项目卸载成功后能继续执行本主题的电脑全局卸载步骤；本主题的来源判断、项目隔离和产品代码不变。
