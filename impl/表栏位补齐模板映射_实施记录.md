## 2. 实施前计划（代码计划）


### 2.1 预期产品结果

- AI 在实施/验收/测试各环节拿到的工作记录表包含模板每一节对应栏位，按表填写后程序生成的正式文档章节齐全、无占位句；旧轮次按开工冻结的 v1 口径继续工作不受升级影响。

### 2.2 最低实现设计

| 设计项 | 已确认做法 | 选择理由 | 对应验收条件 |
|---|---|---|---|
| 模块与职责 | records.py 的 KIND_SCHEMAS 成为栏位唯一声明处，渲染器按表全量渲染模板每节；state.py 增加 table_format_version 字段 | 栏位、渲染和校验共用同一 schema 声明，改一处即三处同步，避免模板与表再脱节 | AC-01、AC-02、AC-03 |
| 接口与调用顺序 | _schema(kind, version) 按冻结版本选 schema；create_or_complete_table/validate_table/generate_document 全部经 _workflow_table_version 取冻结版本 | 进行中轮次不因程序升级报新栏位缺失，v1 快照保证历史轮逐字节兼容 | AC-03 |
| 数据、状态与副作用 | workflow start 创建 state 时写入 TABLE_FORMAT_VERSION；v1 轮次的表校验与渲染走 _LEGACY_KIND_SCHEMAS/_LEGACY_COLUMN_HINTS 快照 | 冻结一次性完成，后续所有环节只读 state 不再推断 | AC-03 |
| 错误与边界 | 表版本不等于冻结版本或不在支持清单时报内容问题并拒绝生成；v2 渲染覆盖 impl_record/test_plan/acceptance_plan 等全部模板表格 | 版本错配和丢表都是本轮修复的核心故障形态，必须显式报错 | AC-01、AC-02、AC-03 |
