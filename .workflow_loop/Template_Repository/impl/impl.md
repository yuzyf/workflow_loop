# 实施文档模板

本模板定义实施阶段最终生成的两类文档：

1. `impl/索引.md`：继承验收主题关系，并提供各主题实施文档入口。
2. `impl/<主题文件标识>_实施记录.md`：记录一个验收主题的实施依据、实施前计划和实施后记录。

文档标题保留完整中文主题名称；文件名使用程序生成并保存的稳定中文文件标识，与该主题的验收计划使用同一个标识。

本模板只规定最终产物的章节、字段、表格、链接和内容边界，不规定 AI 怎样调查代码、怎样和用户讨论实施方案或怎样执行代码修改。

## 一、`impl/索引.md` 模板

```markdown
# 实施索引

## <workflow_id>

### 主题关系

| 展示顺序 | 验收主题 | 前置主题 | 验收计划 | 实施记录 |
|---|---|---|---|---|
| 1 | <主题 A> | 无 | [主题 A 验收计划](../acceptance/<主题 A 文件标识>_验收计划.md) | [主题 A 实施记录](./<主题 A 文件标识>_实施记录.md) |
| 2 | <主题 B> | <主题 A> | [主题 B 验收计划](../acceptance/<主题 B 文件标识>_验收计划.md) | [主题 B 实施记录](./<主题 B 文件标识>_实施记录.md) |
```

规则：

- `impl/索引.md` 必须继承 `acceptance/索引.md` 的展示顺序和前置主题，不能重新制定主题关系。
- `展示顺序`只用于阅读；真正的等待关系由“前置主题”表达。
- 每个主题必须且只能出现一次。
- `验收主题`列写完整中文主题名称；链接路径使用程序保存的稳定中文文件标识。
- 索引只保存主题关系和文档入口，不复制代码修改逻辑、运行状态、测试结果或验收结果。

## 二、`impl/<主题文件标识>_实施记录.md` 模板

```markdown
# 【实施】<验收主题>

- 工作流编号：<workflow_id>
- 验收主题：<验收主题>

## 4. 上下游文档

| 关系 | 文档 | 说明 |
|---|---|---|
| 上游 | [验收计划](../acceptance/<主题文件标识>_验收计划.md) | 本主题要达到的用户结果和验收条件 |
| 上游 | <代码设计章节链接> | 本次实施遵守的架构设计 |
| 全局 | [需求交付追踪表](../需求交付追踪表.md) | 查看完整交付链路 |
| 下游 | `qa/<主题文件标识>_测试计划.md`（待生成） | 根据已确认实施记录和真实代码制定测试计划 |
| 下游 | `qa/<主题文件标识>_测试结果.md`（待生成） | 测试代码完成后执行正式主题测试 |
| 下游 | `acceptance/<主题文件标识>_验收结果.md`（待生成） | 正式测试后执行主题验收 |
```

## 三、内容边界

- `impl/索引.md` 不能写具体代码修改步骤；这些内容写在对应主题文档中。
- `impl/<主题文件标识>_实施记录.md` 必须写到具体文件、类、函数或新增位置，不能只写模块名称。
- “实施前计划”写代码修改前已经确认的方案；“实施后记录”必须根据最终代码填写，不能复制计划内容代替事实。
- 实施计划、实际代码差异集合和实施后记录必须一一一致；实际记录必须写具体文件、精确位置、真实逻辑，以及数据、状态或输出变化。
- 实施文档只绑定验收条件，不依赖尚未生成的测试计划或 `TC`（测试项编号）。
- 不建立“计划与实际差异”章节。实施结果与当前确认计划不一致时，应停止实施并返回对应阶段，不把差异当成正常结果写入文档。
- 实施文档可以记录语法、类型、静态检查或局部运行等开发检查反馈，但这些反馈不是正式测试，不能填写正式测试通过、正式测试失败或主题验收通过。
- 尚未生成的下游文档只写反引号包裹的普通相对路径和“（待生成）”，文件真实存在后才改成 Markdown 链接。
- 没有相关内容时写“暂无”，不得编造内容填满表格。
