# 实施文档模板

本模板定义实施阶段最终生成的两类文档：

1. `impl/index.md`：继承验收主题关系，并提供各主题实施文档入口。
2. `impl/<topic>.md`：记录一个验收主题的实施依据、实施前计划和实施后记录。

本模板只规定最终产物的章节、字段、表格、链接和内容边界，不规定 AI 怎样调查代码、怎样和用户讨论实施方案或怎样执行代码修改。

## 一、`impl/index.md` 模板

```markdown
# 实施索引

## <workflow_id>

### 主题关系

| 展示顺序 | 验收主题 | 前置主题 | 验收计划 | 测试计划 | 实施文档 |
|---|---|---|---|---|---|
| 1 | <主题 A> | 无 | [主题 A 验收计划](../acceptance/<主题 A>_plan.md) | [主题 A 测试计划](../qa/<主题 A>_plan.md) | [主题 A 实施文档](./<主题 A>.md) |
| 2 | <主题 B> | <主题 A> | [主题 B 验收计划](../acceptance/<主题 B>_plan.md) | [主题 B 测试计划](../qa/<主题 B>_plan.md) | [主题 B 实施文档](./<主题 B>.md) |
```

规则：

- `impl/index.md` 必须继承 `acceptance/index.md` 的展示顺序和前置主题，不能重新制定主题关系。
- `展示顺序`只用于阅读；真正的等待关系由“前置主题”表达。
- 每个主题必须且只能出现一次。
- 索引只保存主题关系和文档入口，不复制代码修改逻辑、运行状态、测试结果或验收结果。

## 二、`impl/<topic>.md` 模板

```markdown
# 【实施】<验收主题>

- 工作流编号：<workflow_id>
- 验收主题：<验收主题>

| 检查命令或方法 | 检查范围 | 实际反馈 | 是否需要继续修改 |

## 4. 上下游文档

| 关系 | 文档 | 说明 |
|---|---|---|
| 上游 | [验收计划](../acceptance/<topic>_plan.md) | 本主题要达到的用户结果和验收条件 |
| 上游 | [测试计划](../qa/<topic>_plan.md) | 本主题准备覆盖的测试范围 |
| 上游 | <代码设计章节链接> | 本次实施遵守的架构设计 |

```

## 三、内容边界

- `impl/index.md` 不能写具体代码修改步骤；这些内容写在对应主题文档中。
- `impl/<topic>.md` 必须写到具体文件、类、函数或新增位置，不能只写模块名称。
- “实施前计划”写代码修改前已经确认的方案；“实施后记录”必须根据最终代码填写，不能复制计划内容代替事实。
- 不建立“计划与实际差异”章节。实施结果与当前确认计划不一致时，应停止实施并返回对应阶段，不把差异当成正常结果写入文档。
- 实施文档可以记录开发检查反馈，但不能填写正式测试通过、正式测试失败或主题验收通过。
- 没有相关内容时写“暂无”，不得编造内容填满表格。
