# 产品设计变更后的代码架构修订规范

## 目的

在产品设计已经确认、正式实施还没有开始时，检查产品变化会怎样影响现有代码架构，并修改 `spec/architecture_code_design.md` 的计划设计。

最终文档结构使用 `Template_Repository/code_design/code_design.md`。本文件只说明本阶段怎样工作，不重复架构文档模板。

## 讨论和调查

1. 读取本次工作流已经确认的 `spec/product.md` 和受影响的功能文档。
2. 读取现有 `spec/architecture_code_design.md`，找出受影响的代码层、架构关键节点、功能代码过程、共享代码和差异记录。
3. 对照产品变化，逐项确认新增、修改或删除了哪些产品职责、规则、边界和异常处理。
4. 需要时查看相关代码和测试，确认当前架构文档没有把计划代码写成已有实现。
5. 只修改受本次产品变化影响的架构内容，不重写无关部分。

## 修改要求

- 继续从产品功能、产品通用规则或系统约束推导代码设计。
- 更新受影响的架构层、关键节点、功能场景代码过程、共享代码和差异记录。
- 架构图只表示代码分层、职责和依赖方向；功能流程图才表示具体执行顺序。
- 每个程序节点写真实或计划的文件、类、函数、类型或接口，并说明关键逻辑、状态或数据、失败结果和验证位置。
- 计划实现必须标记为“计划”，不能写成已经完成。
- 不在本阶段修改正式代码，不制定测试执行步骤，不提前写最终实现结果。

## 结束前检查

- 产品变化是否逐项对应到受影响的代码设计。
- 是否保留了未受影响的架构内容。
- 架构图是否仍然是分层图，没有混入功能执行顺序。
- 代码位置是否能定位到文件和符号，并说明具体职责。
- `spec/architecture_code_design.md` 是否确实反映本次产品设计变化。
